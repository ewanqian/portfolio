# 一间由 Agent 协助的电子音乐工作室
## 从声音草稿、作品审查到可演奏的现场工程

**钱誉文 / Ewan Qian · Performable Music 方法手册 · 2026 年 11 月**

我的优势首先是空间与实时视觉设计，而不是长期的传统作曲训练。过去的演出经验包括异形与大型屏幕、实时播放、舞台事件、音乐人与视觉的协作。这使我能较早理解音乐和图像如何共享时间，却也容易产生一个误会：**既然已经能把互动系统搭起来，是否就能很快写出成熟的音乐？**

事实并非如此。程序可以快速制造一件能响的东西，但音乐要成立，还需要有人对听觉做判断：动机是否值得记住、节奏是否有弹性、哪一次沉默真正有力、尾音是否合适、和声有没有变化的原因。这篇方法手册把 Agent 从“不断生成音符的机器”重新放回工作室的位置。

## 一、先分清三种文件

**Sound Sketch**：听起来有一个有趣想法的音频片段，可能只有 30 秒。适合研究材料和机制，还不需要正式完成全部编曲。

**Composition Demo**：至少有一个完整的听觉结构，可以独立从头听到尾；它不一定已经母带化，但需要明确的发展、对比、结束以及经过选择的声音材料。

**Performable Instrument**：除了可以听，还保留能被现场输入改变的音乐关系。它可能通过脚踏、MIDI、手势或时间控制来改变段落、共振、记忆和声场。

这三种文件可能来自同一组声音，但验收方法不同。不能因为一个声音可以被 OSC 控制，就称它为成熟歌曲；也不能因为它在 DAW 里有九条轨道，就认定它有九种音乐想法。

## 二、给 Agent 一个清楚的“问题”，不是要求它更酷

一个差的需求是：“帮我生成一段很炸裂、很高级、风格像著名实验电子音乐人的四分钟音乐。”

它隐含了太多互相矛盾的词。Agent 很可能选择最容易生成的通用元素：持续的四拍 Kick、锯齿波、上升噪声、宏大混响和任意四段结构。最后听起来既像游戏配乐，也像演示项目。

更好的需求应该可被听觉检验：

> 用一个自录的金属接触声构成三种声音角色。制作 16 小节，两次重复必须在节奏与音乐功能上不同；第 9–12 小节撤除低频但保留时间感；第 13 小节的重新进入必须由前面的期待产生。禁止新添第四种素材。导出 A/B 音量匹配版本，并指出哪一次返回是必需的。

这条指令的价值，是 Agent 无法仅靠“更复杂”完成任务。

## 三、让声音进入 DAW，而不是让 DAW 变成 Agent 的游戏界面

在电脑上，一套合理的零购买成本生产环境可以使用现有、合法可保存的 Ableton；若没有，就先在免费 Waveform Free 中验证原生保存和导出。声音来源可以来自免费的 Surge XT、自行合成或录制；需要可编程效果器时，再用 plugdata、SuperCollider 或 Max。

工具可以分工，但不应为每个方向安装一套新系统：

- **Agent**：读取原始材料、提出分段、产生 MIDI、生成或修改参数、记录可比版本。
- **DAW**：编辑、安排、混音和导出真实音频；解决细微的声部呼应、力度与过渡。
- **可编程声音引擎**：当某种音色或响应关系现有音源很难做到时，才开发新的合成器或效果器。
- **演出控制层**：将音乐状态和有限的外部输入映射成一个可回放、可恢复的系统。
- **人**：决定哪些声音值得继续投入。

如果 Agent 能很熟练地编辑 MIDI，但用户不能正常保存工程，这条制作链就是不可靠的。可回退、可重开，与创作本身同等重要。

## 四、混响和 Delay 不是“让声音变高级”的按钮

如果声音听起来又干又薄，最直觉的做法是增加 Reverb。但大而均匀的混响很容易把打击的边缘抹掉，鼓与 Bass 混成一团，让曲子越来越远，却没有更好的空间。

一个有效的第一版可以把声音分成三层：

1. **Near / 近景**：Kick、Bass 和最关键的打击保持相对干燥。攻击决定动作是否有力。
2. **Middle / 中景**：少量金属敲击或音色答句进入具有 Predelay（早期直接声与混响起始之间的延迟）的短空间，形成厚度和定位。
3. **Far / 远景**：环境材料、粒子和被刻意延长的声音进入较长的尾音。不是所有声音都长期待在那里。

Delay 也应承担明确任务：几拍之后返回的音是否成为新乐句？它是否在下一段出现之前制造提示？反馈增高时，哪个声部必须退后，避免尾音失控？

可以制作两种混音：A 保持干燥、突出节奏；B 只让少数声音获得距离感。两份以接近的听觉响度播放，若 B 不能让结构更清楚，就不需要为了“专业”而保留。

## 五、真正值得开发的合成器有一个明确任务

对我而言，一件“签名乐器”应当比庞大的通用 Patch 更有价值。例如：

**Rubber Metal Drum** 解决“弹性低音和金属打击如何相互回答”的问题。可调参数不是五十个旋钮，而是 Bounce、Body、Metal、Distance；声音通过包络、共振、轻微 FM 与时间错位形成自身身份。

**Afterimage Piano** 解决“之前的旋律如何作为声音记忆回来”的问题。它记录片段或事件，通过延迟、共振、粒子与回放规则，让旧材料以新的音色出现。

**Orbital Hocket** 则解决“空间中的几个声部如何交替完成一个节奏”的问题。控制器改变相位与顺序，合并时形成新节奏，视觉轨道可以从同一组相位数据生成。

开发自己的音源不是为了证明会编程。它必须解决一个现成预设难以表达的音乐问题，而且在不看屏幕时也能听出它为什么有用。

## 六、音画同源需要共享“事件”，不只是共享 BPM

在现场，音乐与视觉都知道现在是 128 BPM，还远远不够。它们可能不在同一拍，甚至不知道当前已经进入哪一幕。

更完整的数据协议需要描述：谁发出了动作、什么事件发生、发生在何时、当前处于什么状态、状态的连续控制值是什么，以及系统是否安全。

例如一条事件可以同时产生不同结果：

```json
{
  "scene": "OVERRIDE",
  "state": "PEAK",
  "event": {"id": "override-001", "type": "OVERRIDE", "source": "FOOT"},
  "controls": {
    "energy": 0.91,
    "tension": 0.93,
    "space": 0.88,
    "pressure": 0.96
  }
}
```

这是阐释性片段，而非完整的网络协议。真实工程还需要时间戳、序列号、追踪有效性与 SAFE 状态，保存在 [Show Score v1](https://github.com/ewanqian/performable-music/blob/main/protocols/show-score-v1.schema.json)。

如果同一个 OVERRIDE 事件让声音的低频和节奏结构改变、让空间中的几何体骤然重构，还让灯光进入一个新的明确场景，观众就能理解演奏动作的因果关系。没有这种因果关系，所谓“音画同源”容易退化成同步播放。

## 七、一个可复制的制作循环

每次只选择一段 16 小节音乐进行以下练习：

1. **Listen**：先不看视觉和界面，听完整片段并写下三个时间码。
2. **Name**：用一句话说明音乐里最重要的声音关系。
3. **Subtract**：删除一个声部或者一次重复，检查音乐是否反而更清楚。
4. **Develop**：给出两种实质不同的编曲结果，不能只是更快、更大、更湿。
5. **Produce**：用真实音源、效果器和混音把 A/B 两个版本导出。
6. **Review**：音量匹配，打乱文件名试听。只针对听得到的东西评论。
7. **Perform**：在被选中的版本里加入 2–4 个语义参数和一条可靠的状态转换。
8. **Archive**：保存工程、MIDI、Stem、预设、事件记录和失败原因。

这里最困难的一步往往不是 Develop，而是 Review：当 Agent 不断提供新的版本时，创作者必须有能力说“这个不值得继续”。

## 八、让 Agent 真正可控的工程约定

为了防止“换一个 Agent，整个工程又被重新生成”，需要区分三种工作单位：

**Task / 任务** 定义一个小而明确的目标，例如“保留鼓和 Bass 的 Groove，只重写第 17–24 小节缺失的声部线索”。

**Plan / 作曲计划** 定义音乐材料、目标事件、预期的听觉后果、不可更改的关系和两个版本的区别。它可以在不同工具之间复用。

**Execution / 实际工程修改** 负责在 DAW 里操作轨道、设备、MIDI、发送与自动化，随后提供能够打开和试听的音频或工程文件。

一个可接受的 Agent 交接至少包括：输入 Git Commit/工程副本、目标文件、允许修改的范围、预计听见的变化、不可修改的东西、实际执行的命令、输出 WAV/MIDI/工程路径、测试结果、可回滚方案。**没有实际输出文件时，只能叫提案或待执行任务。**

这类约束已经写为 [Composition Plan v1](https://github.com/ewanqian/performable-music/tree/main/protocols/composition-plan-v1)。其中的检查脚本能够发现小节越界、动机引用不存在和曲式覆盖缺口，但不会假装知道哪首音乐更好。

四个最重要的验收与此对应：

- **Structure**：Agent 宣称撤掉第十七小节低频，MIDI 或事件表里是否真的删掉了预期事件？
- **Audio**：新版本是否真正导出、不是静音，并且在合适的响度下可试听？
- **Music**：A/B 在没有视觉的情况下是否能听见不同的发展，哪一版值得再次播放？
- **Performance**：事件重放时是否稳定，脚踏或手势是否能改变音乐中的某项决策，断线后是否能够安全退出？

已有的实际工具能力、授权限制以及本地适用性见 [2026 年 Agent 音乐系统评估](07-2026-agent-music-systems.md)。其中可区分 MIDI 变奏、DAW 自动化、音频生成和实时共同即兴，不要混称为一种万能的音乐制作 Agent。

## 八、作品的完成标准

我希望以后每首正式列入 Performable Music 的作品都至少回答：

- 关掉视觉，是否依然有明确的听觉身份？
- 同一声部重复四次时，为什么第四次仍然值得出现？
- 声音的空间距离是否有可以解释的作用？
- 演奏者改变了音乐中的什么决定，而不是只改变音量？
- 停止输入或断线以后，是否能够安全而有音乐性地继续或退出？
- 工程能否在下一台经过配置的电脑上重新打开并恢复到可靠状态？

如果答案尚不清楚，就把它归档为练习而不是正式作品。这种归档不是失败：长期的音乐研究需要大量明确知道“为什么没留下”的草图。

**Performable Music 的目标不是证明 Agent 生产得多快，而是建立一种音乐创作者真正愿意反复演奏、可以长期复用与持续深化的音乐结构。**
