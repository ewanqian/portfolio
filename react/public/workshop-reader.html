Workshop Reader · 8.29

从一个效果，走向一套系统。

这份阅读只解释下午会反复用到的几个概念：输入、状态、反馈、连续性，以及为什么一个可以玩的网页和一个可以被演奏的系统并不是同一件事。

一分钟版本

实时作品可以先被理解成一个持续循环的关系。下一刻发生什么，不只由“刚刚按了哪个键”决定，也和系统当前的状态、之前留下的结果、以及现场正在发生的事情有关。

当前状态 + 人的操作 + 外部条件 ↓ 下一个状态 ↓ 声音 / 视觉 / 空间 ↓ 反馈 ↓ 下一次判断

1. Input 只是入口

最简单的原型可以是：A 触发一个声音和一个圆，B 触发一条线。它非常适合开始，但如果每次按 A 都得到完全一样的结果，系统很快就会被看完。

Result = Input ↓ 进一步 Result = Input + State + History

2. State 让同一个动作获得不同意义

同一个按键，在不同状态中可以承担不同角色。OPEN 时它可能很轻，BUILD 时开始累积，PEAK 时成为强烈的 accent，BREAK 时则用于释放或留白。

按钮没有变多，但系统的深度增加了。

3. Feedback 让操作变得可理解

一个动作发生以后，操作者需要快速知道系统收到了什么、改变了什么。视觉和声音不一定要完全同步，但关系需要清楚到足以形成下一次判断。

4. 连续性比“效果数量”更重要

现场系统不能要求表演者每一秒都不断按键来维持生命。好的结构会在短时间无人操作时仍然保持连续，同时把少量真正重要的决定留给人。

机器适合处理时钟、quantization、密度保护、音量安全、稳定运行。
人更适合处理进入、等待、增加、减少、保持、释放，以及什么时候停止。

5. 下午的五个 Demo

D0 · Direct Trigger最直接的一次输入 → 一次结果。
D1 · Quantized Capsules人的输入不必精确落点，系统帮助把意图放进节拍结构。
D2 · Four Layer Sequencer从单次触发进入多层、持续的时间结构。
D3 · Shared State A/V声音和视觉读取同一个高层状态，而不是只做简单 reactive。
D4 · Spatial Adapter同一控制模型如何换一种输入空间继续工作。

后面的 D5 Control Field 与 Topological Playground，是把这些关系继续推进到更接近演出系统的尝试。

今天只需要记住一句

不要只设计“按下之后出现什么”。也要设计：系统现在在哪里，这个动作准备把它带到哪里。
