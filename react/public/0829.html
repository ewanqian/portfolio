01 / Before we start

开始前，建议完成这些准备

浏览器
Chrome、Edge 或其他现代浏览器，可以正常打开网页并播放声音。
设备
笔记本电脑和有线耳机。现场请尽量使用耳机试听。
智能工具
ChatGPT、豆包、Kimi、Codex、Claude Code 等，选择一个你已经能够正常使用的即可。
GitHub
建议提前注册并登录。它可以帮助你保存版本，也方便把作品发布成链接。
个人素材
可选：1–2 段短声音、3–6 张图片。没有准备也可以使用现场材料。
本次不需要
MIDI、TouchDesigner、Resolume 或复杂 API 环境都不是今天的必要条件。
如需使用 GitHub Token，请仅创建最小权限的 Fine-grained PAT，并妥善保存。不要把 Token 发到群聊、Prompt、网页源码或公开仓库。能够使用 GitHub 官方登录、Connector 或 GitHub CLI 时，优先选择这些方式。

04 / Observe

体验时，可以留意三件事：
我做了什么？系统怎样回应？什么让我愿意继续操作？

INPUT / GESTURE ↓ MAPPING / RULE ↓ STATE CHANGE ↓ SOUND + VISUAL ↓ FEEDBACK ↓ NEXT DECISION

今天更关注关系是否清楚、反馈是否成立，以及同一个系统能不能留下一点继续探索的空间。

05 / Make your own

从试玩，到自己的版本

选择一个起点

从一个你愿意继续玩的 Demo 或 Starter 开始，不必从空白工程起步。

确定一个输入

键盘、鼠标或按钮都可以。先把一条关系做清楚，再决定是否继续扩展。

连接声音与视觉

让同一个动作或状态同时进入 Sound 与 Visual，而不是把两者放在最后再对齐。

换成自己的材料

图片、录音、文字、朋友语音、自己拍的素材都可以。个人材料会很快改变作品的气质。

交给别人试玩

先让对方直接体验 30–60 秒，再听反馈。观察哪里自然，哪里需要更清楚的提示。

完成一次修改

选择一个最值得调整的问题。它可能是增加，也可能是删除、限制、延迟或重新安排状态。

06 / Work with your assistant

让工具围绕清晰的目标工作

Broad request

范围较宽

“帮我做一个炫酷的音画网页”会留下很多未定义的选择，工具往往会自行增加 UI、效果和依赖。

Focused request

范围更清楚

说明当前输入、希望改变的行为、哪些部分保持不变，以及你准备怎样测试，会更容易得到可控的结果。

Example
请先读取现有项目，并保留当前结构。 当前输入：Space 当前行为：按下时触发一个声音与一个视觉事件。 这次只调整以下关系： - Tap：保持原行为 - Hold：逐渐增加密度 - Release：进入 1.5 秒衰减 请保持： 1. 不增加新的按钮； 2. 不改变现有视觉风格； 3. 不引入新的依赖； 4. 完成后说明修改了哪些文件。 我会先运行测试，再决定下一步。

把每次修改控制在一个清楚的小目标里，通常会更快，也更容易判断结果。

07 / Save & share

把它保存成一个可以继续使用的链接

创建 GitHub Repository

可以一件作品一个仓库，也可以放进自己的长期项目目录。

保存网页与 README

至少保留 index.html。README 可以简单写明作品名称、操作方式、版本与下一步计划。

提交文件

可以通过 Connector、CLI、Agent 或手动上传完成。选择你最熟悉的方式即可。

开启 GitHub Pages

在仓库 Settings → Pages 中选择发布分支，部署完成后即可获得公开 URL。

发给别人打开

真正值得测试的是：离开你的电脑后，别人能不能从一个链接开始体验。

继续保存版本

保留 V1、试玩反馈与 V2。以后再做宣传页、作品页或新版本时，都可以直接引用。
