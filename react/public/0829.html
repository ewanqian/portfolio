准备5 个 Demo演出系统阅读制作
Minimal Input / Audiovisual System · 2026.08.29

从一个输入开始，
做成自己的音画系统。

下午会先试玩几组不同层级的实时系统，再从最简单的输入关系开始制作。最后留下一个可以运行、可以交给别人试玩、也可以继续发布和修改的网页版本。

不需要提前掌握某一种软件。我们会把重点放在操作、状态、声音、视觉和时间关系本身。

00 / Preparation

开始前，确认这些即可。

电脑
笔记本电脑 + 有线耳机。
浏览器
Chrome / Edge / Safari 等现代浏览器。
AI 工具
ChatGPT、豆包、Kimi、Codex、Claude Code 等，准备一种自己可以正常使用的即可。
GitHub
建议提前注册并登录；今天想把作品发布成链接时会用到。
个人素材
可选准备 1–2 段短声音、3–6 张图片。没有也可以使用默认材料。
其他软件
今天不要求 TouchDesigner、Resolume、MIDI 或复杂本地环境。
如果需要 GitHub Token，请只创建必要权限，并妥善保存。不要把 Token 发到群聊、网页源码或公开仓库。
01 / Demo Ladder

五个 Demo。按顺序玩。

D0

Direct Trigger

最直接的一次输入 → 一次声音 / 视觉结果。先感受它为什么简单，也为什么很快会被看完。

试玩
D1

Quantized Capsules

输入不一定要精确落在节拍上。系统可以帮助把人的意图放进稳定的时间结构。

试玩
D2

Four-Layer Sequencer

从单次触发进入多层持续结构。重点观察：人不操作的时候，系统是否仍然保持连续。

试玩
D3

Shared-State A/V

声音和视觉不必互相“跟随”，它们可以读取同一个 State，再分别解释同一次变化。

试玩
D4

Vision Pro Spatial Adapter

再看两套更接近演出的版本。

Fullscreen Control Field

打开 Topological Playground
03 / Reading

一个实时系统不只需要回答：
“按下以后出现什么？”
还要回答：系统现在在哪里，下一步准备往哪里走。

阅读：从效果到系统Patataptouch:waves
04 / Observe

试玩时，留意这条关系。

INPUT / GESTURE ↓ MAPPING / RULE ↓ STATE ↓ SOUND + VISUAL ↓ FEEDBACK ↓ NEXT DECISION

一个系统是否值得继续玩，通常不取决于按钮数量，而取决于操作以后是否有清楚反馈、是否存在第二层变化，以及系统是否给下一次操作留下空间。

05 / Build

下午的制作流程。

选一个最简单的输入

键盘、鼠标或按钮都可以。先让第一条关系跑起来。

同时建立声音与视觉反馈

让同一个动作进入声音和视觉，不需要先把系统做复杂。

加入一个 State

例如 Quiet / Active，或让 Hold、Release、Repeat 对同一个输入产生不同解释。

替换成自己的材料

加入自己的声音、图片、文字或其他素材，让系统逐渐形成个人身份。

交给别人试玩

作者先不解释。观察对方如何开始、哪里看不懂、什么时候开始失去兴趣。

完成一次修改

选择一个最需要调整的问题，修改以后保存新的版本。

07 / Publish

把结果保存成一个可以继续使用的版本。

创建 Repository

一个项目可以拥有一个清楚的仓库，或放进自己的长期项目目录。

保存网页与 README

至少记录作品名称、怎么玩、当前版本和下一步准备修改的内容。

开启 GitHub Pages

把作品变成公开 URL，方便测试、分享和继续引用。

把 URL 发给别人

真正的测试从这里开始：别人打开以后，是否可以自然地开始操作。
