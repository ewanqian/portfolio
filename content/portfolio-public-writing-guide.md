# Portfolio Public Writing Guide

Last updated: 2026-05-07

This document is an internal writing reference for the portfolio. It is not public site copy.

## Current Direction

The site is clearer than the earlier version, but the public language still needs to stay away from guide-panel logic. Gallery and Production should not describe the same material in the same way. Gallery should read as a curated artwork view; Production should hold the broader project, collaboration, and delivery record.

## Reader-Based Review

### Curator / Gallery Reader

Strength: The strongest works are visible and the practice direction is legible.

Issue: Gallery should feel like an artwork gallery: fewer entries, stronger images, clearer titles, and concise context. Production Records can hold the broader project information.

What this reader needs:

- a clear artistic position;
- selected artworks or public presentations;
- exhibition, venue, award, or performance context;
- enough project detail to understand scale and quality.

### Institution / Brand / Production Team

Strength: Production now contains useful information about project types, delivery, and pricing logic.

Issue: Some labels still sound like instructions to a client, such as "what clients should read first" or "how to continue the conversation." Public institutional copy should describe collaboration conditions, project scope, and useful preparation without sounding like a support page.

What this reader needs:

- collaboration formats;
- project fit;
- deliverables and technical conditions;
- how a project is scoped;
- what information helps begin a serious inquiry.

### International Collaborator

Strength: English copy is mostly functional and understandable.

Issue: It should become more product/editorial in structure: less "go here next," more "this section provides..." or "this work brings together..." The tone should be clear, modest, and direct.

What this reader needs:

- stable English section names;
- concrete nouns over abstract site-navigation language;
- terms that translate well: Gallery, Production, Spatial, Writing.

### Returning Reader / Existing Follower

Strength: The archive depth and project history are valuable.

Issue: Returning readers can tolerate deeper detail, but first-time readers should not be forced through the same amount of explanation.

## Current Naming System

Hard classification rule:

- Gallery is the selected artwork layer. It should not contain commercial case
  studies just because they have strong images or public proof.
- Production Works is the commercial, delivery, engineering, event, stage, and
  collaboration layer. It should contain projects where the useful reading is
  scope, public context, technical condition, output requirement, and execution.
- Yu Jiayun 45㎡, Rain Singapore, and VRplay WORLD REMIX XR Hackathon are
  Production Works.
- Drop Flow, Kashiwa Daisuke audiovisual work, TIMER, MKE Terminal, and similar
  creative/research-led projects are Gallery candidates when presented as
  artworks.
- Do not classify pages from `showOnHome`. Use explicit Gallery and Production
  Works lists.

Use this naming system for public pages.

### 1. Gallery / Works

Role: selected artworks and public-facing art projects.

This is the gallery layer. It should not hold every collaboration, proof point, process note, or project version. It should feel like a curated artwork gallery.

Recommended Chinese label:

- 画廊
- 作品画廊

Recommended English label:

- Gallery
- Works
- Artwork Gallery

Use this for:

- Drop Flow
- Kashiwa Daisuke audiovisual collaboration
- TIMER
- a small number of other finished or public-facing works

Copy direction:

> 作品部分收录当前最能代表实践方向的艺术项目与公开呈现。它们展示时间、图像、声音和空间如何在不同现场与媒介中被组织。

English direction:

> Works gathers selected artworks and public presentations that best represent the practice across time, image, sound, and spatial experience.

### 2. Production / Production Works

Role: commercial cases, production projects, collaboration records, public nodes, delivery formats, and project references.

Production is broader than a service page. It is the place for Behance-like project information, collaboration cases, public production records, and delivery logic. Do not call this layer "work archive" in public navigation.

Recommended Chinese label:

- 制作
- Production
- 项目记录
- 制作项目

Recommended English label:

- Production
- Production Works
- Production Records

Use this for:

- commercial cases;
- stage visuals;
- event visual systems;
- delivery and engineering projects;
- public nodes;
- exhibition records;
- project versions;
- process records;
- older or supporting entries;
- Behance-like project information, but more restrained and production-oriented.

Copy direction:

> Production 整理制作项目、合作案例、公开呈现节点与交付参考，覆盖现场视觉、空间影像、沉浸内容和音画系统等方向。

English direction:

> Production gathers project records, collaboration formats, public presentation nodes, and delivery references for live visuals, spatial image work, immersive content, and audiovisual systems.

### 3. Spatial / Gaussian Samples

Role: spatial sample library.

This is a method-specific sample layer. It should not compete with Gallery or Production.

Recommended Chinese label:

- 空间
- 空间样本
- Spatial

Recommended English label:

- Spatial
- Spatial Samples
- Spatial

Copy direction:

> Spatial 收录 Gaussian Splat、空间保存、网页嵌入与 Vision Pro / XR 相关样本，呈现空间影像方法的实验层。

English direction:

> Spatial collects Gaussian Splat, spatial preservation, web embeds, and Vision Pro / XR samples that show the spatial-image research layer.

### 4. Writing / Methods

Role: methods, notes, and research.

Recommended Chinese label:

- 写作与方法
- 方法笔记

Recommended English label:

- Writing
- Methods and Notes

Copy direction:

> Writing 收录围绕作品、现场、交付、空间影像和制作系统展开的文本。它帮助读者理解作品背后的方法、判断和工作流。

## What Apple Does Well

Sources reviewed:

- Apple Human Interface Guidelines: Writing
- Apple Style Guide
- Apple Newsroom: Freeform
- Apple Newsroom: Vision Pro
- Apple Vision Pro product page
- Apple Developer: Vision Pro developer tools

Patterns to borrow:

1. Lead with what the thing enables.

Apple writes around capability and experience: a flexible canvas, spatial computing, shared collaboration, natural inputs. It does not over-explain where to click first.

Portfolio application:

Avoid:

> 如果是第一次访问，先看代表作品。

Prefer:

> Works presents selected projects that define the practice across sound, image, time, and spatial experience.

2. Use concrete section names.

Apple section titles are capability-based: "A Collaboration Space", "A Canvas Built for Creativity", "Enterprise APIs and Tools." They are not self-commentary.

Portfolio application:

Avoid:

> 怎么读这个站

Prefer:

> Site Structure
> Gallery, Production, Spatial, Writing

3. Keep the first paragraph stable.

Apple often follows this pattern:

- identify the product or section;
- state the main capability;
- name the relevant use cases;
- add one or two proof details.

Portfolio application:

> Works gathers selected artworks and public presentations by Ewan Qian. The projects move between live visuals, spatial image systems, audiovisual performance, and archival interfaces, with public presentations across exhibitions, festivals, and live venues.

4. Avoid unstable pronouns.

Apple's writing guidance says possessive pronouns should be used sparingly, and "we" can be unclear. For this portfolio, too much "you" also creates a support-page tone.

Portfolio application:

Avoid:

> 如果你是客户，先看 Production。

Prefer:

> Production provides collaboration formats, project-scope references, and delivery considerations for institutions, brands, curators, and production teams.

5. Use action labels that describe the destination.

Apple recommends clear, descriptive link labels. Avoid vague labels like "click here" or overly instructional labels.

Portfolio application:

Use:

- View selected works
- Open work archive
- Review production formats
- Read method notes

Avoid:

- vague "more" labels;
- conversational support-page headings;
- client-instruction headings.

## What Philips Does Well

Sources reviewed:

- Philips Innovation
- Philips LumiGuide design interview

Patterns to borrow:

1. Start from real needs.

Philips frames innovation as starting from real needs and working back from those needs. This is useful for Production copy.

Portfolio application:

> Collaboration usually begins by clarifying the site, audience, screen conditions, duration, and delivery format. These details help determine whether the project is closer to live visuals, spatial image work, previsualization, or delivery-spec support.

2. Use co-creation carefully.

Philips uses collaboration and co-creation as serious terms tied to workflow, early involvement, and long-term partnership.

Portfolio application:

> Projects can be shaped through early visual tests, spatial studies, and delivery planning, especially when music, venue, image system, and playback conditions need to be developed together.

3. Show expertise through process, not claims.

Philips explains research, prototypes, field observation, and feedback loops. It does not rely on adjectives alone.

Portfolio application:

> For complex live or spatial projects, early tests can clarify rhythm, screen relationships, spatial comfort, playback conditions, and versioning before full production begins.

## Proposed Homepage Structure

Recommended order:

1. Hero: identity and practice direction.
2. Gallery / Works: 3 to 4 selected artworks.
3. Site Structure: short routing module.
4. Public Proofs: 3 to 4 public nodes only.
5. Production: one compact bridge into project records and collaboration formats.
6. Writing / Methods: one compact bridge.

Remove from homepage:

- "ongoing projects" as a separate major layer;
- "more works" if it duplicates Production Records;
- long explanations of why records exist;
- any language that tells the reader they should read in a fixed order.

## Production Works Rule

Do not keep archive as a main public navigation item. If the route remains for compatibility, treat it as Production Works, not as a second gallery.

Recommended sections:

1. Commercial and Delivery Records
   - production entries sorted by year or priority;
   - excludes Gallery-only artworks unless there is a clear commercial,
     delivery, or engineering reason to include them.

2. Public Nodes
   - exhibition, festival, performance, publication, public presentation.

3. Spatial Samples
   - link into Spatial.

4. Versions and Process
   - versions, drafts, research branches, technical records.

Recommended Production Works intro:

> Production Works gathers commercial, stage, event, spatial, and delivery-based project records. Gallery remains the selected artwork layer; this page focuses on production context and project delivery.

Chinese:

> Production Works 整理商业、演出、活动、空间与交付型项目记录。Gallery 保留为作品画廊；这一页更关注制作语境与项目交付。

## Proposed Reading Module Replacement

The earlier reading-guide label was too instructional.

Replace with "Site Structure" or "Sections."

Chinese draft:

> 这个网站分为四个主要部分：Gallery 呈现作品画廊；Production 整理制作项目、合作案例与交付方式；Spatial 收录空间样本与网页嵌入；Writing 记录方法、研究与工作流。

English draft:

> The site is organized into four main sections: Gallery presents selected artworks; Production gathers project records, collaborations, and delivery formats; Spatial collects spatial samples and web embeds; Writing holds methods, research, and workflow notes.

Rows:

1. Gallery / 作品画廊

> Selected artworks and public presentations across live visuals, spatial image systems, and audiovisual performance.

2. Production / 制作项目

> Project records, collaboration formats, public nodes, delivery conditions, and production references.

3. Spatial / 空间样本

> Spatial preservation, Gaussian Splat, web embeds, and Vision Pro / XR sample paths.

4. Writing / 写作与方法

> Method notes, research texts, workflow reflections, and project essays.

## Recommended Naming Rules

Use these consistently:

- Gallery = selected artworks / gallery layer.
- Production = project records, collaboration, scope, deliverables, budget logic, public production references.
- Public Nodes = evidence of exhibition, festival, venue, performance, public presentation, usually inside Production Records.
- Writing = methods, research, essays, notes.
- Spatial = Gaussian Splat / spatial sample library.

Avoid mixing:

- Gallery and Production as two galleries.
- archive as a main navigation label.
- Production as only a service list.
- Spatial and Production as the same thing.
- Production and services as a list of skills.
- Writing as a blog if the entries are method records.
