New Media Engineering Control Model

新媒体工程控制论

如何把“按一下出一个效果”的 Demo，变成一个可以被观看、被演奏、被维护、被带进真实现场的新媒体系统？这份讲义从状态、反馈、稳定性与结构开始回答这个问题。

说明：“新媒体工程控制论”是一个面向创作实践的工作框架。它借用经典控制论、交互系统和工程设计中的概念，但不是一个已经被学术界确立的独立理论名称，也不试图替代控制论本身。

01 / LOOP

从“按钮触发什么”换成“系统下一步去哪”

最简单的新媒体原型通常把输入直接映射到结果：一个按键对应一个声音、一段动画或一个灯光变化。这种方式非常适合快速验证，但如果每次结果只取决于当前输入，它很快就会耗尽。

Result = Input ↓ 更深一层 ↓ Result = Input + State + History

实时作品真正开始变成“系统”，是因为它开始记住自己现在在哪里、之前发生过什么，以及新的输入应该如何改变下一步。

x(t+1) = F( x(t), u(t), d(t) )

这里不需要先学数学。把它直接读成：下一刻的系统 = 当前状态 + 人的操作 + 外部条件经过规则处理后的结果。

不要只问“这个按钮触发什么？”
先问“系统现在在哪里，我这个动作准备把它带到哪里？”

02 / STATE

State：系统必须知道“现在是什么时候”

State 不只是“换一个颜色主题”。它应该真正改变接下来发生的事情。一个实时系统可以只保存少量但关键的状态，例如：

SECTION · ENERGY · TENSION · DENSITY · SPACE · MEMORY ACTIVE AUDIO LAYERS · ACTIVE VISUAL LAYERS TIME / BAR / PHRASE

例如同一个 `HOLD` 在不同作品里可以代表“暂时不释放”“保持当前密度”“冻结结构变化”或“延长一个空间状态”。重要的不是按钮名称，而是它如何改变后续系统行为。

State 的价值：按钮没有变多，但同一个动作开始具有上下文。

03 / SIX QUESTIONS

一个可用系统至少要回答六类问题

State / 状态

系统现在在哪里？当前段落、能量、密度、历史是什么？

Feedback / 反馈

人的操作产生了什么结果？操作者能不能根据结果继续判断？

Stability / 稳定性

系统能不能避免无限变响、变满、变亮？失控以后还能不能回来？

Controllability / 可控性

不仅能不能增加，还能不能减少、退出、释放、召回、结束？

Observability / 可观察性

操作者是否知道当前 Section、Layer、Pending Transition 和 Reset 状态？

Robustness / 鲁棒性

早一点按、晚一点按、换个人操作、素材变化，系统是否仍然能工作？

这六个词不是为了让作品听起来更“工程”。它们只是帮你快速找到问题究竟发生在哪一层。

稳定不是“不变化”

稳定更接近：无论系统怎么变化，它仍然能回到可继续工作的范围。

MAX AUDIO VOICES MAX VISUAL DENSITY MAX LIGHT INTENSITY LIMITER · AUTO DECAY · PRIORITY · RESET / PANIC

可控不是“控制参数多”

ENTER / EXIT ADD / REMOVE BUILD / RELEASE ACCUMULATE / CLEAR RECALL / FORGET
04 / SHARED STATE

声音、视觉和灯光不必做同一件事

“同源”不等于每一个 kick 都必须对应一次闪光，也不等于视觉必须逐拍跟随音乐。更成熟的做法，是让不同媒介共享一个更高层的状态或意图。

STATE = PRE-RELEASE / 还不能释放 MUSIC → 减少完整鼓组，保留紧张感 VISUAL → 减少新对象，让已有结构继续积累 LIGHT → 保持空间狭窄，不完全打开

三种媒介没有复制彼此，却共同解释“还不能释放”这个状态。

Music
适合处理 rhythm、anticipation、build、drop、release，可以快速变化。
Visual
适合处理 persistence、accumulation、transformation、memory、return，可以跨越多个段落持续存在。
Light / Space
适合 reveal、hide、isolate、expand、blackout，直接改变真实空间经验。
05 / HIERARCHY

从一个事件到一整场 Show

很多作品的问题不是没有内容，而是所有内容都挤在同一个时间尺度。大型演出需要层级。

SHOW ↓ SET ↓ TRACK / PIECE ↓ SECTION ↓ PHRASE ↓ CELL / CAPSULE ↓ EVENT
EVENT
一个 kick、一次 flash、一个音符。
CELL
一个能自己成立 1–8 秒的小行为。
PHRASE
几个 Cell 的时间关系。
SECTION
OPEN、BUILD、PEAK、BREAK 这一类较长的状态。
TRACK / SET / SHOW
把多个局部结构组织成完整作品、整套演出与空间事件。

网页小乐器与大型现场并不是两个世界。
差别首先是控制层级、内容完成度和制作尺度。

06 / HYBRID CONTROL

人不需要负责所有精确细节

完全写死的时间轴可靠，但现场判断空间有限；完全开放的随机系统自由，却容易失控。很多实时作品更适合混合控制：

预先设计并试听过的可靠材料 + 系统自动维持时间与安全边界 + 人在少数关键位置做结构决定
系统负责

BPM、Clock、Quantization、音量、最大声部、密度预算、Transition Scheduling、Reset。

人负责

现在进入吗？还要等吗？应该加还是减？什么留下？什么时候释放？

机器处理精确、重复和风险；人处理意义、方向和判断。

07 / WORKFLOW

创作流程本身也是一个反馈系统

FRAME 确定作品怎样工作 ↓ FILL 加入声音、图像、文字、空间材料 ↓ FINISH 测试、删减、修正 ↓ FEEDBACK 让别人使用 / 观看 ↓ NEXT VERSION

AI Coding、Creative Coding、Three.js、Tone.js、MIDI、OSC、游戏引擎都属于实现层。真正决定项目能不能推进的，是当前版本解决什么问题、失败以后能不能回退、测试结果是否真正改变下一版。

一个好的创作工作流，本身也应该有状态、有反馈、有边界。

08 / TEST

四个问题，四个测试

先问四句话：
现在是什么状态？
我这个动作改变了什么？
我停手以后会发生什么？
我怎么把它收回来？

30 秒无输入

停手以后，系统是不是马上死掉？

返回测试

已经很满时，能不能主动回到更空？

新手测试

只解释 2 分钟，一个新操作者能不能完成一次 build → release？

观众测试

只看 Screen + Sound，别人看到的是作品，还是有人在测试网页？

10 / SUMMARY

一句话总结

新媒体工程控制论不是教你控制更多参数，而是帮助你设计：什么应该自动，什么应该由人判断；什么可以变化，什么必须被保护；一个动作怎样进入时间、状态和反馈，最后形成可以持续工作的作品。

这套框架最适合在真正的原型、排练、展览和现场测试中继续修正，而不是停留在概念层。
