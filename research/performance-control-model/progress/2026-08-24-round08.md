## CONTROL AUDIT

The canonical runtime already requires:

```text
ASSET → CAPSULE → SEQUENCE → LAYER → STATE → SHOW
```

and separates authoring UI from performer UI.

The latest prototype had begun to violate that separation: performance controls, sequence editing, accents, randomness and preset management were all visible at once.

That increases observability but also increases the number of wrong actions available during performance.

The corrected architecture is:

```text
             ┌─ SYNTH / FX
             │
INPUT → SEQUENCER → MIXER → OUTPUT
             │
             └─ VISUAL BEHAVIOUR
```

### SYNTH / FX

Defines what an event sounds like.

Per-lane parameters remain limited:

```text
TIMBRE
DECAY
```

Special transient vocabulary:

```text
AIR
METAL
GLASS
IMPACT
```

These are useful because recognisable special effects create high perceptual salience without requiring additional harmonic complexity.

### SEQUENCER

Defines when events happen.

The grid returns to binary event editing by default:

```text
PATTERN MODE
OFF / ON
```

Accent is separated into its own tool:

```text
ACCENT MODE
normal / accented
```

This removes the ambiguous triple-state editing interaction from the main workflow.

Probability is a lane-level event pass rate.

Randomisation is separated into mutation amount:

```text
10% / 25% / 50% / 100%
```

This makes `RANDOM` controllable rather than destructive.

### MIXER

Defines how much each lane occupies the output.

Each lane exposes only gain in the first implementation.

More detailed EQ/pan/send controls remain parked until a measured need appears.

## TWO UI MODES

### EDIT MODE

Expanded system:

```text
shared step grid
pattern paint
accent paint
15 / 20 step length
P1–P4 preset recall
probability
mutation amount
synth timbre / decay
special FX audition
8-channel gain mixer
auto preset HOLD / CYCLE / RANDOM
```

The user can drag across cells to paint values while transport continues running.

### PERFORM MODE

Compressed system:

```text
8 pads
A S D F J K L ;
4 state buttons
OPEN BUILD PEAK BREAK
RELEASE ALL
PANIC
```

Keyboard remains:

```text
key         → trigger one cycle
Shift+key   → latch lane
```

The performer does not need to see the sequencer, probability, synth parameters or mixer during normal play.

## IMMEDIATE ACK + QUANTIZED BODY

This is the main control-theory improvement in Round 08.

A fully quantized interface can be musically stable but perceptually sluggish.

A fully immediate interface feels responsive but exposes timing errors.

The new model is:

```text
INPUT
├─ immediate ACK       → short audio transient + visual flash
└─ semantic request    → quantized sequence body
```

Therefore:

```text
OBSERVABILITY / FEEDBACK
is immediate

STRUCTURAL EXECUTION
remains quantized
```

This combines responsiveness with stability.

## EVALUATION AGAINST CONTROL MODEL

### Stability

Improved: body remains scheduled by one authoritative transport.

### Controllability

Improved: edit actions and performance actions are separated.

### Observability

Improved: immediate ACK confirms input before quantized execution.

### Robustness

Improved: performance view removes destructive/random/edit controls.

### Expressivity

Improved: probability, accent, mutation, timbre and special FX exist in preparation without increasing front-stage input count.

### Depth

Improved: the same eight performance keys can address a much richer prepared system.
