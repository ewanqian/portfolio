# Performance Control Model — 2026-08-24 / Round 05

## ACTIVE RESEARCH TASK

Reduce the performance system to **one global sequencer with eight visible lanes**, while preserving high internal precision and low front-stage input complexity.

## CORRECTION FROM ROUND 04

Round 04 over-interpreted `8×8` as eight families each containing eight semi-independent internal sequencers.

That creates hidden complexity and weakens the main idea.

The corrected model is:

```text
ONE GLOBAL TRANSPORT
↓
ONE SHARED STEP GRID
↓
8 LANES
A S D F J K L ;
↓
VISIBLE EVENT / ACCENT DATA
↓
AUDIO + VISUAL BEHAVIOUR
```

Pattern Bank entries are only stored/recallable lane arrangements. They are not separate clocks or separate sequencers.

## D5 v3 — UNIFIED PERFORMANCE SEQUENCER

Implemented:

- one authoritative 128 BPM Web Audio transport;
- selectable global sequence length: 8 / 12 / 15 / 16 / 20 steps;
- eight visible lanes: ROUTE / FIELD / ORBIT / REWIND / CELLS / PARTITION / SCAN / DROP;
- every cell has three states: `OFF / WEAK / STRONG`;
- a shared top beat-weight row has `OFF / BEAT / DOWNBEAT` states;
- lane events multiply local cell strength by global musical beat weight;
- each lane has eight Pattern Bank slots, but the slots only save/recall that lane's visible row;
- keyboard A/S/D/F/J/K/L/; triggers one complete cycle of that lane;
- Shift + key toggles persistent LATCH for that lane;
- all latched and one-shot lanes remain synchronized to the same BPM and global step;
- visual sub-state is derived from lane identity + current step, so one language can contain many temporal visual states without becoming a collection of unrelated presets;
- OPEN / BUILD / PEAK / BREAK macros compress ENERGY / SPACE / TENSION / SWING into a few performance-level decisions;
- sound remains browser-native Web Audio synthesis with no external backing file requirement.
