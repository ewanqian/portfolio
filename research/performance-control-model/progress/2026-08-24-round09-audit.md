# Performance Control Model — 2026-08-24 / Round 09 Audit

## PURPOSE

Review D0–D5 v6 and distinguish:

1. ideas that proved useful and should be preserved;
2. useful ideas that were accidentally diluted or removed;
3. branches that became over-engineered;
4. the next architecture after the user identified that eight total materials are too few.

---

## PRIMARY CORRECTION

The previous iterations repeatedly conflated:

```text
NUMBER OF AVAILABLE MATERIALS
=
NUMBER OF ACTIVE SEQUENCER LANES
=
NUMBER OF PERFORMANCE INPUTS
```

These are different quantities.

A performance system can contain many prepared materials while exposing a small action vocabulary and bounding simultaneous activity.

Revised principle:

> Minimal input means a small semantic action vocabulary, not a small material library.

The live grammar can remain:

```text
TRIGGER
LATCH
RELEASE
RANDOM / MUTATE
MACRO
```

while the material library grows to 16–24 prepared audiovisual behaviours.

---

# WHAT WORKED AND MUST BE KEPT

## 1. Prepared audiovisual capsule from early D5

The strongest Touch:waves-like property was:

```text
ONE INPUT
→
IMMEDIATE CHARACTER
+
3–5 SECOND PREPARED MUSICAL PHRASE
+
3–5 SECOND VISUAL BEHAVIOUR
```

This was more immediately playable than later versions where each family became mainly a sequencer lane.

Restore the idea that a material has a coherent attack / development / release identity, not only step events.

## 2. Shared authoritative transport and quantized body

Keep one clock and common BPM.

Keep the distinction:

```text
IMMEDIATE ACK
→ performer knows the input registered

QUANTIZED BODY
→ prepared material enters on a valid musical boundary
```

ACK should feel like the material's attack, not a generic confirmation beep.

## 3. One visible global sequencer

Round 05 correctly removed hidden 8×8 mini-sequencers.

Keep:

- one shared timeline;
- selectable 15 / 20 step phrase lengths;
- multiple visible lanes;
- live editing while transport runs.

## 4. Round 06 live-edit interaction

Keep:

- stable grid DOM during playback;
- drag painting;
- explicit RANDOM action;
- TRIGGER vs LATCH;
- clear PLAY / STOP ownership;
- automatic preset evolution only when requested.

## 5. Round 07 curated musical roles

Keep lane-role composition and collision budgets.

Useful distinctions:

```text
anchor / pulse
low pressure
high cyclic motion
descending gesture
micro percussion
mid-band blocks
spectral sweep
structural impact
```

Keep curated P banks as starting points rather than empty preset slots.

Keep role-aware random and collision limiting.

## 6. Round 08 EDIT / PERFORM split

This is a major structural improvement.

EDIT may expose complexity.
PERFORM must expose only reliable live decisions.

Keep SYNTH / SEQUENCER / MIXER as backstage modules, but do not let their parameter count dominate the research.

## 7. Special transient / FX vocabulary

AIR / pressure-release / hiss-like sounds are particularly valuable because they create strong perceptual punctuation without consuming harmonic space.

Keep and expand a small library of distinctive FX behaviours.

---

# WHAT WAS ACCIDENTALLY DILUTED OR REMOVED

## A. Early D5 capsule identity

Later sequencer versions weakened the feeling that each key launches a complete prepared behaviour.

Restore full capsule identity alongside the sequencer.

A sequencer event should not reduce every material to a short note.

## B. Long visual behaviour

Early D5 had ROUTE / FIELD / ORBIT / REWIND / CELLS / PARTITION etc. as recognisable multi-second behaviours.

Later versions increasingly visualised individual step events.

Restore:

```text
MATERIAL ACTIVATION
→ long visual system / envelope

STEP EVENTS
→ internal perturbations inside that visual system
```

## C. Role-aware / collision-limited random

Round 07 contained a stronger concept of constrained randomisation than a generic mutation percentage alone.

Future RANDOM must combine:

```text
MUTATION AMOUNT
+
ROLE PROFILE
+
COLLISION / DENSITY BUDGET
```

## D. Automatic evolution as a performance action

AUTO CYCLE / RANDOM was useful and should not disappear completely inside EDIT mode.

PERFORM should eventually expose one safe high-level `AUTO / EVOLVE` action rather than all preset mechanics.

---

# WHAT WAS OVERDONE

## 1. Hidden 8×8 variation architecture

Eight families × eight semi-independent internal sequencers created invisible state and duplicated the time model.

Rejected.

## 2. Editable global beat-weight row

The explicit weak / beat / downbeat row made basic step editing less direct.

Musical accent should be a dedicated editing mode or derived from time, not mandatory top-level grid complexity.

## 3. Treating four states as the answer to every structural problem

OPEN / BUILD / PEAK / BREAK are useful macros or scene labels, but should not force every lane to share the same preset semantics.

They are optional high-level orchestration, not the core data model.

## 4. Too many low-level synth controls too early

SYNTH / SEQUENCER / MIXER is a useful architecture.

But exposing many oscillator-style controls is not the research contribution.

Prefer a few musically meaningful parameters and distinctive curated material.

## 5. Eight total performance materials

Eight simultaneous active layers may be a reasonable safety budget.

Eight total available behaviours is too small for the desired Touch:waves-like immediacy and surprise.

Do not solve material scarcity by making every lane internally more complicated.

---

# PROPOSED NEXT ARCHITECTURE

## MATERIAL POOL

Start with 16 prepared audiovisual materials, with room to grow to 24 later.

Do not make all 16 permanent sequencer lanes.

### GROUP A — 8 SEQUENCE / LAYER MATERIALS

Current structured families can remain as the first deck:

```text
ROUTE
FIELD
ORBIT
REWIND
CELLS
PARTITION
SCAN
DROP
```

They may be:

- triggered one-shot;
- assigned / kept as active sequencer lanes;
- latched;
- edited in the shared 15/20-step sequencer.

### GROUP B — 8 CAPSULE / FX MATERIALS

Add a second direct-performance deck of distinctive short behaviours, initially:

```text
AIR / HISS
METAL
GLASS
IMPACT
STUTTER / CUT
RISE / PRESSURE
REVERSE / SUCTION
RESIDUE / TAIL
```

These should primarily be direct 0.1–5 second capsules rather than eight additional continuous sequencer lanes.

This restores the high-variety prepared-sample / Touch:waves feeling without doubling continuous system complexity.

---

# ACTIVE-LAYER BUDGET

Separate availability from simultaneity:

```text
16 MATERIALS AVAILABLE
↓
MAX 6–8 CONTINUOUS / LATCHED LAYERS
↓
TRANSIENT FX MAY ENTER ABOVE THEM UNDER VOICE / DENSITY LIMITS
```

This improves expressivity without sacrificing stability.

---

# EDIT MODE

Backstage may expose:

```text
MATERIAL LIBRARY 16+
8 ACTIVE SEQUENCER SLOTS
15 / 20 STEP GRID
PATTERN BRUSH
ACCENT BRUSH
PROBABILITY
MUTATION AMOUNT
ROLE-AWARE RANDOM
COLLISION LIMIT
CURATED PRESET BANK
MINIMAL SYNTH PARAMETERS
8-CHANNEL ACTIVE MIXER
```

A material can be auditioned directly before being assigned to a sequencer slot.

---

# PERFORM MODE

Do not reduce the performance surface to only eight total behaviours.

Target next prototype:

```text
16 DIRECT PADS

8 structured / latchable materials
+
8 transient capsule / FX materials
```

Keep semantic actions few:

```text
tap / key      → TRIGGER
modifier/hold  → LATCH where supported
RELEASE        → remove persistent layers
AUTO / EVOLVE  → safe structural continuation
MACRO          → atmosphere / density / space
```

The performer sees more material choices but not more implementation detail.

---

# CONTROL-THEORY AUDIT

## Stability

Keep one transport, quantisation, max voices, active-layer limit and collision budgets.

## Controllability

Increase available materials, but keep each performance action predictable and reversible.

## Observability

Keep immediate material-specific ACK, visible latch / pending state and current active-layer count.

## Robustness

Prevent destructive editing in PERFORM mode; keep panic / release and bounded density.

## Expressivity

This is the current main deficiency.

Eight total materials are insufficient. Increase the prepared material field rather than adding more hidden state to each of eight lanes.

## Depth

Depth should come from:

```text
prepared capsule identity
+
shared sequencer detail
+
controlled randomisation
+
material selection
```

not from multiplying nested UI states.

---

# NEXT IMPLEMENTATION GATE

Do not rewrite the sequencer again.

Next prototype should keep the D5 v6 EDIT / PERFORM shell and change only the material model:

```text
8 current sequence materials
+
8 new transient / capsule materials
+
restore long 3–5 second visual/audio capsule envelopes
+
retain shared sequencer for the structured deck
+
restore role-aware collision-limited random
```

Then test whether 16 direct behaviours provide enough variety before expanding toward 24.
