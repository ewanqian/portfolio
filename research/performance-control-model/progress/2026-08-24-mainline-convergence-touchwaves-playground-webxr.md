# 2026-08-24 — Mainline Convergence Checkpoint

## ACTIVE QUESTION

How should the current browser audiovisual instrument research converge after the midterm review?

## RESULT

The research is now explicitly converged into one mainline:

```text
TOUCH:WAVES-LIKE DIRECTNESS
+
PLAYGROUND-LIKE GRAPHICAL / ADJACENT NAVIGATION
+
PERFORMANCE CONTROL MODEL
+
WEBXR-COMPATIBLE 2D → 3D SPATIAL LANGUAGE
```

This is not four parallel projects.

It is one performance-control research line with different reference and implementation layers.

---

# 1. Touch:waves contribution to the mainline

Retained:

- immediate audiovisual trigger response;
- curated compatible material;
- continuous backing / musical ground;
- quantized timing protection;
- distinctive special sounds and strong one-input identity;
- simple surface despite deeper preparation.

Rejected as fixed requirements:

- exact interface;
- exact sample set;
- fixed 26-key count;
- copying source or visual identity.

Research interpretation:

> Direct interaction only works at performance level when the material behind it has already been selected, composed and constrained for compatibility.

---

# 2. Playground contribution to the mainline

The key value is graphical and topological interaction:

- shapes communicate possible gestures;
- neighbours have semantic relationships;
- movement between states is itself meaningful;
- one path can create a larger temporal structure;
- playability can come from navigating a space rather than remembering mappings.

Research interpretation:

> The interface can carry part of the composition by embedding transition logic into spatial adjacency.

---

# 3. Performance Control Model contribution

The current system keeps:

```text
STATE
HISTORY
TRANSPORT
QUANTIZATION
SIGNAL GUARD
DENSITY / SPECTRAL BUDGET
AUTO SUPPORT
RESET / PANIC
```

The performer controls high-value decisions while the system maintains safe execution.

The main equation remains:

```text
Result = Input + State + History
```

The next spatial/topological interface is therefore not a new musical engine.

It is a richer control adapter to the same runtime.

---

# 4. WebXR / 3D direction

The current 2D graphical language is being designed as a projection of the future spatial system.

```text
NODE → VOLUME
EDGE → CORRIDOR / ARC
PATH → HAND TRAJECTORY
FIELD → NAVIGABLE SPACE
DWELL → SPATIAL DWELL / PINCH HOLD
POINTER SPEED → HAND VELOCITY
```

The 2D system must first prove that geometry genuinely improves control and performance form.

Only then does the WebXR branch resume device validation as the next interaction dimension.

---

# 5. Current artistic correction

The latest 4×4 prototypes showed that interaction sophistication cannot compensate for weak art direction.

Therefore:

```text
OLD RULE
preserve old effect because it already exists

NEW RULE
preserve only effects that pass current musical / visual / interaction quality gates
```

The visual and musical content will be redesigned for the new body / environment / interaction model.

The move from button / grid interaction to navigation means node content must evolve too.

---

# 6. Current style direction

Primary identity to test:

```text
PROFESSIONAL ELECTRONIC / EXPERIMENTAL PERFORMANCE
```

Characteristics:

- dark / precise / high contrast;
- electronic, spectral, metallic, noisy, hiss / electricity / pressure capable;
- strong full-screen composition;
- strobe / burst available but structurally controlled;
- not decorative UI graphics.

Borrow from Playground:

- readable shapes;
- intuitive affordance;
- adjacency;
- movement / discovery;
- playful navigation.

Do not let the final identity drift into generic cartoon UI unless testing proves that direction stronger.

---

# 8. Quality-control rule

A node or effect is retained only if it has:

1. a distinct identity;
2. a full-screen consequence;
3. a useful 3–6 second or longer behaviour envelope;
4. compatibility with neighbouring materials;
5. meaningful ENTER / STAY / EXIT / RESIDUE behaviour;
6. no dependence on generic cursor-following or XYZ translation;
7. a clear reason to exist in the route.

Audio must pass with the screen hidden.

Visuals must pass with controls hidden.

Topology must pass without the performer memorising arbitrary labels.

Build no more than 6–8 nodes.

Prove one route first.

The route must:

