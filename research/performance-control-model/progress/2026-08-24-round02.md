# Demo sequence for today

## D0 — Capsule Baseline

Purpose: establish the failure case.

```text
4 inputs
→ 4 immediate note/effect events
→ no quantization
```

Record 10–15 seconds.

Expected result: responsive but musically fragile / shallow.

## D1 — Quantized Capsules

Purpose: prove that imperfect input can still produce stable musical timing.

```text
4–8 prepared capsules
+ one Web Audio transport
+ pending queue
+ 1/4 or 1-bar quantization
```

Each capsule has:

```text
attack
→ development
→ release / residue
```

Record 20–30 seconds with deliberately early/late presses.

## D2 — 4-Layer Sequencer Study

Purpose: test whether structure can emerge mainly from layer activation/removal.

Initial layers:

```text
L1 PULSE / KICK
L2 LOW
L3 HIGH / PERC
L4 TEXTURE
```

Only expose:

```text
ADD
REMOVE
DENSITY
RESET
```

Perform:

```text
0 layers
→ 1
→ 2
→ 4
→ 2
→ 1
→ 0
```

Record 30–45 seconds.

Do not build the full 8-layer runtime today unless D2 is already stable.

## D3 — Shared A/V State

Purpose: stop treating visual as a decorative audio meter.

Use the same sequencer/state event data but allow audio and visual to interpret it differently.

Test two states only:

```text
OPEN
BUILD
```

Example:

```text
DENSITY ↑
Audio → more subdivisions / active events
Visual → stronger accumulation / reduced empty space
```

Record 20–30 seconds.

## D4 — Vision Pro Spatial Adapter

Purpose: prove that WebXR can control the same semantic actions used by the desktop demo.

Do not create a second musical engine.

Minimum mapping:

```text
pinch → TRIGGER / COMMIT
left/right hand region → select layer
hand depth or distance → DENSITY / WEIGHT
release / exit → REMOVE / RELEASE
```

Required visible evidence:

- immersive XR starts;
- hands/head tracking visible;
- at least one spatial action changes the same runtime state used by desktop input;
- status labelled `IMPLEMENTED`, then `TESTED` only after actual device run.

# Exact webpage test order

Use this sequence every time:

1. Reload.
2. Unlock audio with one explicit user gesture.
3. RESET; verify all states known.
4. Do nothing for 10 s.
5. Trigger each capsule once.
6. Deliberately press early/late.
7. Repeat one trigger 8–16 times.
8. Build layers 0→1→2→4, then release 4→2→1→0.
9. Perform once for 45 seconds without debugging.
10. Record screen + system audio.
11. Write only `WORKED / FAILED / NEXT CHANGE`.
