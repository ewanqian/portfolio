作品简介

Work Statement

《无需进一步输入》围绕自动化与人类判断之间的关系展开。作品关注人的输入、修正与偏好如何逐步进入系统，并使系统最终呈现出能够自行运行的状态。

当持续操作减少以后，人的判断并未随之消失。它仍可能以被选择的视觉模块、规则、参数、转移关系、权重与历史记录继续影响系统。作品因此把“自动运行”理解为一种判断被内化后的状态。

Direction update / 2026.08.15

当前方向进一步从“关于自动化的一条影像”发展为“一套能够实际运行的生成式音画系统，以及由该系统产生的单通道影像与现场版本”。概念需要进入真实运行机制，而不只停留在作品说明中。

V0 runtime / 2026.08.14

已实现（私人原型）： 6 个可持续 visual behaviours、加权状态转移、音频输入接口、NEXT / HOLD / AUTO、操作日志。未实现： 根据操作历史自动改写转移权重，以及任何“系统已学习艺术家”的表述。公开页不展示原型画面冒充最终作品。

AI 的位置

AI as Production Relation

AI 当前不被设定为最终画面的唯一生成器。更重要的角色发生在代码协作、视觉算法候选、状态逻辑和系统结构的形成过程中。

AI 可以扩大艺术家能够迅速测试的形式可能性；艺术家负责筛选、删减、修改、决定持续时间与空间关系，并判断哪些结果真正进入作品。最终的系统保存的是这些经过判断后留下来的结构。

AI 生成可能性，人形成判断，系统继续携带这些判断运行。

运行结构

Runtime Structure

Visual Vocabulary

先建立少量完整 visual behaviours，而不是直接剪出一条时间线。V0 为 6 个状态：FIELD / LINES / ARCS / RECT / ACCUM / SPARSE。每个状态都可以持续运行，并具有统一但不同的形式规则。

Implemented · Private V0 · Awaiting visual QA

State Machine

状态通过 entry、duration、behaviour、exit 与 transition weight 组织时间。V0 已具备加权转移与 MANUAL / HOLD / AUTO。基于操作历史的权重自适应尚未实现。

Implemented core · Developing tuning

Audio Structure

音乐不只控制尺寸或亮度。V0 已接入麦克风分析与内部 pulse fallback，用 energy / onset 门控 AUTO 转移与局部事件。完整 phrase / bar 结构仍在开发。

Implemented interface · Developing structure

Human Control / History

现场版本保留 NEXT / HOLD / AUTO。操作可写入日志。根据日志自动改写持续时间与转移权重属于后续实验，当前不得写成已实现能力。

Controls implemented · Preference history planned

作品形态

Three Manifestations
Gallery

持续运行的系统

观众面对一套不断变化、但不完全重复的音画过程。控制界面可以被隐藏，作品只显示系统运行的结果。

Film

8–10 分钟影像版本

从系统长时间运行中形成或选择一个单通道版本，作为当前展览交付。影像是系统的一次 manifestation。点云与数据流图谱方向见 Issue #24，与系统 V0 并行。

Live

个人音画演出系统

音乐实时进入，系统自主运行，艺术家只进行少量关键干预。长期可继续发展为个人现场视听工具与作品。

作品结构

Artwork Framework

技术 / Technology

V0 实际使用 Web Canvas 2D、WebAudio 与浏览器状态机。候选仍包括 WebGL / Processing / p5.js。最终技术栈尚未锁定，技术选择服从视觉语言与现场稳定性。

Developing

媒介与形式 / Medium & Form

生成式音画系统、单通道影像与现场表演系统共同构成作品。时间从固定剪辑进一步转向由状态、转移与运行过程共同组织。

Defined / Developing

艺术语言 / Artistic Language

进入、停留、回返、退出；重复中的偏差；修正后的残留；已经消失的输入继续改变当前结构。作品需要避免沦为普通“漂亮生成动画”。

Developing

艺术问题 / Artistic Inquiry

当人的经验、修正与偏好已经进入系统，一个看似自主运行的系统中还保存着多少人的判断？当操作停止以后，作者是否真的离开了作品？

Active Inquiry

当前问题

Questions in Development
当 AI 让大量形式可以被快速实现，艺术家的工作会不会更多落在选择、删减、组织和判断上？
当这些判断被写回软件结构，系统是否开始携带一个创作者过去的判断历史？
一件作品能否同时是一段影像、一套乐器和一套持续演化的运行规则？
“无需进一步输入”究竟意味着系统自主，还是意味着人的判断已经被提前吸收？

相关语境

Media Art Context / References

sascacci + ksmt — touch:waves

NTT ICC ↗

参考其“visual instrument”的组织逻辑：一个输入对应完整的声音—视觉行为，软件本身成为可演奏媒介。本项目不复制其白线视觉或代码，而把单次 trigger 进一步扩展为可持续运行的 state / behaviour。

Casey Reas — Process

REAS ↗

Process 把规则、软件执行与持续变化的图像连接起来，使“产生图像的系统”本身成为作品结构。这里的联系主要在规则、运行和开放结果，而本项目进一步加入音画、AI-assisted coding 与人工判断的沉积。

Sougwen Chung — Drawing Operations

Artist site ↗

其长期实践将人的动作、机器人、机器学习和共同表演放进同一反馈过程。对本项目更重要的启发，是 AI / 机器可以改变创作关系本身，而不只负责输出一张“AI 图像”。

Memo Akten — Learning to See

Artist site ↗

作品关注机器如何通过已有经验过滤当前输入。本项目把类似问题转向创作判断：当系统保存并重新调用过去的选择，它是否开始通过这些历史继续运行？

Daito Manabe — computational audiovisual practice

Artist site ↗

音乐、计算、身体信号、实时视觉与 AI agents 可以在现场、装置和表演中构成连续实践。这里的参照帮助把本项目放回更长的 computational / audiovisual art 语境，而不必把它收缩成单纯“AI art”。

边界

What This Work Should Avoid
不复制 touch:waves 的视觉皮肤；不把 AI 使用本身当作主题；不让“自主”只存在于文案；不把随机等同于生成；不让画面退化为高级 screensaver；在 preference history 真正实现之前，不宣称系统已经“学会了艺术家”。
