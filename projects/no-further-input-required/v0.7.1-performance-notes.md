# No Further Input Required v0.7.1 — Performance Revision Notes

> 2026-08-22 / derived from hands-on evaluation of Interactive v0.7

## Main discovery

The strongest performative quality of v0.7 is not any individual visual state. It is the relationship between the physical keyboard and the audiovisual runtime.

The performer can learn the spatial order of:

```text
1 2 3 4 5 6 7 8 9 0
Q W E R T Y U I O P
A S D F G H J K L
Z X C V B N M
```

and deliberately play ordered gestures such as left-to-right rows, descending rows, repeated cells, or directional progressions. The continuous musical system supports these patterns and makes even simple keyboard movement feel composed.

## Design rule

Future revisions should treat the 36-key QWERTY topology as a reusable spatial score.

Different visual states may transform the topology into:

- parallel rows;
- warped grid;
- concentric arcs / circles;
- mirrored rows;
- cell matrices;
- partitions / bands;

but the relational structure between keys must remain learnable. A performer should be able to transfer motor memory from one visual state to another.

## Avoid

- visual events that appear at positions unrelated to the played key;
- state-specific mappings that destroy learned QWERTY adjacency;
- cursor-following as the primary interaction;
- visual effects that only translate an object without changing its behaviour;
- hard visual cuts between states with no temporal preparation.

## v0.7.1 implementation targets

1. Preserve the v0.7 harmonic / rhythmic architecture and global BPM clock.
2. Draw a subtle visual skeleton of the current keyboard mapping.
3. Map every keyboard event to the transformed position of the same key.
4. Let each state deform the same topology rather than invent an unrelated layout.
5. Rework ORBIT so an input launches an event / impulse instead of moving a center point.
6. Add a NEXT-state cue before automatic transitions.
7. Crossfade states rather than replacing the full screen abruptly.
8. Keep the original v0.7 unchanged as a historical reference.

## Future performance/game direction — not implemented yet

Possible later experiments:

- multiple musical structures / song modes sharing the same keyboard topology;
- phrase challenges: play a row, diagonal, symmetry, repetition, or sequence;
- performance scoring based on timing, spatial order, rhythmic consistency, or pattern completion;
- a music-game layer that teaches the instrument through play without reducing it to a conventional piano interface.

These are follow-up directions, not requirements for v0.7.1.
