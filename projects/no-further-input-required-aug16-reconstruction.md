# 《无需进一步输入 / No Further Input Required》— 2026-08-16 Reconstruction + Requirement Ledger

> Purpose: recover the exhibition-oriented visual system that existed by 2026-08-16, then separate that historical visual vocabulary from later interaction / workshop / performance branches.
> Method: minimal-change / reuse-first reconstruction. Reuse documented states and existing Canvas patterns before inventing new systems.

## A. Historical checkpoint: 2026-08-16

Source: `projects/no-further-input-required-devlog-2026-08-16.md` on the historical `agent/nfir-v03-devlog` branch.

The 2026-08-16 system already had six independent visual behaviours, a fixed 1→2→3→4→5→6→1 cycle, hidden controls, and a pure black/white presentation. The six states were:

1. **Constraint / 约束机构**
   - regular pulse families: column / row / local radial impact
   - secondary horizontal / vertical / diagonal supports
   - motion is pulled back by constraints rather than free jitter

2. **Index Field / 索引场**
   - grid skeleton
   - boxes / nested index / offset vertical strips / bidirectional folded lines
   - internal morphs remain inside one indexing rule instead of switching to unrelated visuals

3. **Projection / 高维投影**
   - twelve projection windows in three groups
   - different rotations / planes / scale cycles
   - periodic convergence → synchronization → divergence

4. **Signal Layers / 信号层**
   - quiet propagation baseline
   - scan / latch / deactivate / burst rhythms
   - multiple asynchronous clocks
   - digits only as brief register / calibration / onset traces, not permanent HUD

5. **Quantized Memory / 量化记忆**
   - cellular automaton / multiple binary update rules
   - background triangular traces vary in direction / density / subdivision
   - memory is carried by both active points and weak structural residue

6. **Recursive Assembly / 递归装配**
   - rectangle subdivision + reassembly
   - one or two levels of internal diagonal subdivision
   - calm / fast-response / staggered-follow timing
   - motion can follow energy / phrase without becoming simple 1:1 audio reactive

### What the 8/16 checkpoint had already decided

- default screen should be the artwork, not explanation UI;
- controls may exist for development but should stay hidden by default;
- six states must have genuinely different algorithms and time behaviours;
- line weight / brightness hierarchy matters at full screen and thumbnail scale;
- the system should become increasingly playable / time-structured without turning into a dashboard;
- AI visual analysis, preference learning and “the system learned the artist” were not implemented and must not be claimed.

## B. Artwork requirements collected from later confirmed decisions

These are not all 8/16 facts. They are later corrections that define how the recovered 8/16 language should be used now.

### 1. Exhibition version ≠ interactive instrument

The artwork line must be kept separate from later keyboard / workshop / performance-control experiments.

For exhibition presentation:
- autonomous playback;
- no required audience interaction;
- no NEXT / HOLD / AUTO visible controls;
- no 26-key interface;
- no large HUD / dashboard;
- browser versions may remain as research / behaviour references.

### 2. Core artistic question

The work should make the viewer feel that earlier input has not disappeared. Human input, corrections, selections and preferences become rules, paths, parameters and historical residue that continue shaping later behaviour after new input decreases.

The image must communicate this without depending on explanatory text.

### 3. Current final-duration target

The current exhibition target is approximately **3 minutes, looped**.

Working dramaturgy:
- 00:00–00:35 REGISTRATION / 发生
- 00:35–01:25 ABSORPTION / 沉积
- 01:25–02:15 RECALL / 回返
- 02:15–03:00 REMAINDER / 余项

These are dramaturgical phases, not four fixed scenes.

### 4. Visual behaviour rule

Do not return to a simple six-preset demo reel. The recovered 8/16 states are a **behaviour library**.

They may:
- coexist;
- inherit traces;
- partially cover one another;
- return later in altered form;
- vary in density;
- leave residue that survives their own disappearance.

The useful historical language should be extracted from the six states, not replayed as six isolated showcases in the final artwork.

### 5. Density and pacing

The work needs strong sparse/dense contrast.

Allowed:
- very empty passages;
- concentrated local structures;
- gradual sedimentation;
- later subtraction;
- return of earlier material under changed historical conditions.

Randomness may create variation, but temporal order must come from history, timing and structural relationships.

### 6. Visual identity to preserve

Prioritize:
- black / white or very low colour interference;
- points / short lines / frames / boxes / transparent planes;
- indexing / partition / route / field structures;
- incomplete structures;
- residue / fragments with visible origin;
- calibration / registration marks only as brief traces;
- directional density structures, including the downward / diagonal formations seen in the earlier exhibition-oriented tests.

Do not reduce this to a generic outlined triangle animation.

### 7. What to avoid

- generic AI-tech visual language;
- permanent terminal / hacker HUD;
- state names printed on the artwork;
- text used to explain what the image failed to communicate;
- random effects with no history;
- simple `audio amplitude → particle count` mapping;
- calling structural residue “noise” when it is meant to be historical material;
- claiming preference learning, AI composition or system understanding if not implemented.

### 8. Sound relationship

Sound is not background music and not a seventh visual scene.

Useful internal sound states remain:
- SILENT / TRACE
- PULSE / REGISTRATION
- SEQUENCE / MEMORY
- DENSITY / ABSORPTION

Sound and image should read the same internal history / clock / density / recall variables in different ways rather than one directly driving the other.

### 9. Loop condition

The ending should approach the opening without becoming a clean reset.

A later loop should feel like the system has restarted while still carrying history.

### 10. Acceptance questions

A candidate exhibition version should pass these without reading a statement:

1. Can the viewer recognise that something from earlier is returning?
2. Does later structure visibly depend on earlier history?
3. Does the recall section create tension through return / alteration rather than merely more density?
4. When new input decreases, does the image still feel alive?
5. Does the loop feel like continuation rather than video restart?

## C. Reconstruction strategy used now

Following a reuse-first / minimum-code rule:

1. Do not build a new framework.
2. Reconstruct the six documented 8/16 states as a visual comparison page.
3. Use only browser Canvas and existing project visual primitives.
4. No audio, interaction system, settings panel or new dependency in this comparison pass.
5. Compare the states first; only the selected behaviours move into the 3-minute exhibition composition.
