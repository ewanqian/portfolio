# 1｜这是什么工作坊？

一段声音、一张图片、一次键盘输入，都可以成为一个系统的开始。

这场三小时工作坊不会从某一种软件的功能表开始，而是从最简单的“输入”开始：一个按键、一次鼠标移动、一段声音，如何经过规则与 Mapping，同时改变声音、图像和作品状态？

参与者将在统一的网页 Starter Kit 与 AI 辅助下，建立自己的第一个实时视听原型。

课程不要求编程或音乐基础。目标不是在三个小时里学会最多的软件，而是第一次完整走过：

**输入 → Mapping → Sound + Visual → State → Test → Showcase**

很多数字创作课程从软件开始：

```text
软件
↓
功能 / 参数
↓
效果
↓
组合成作品
```

这次工作坊把顺序反过来：

```text
一个输入
↓
规则 / Mapping
↙          ↘
声音         图像
↘          ↙
State / Feedback
↓
演奏 / 展示
```

软件只是实现这些关系的方法之一。

# 2｜什么是“音画同源”？

“音画同源”不是一个需要读者预先掌握的固定艺术史流派，而是我们在这次工作坊里用来描述一种创作关系的工作概念：

**声音和视觉不只是前后配合，而是尽可能从同一个动作、参数、数据或规则中共同产生。**

例如：

- 按一次键，同时触发声音与动画；
- 鼠标移动，同时改变滤波与图像尺度；
- 一个推子，同时改变声音密度与画面残影；
- 一个按钮，让系统从 Quiet State 切换到 Active State。

传统的音频驱动视觉通常是：

```text
声音已经产生
↓
分析音量 / 频率 / 节拍
↓
视觉跟随变化
```

同源控制更接近：

```text
Gesture / Input / Data
        ↓
      Mapping
      ↙     ↘
   Sound   Visual
```

声音与视觉都是系统的结果，真正被设计的是它们背后的共同关系。

# 3｜三个最适合普通读者的案例

## 3.1 Patatap｜网页为什么可以是一件乐器？

Patatap 是 Jono Brandel 与 Lullatone 合作的网页视听乐器。用户敲击键盘，A–Z 与空格会触发对应的声音和动态图形。

它的结构并不复杂，核心是非常直接的一对一 Mapping，但丰富的声音、动画与即时反馈让用户很快获得“正在演奏”的感觉。

> **一个网页不一定只是信息页面，也可以成为一件数字乐器。**

资料 / 图片参考：
- https://patatap.com/
- https://www.jono.fyi/Patatap
- https://www.lullatone.com/news/patatap/

---

## 3.2 touch:waves｜从按键触发进入连续控制

**touch:waves（2021–）** 由 sascacci + ksmt 创作，是一件可以直接在显示屏上触摸演奏的 visual instrument。

作品把触摸位置、移动过程与声音和视觉变化连接起来。它特别适合解释本工作坊的第二层目标：不只是“按一下出现一个效果”，而是设计一套可以持续操作、具有连续变化的演奏界面。

资料 / 图片参考：
- https://sascacci.com/
- https://www.ntticc.or.jp/en/archive/works/touch-waves/

---

## 3.3 Golan Levin / AVES｜声音和视觉能不能被当成同一种材料？

Golan Levin 在 MIT Media Lab 发展的 **Audiovisual Environment Suite（AVES，1998–2000）** 是一组实时视听系统。使用者通过手势，在同一个界面中实时生成抽象动画与合成声音。

AVES 使用 **audiovisual substance / 视听物质** 作为界面隐喻：与其把声音和画面理解成两个最后再拼起来的文件，不如把它们理解成同一种动态材料的两个维度。

资料 / 图片 / 视频参考：
- https://acg.media.mit.edu/people/golan/aves/
- https://www.flong.com/archive/projects/aves/index.html
- https://acg.media.mit.edu/people/golan/scribble/

# 4｜Mapping：为什么“一个按键”值得讲？

一个按键看起来只有 0 和 1，但数字系统可以把它扩展成：

- 按下：触发声音与图像；
- 按住：进入持续状态；
- 连续快速按：根据速度增加密度；
- 两次按键之间的间隔：成为新的连续参数；
- 同一个按键：同时控制多个声音与视觉参数；
- 触发之后：让系统内部继续运行随机、延迟、物理或连锁规则。

数字乐器的性格不只来自“有什么按钮”，更来自按钮与系统之间怎样被 Mapping。

研究参考：
- https://nime.org/proc/nime2002_hunt/

> **我们不是在教你增加更多按钮，而是在练习如何让一个动作产生值得演奏的结果。**

# 5｜我们的相关实践

## 5.1 yiyisogreen｜一个控制信号进入声音与视觉两套系统

在 yiyisogreen 的 Audio Visual 实践中，控制器并不只是负责播放视觉素材。

例如《Wet Dream》（2023）中，控制器信号同时进入声音与视觉：一方面参与电子声音采样的切割与速度变化，另一方面控制视觉场景。

```text
Controller
↓
Mapping
↙        ↘
Sound    Visual
```

这一案例可以直接用于解释“同源控制”：同一个 Gesture 怎样同时被分配到多个结果，并形成可演奏的关系。

素材建议：由 yiyisogreen 本人提供 1 段现场 / 屏录 GIF + 1 张作品图。

---

## 5.2 钱誉文 Ewan Qian｜《无需任何输入》：从外部信号到视觉乐器

《无需任何输入》是 Ewan 当前正在发展的最新作品之一，目前处于 WIP 阶段。

作品首先被设定为一件 **Visual Instrument / 视觉乐器**。它不以播放一段预先完成的视频为目标，也不要求视觉系统自己发声，而是把重点放在：

**外部输入 → 分析 / 转译 → 规则与状态 → 视觉结果**

外部输入可以来自声音、手势或其他实时信号。作品关心的是：一个不可见或抽象的输入进入系统后，怎样通过 Mapping 被转译成可以观看、控制并持续变化的视觉结构。

```text
Gesture / Sound / External Signal
              ↓
        Mapping / Rule
              ↓
         Visual State
              ↓
       Realtime Output
```

这个作品目前**不是用来证明“声音和视觉已经完整同源”的案例**。它更准确地说明了本工作坊的创作方法来自哪里：**先找到输入，再设计输入与结果之间的关系，而不是先打开软件寻找效果。**

工作坊会在这套视觉乐器结构上继续加入声音分支，把同一个输入进一步连接到 Sound + Visual，从而练习真正的“音画同源” Mapping。

- 1 张完整运行界面 / 视觉状态截图；
- 1 张 Input → Mapping → Visual 的极简结构图。

# 6｜为什么是网页？

网页足够轻：键盘、鼠标、触摸、音频和视觉都可以进入同一个运行环境，也方便快速修改、全屏运行和分享。

网页在这里更像一张公共工作台：先让初学者理解系统，再决定未来进入哪一种专业工具。

---

# 7｜AI 在这里做什么？

AI 主要帮助：

- 建立网页骨架；
- 修改代码与参数；
- 解释报错；
- 把个人声音、图片与交互关系接入 Starter Kit；
- 快速生成不同实现方案供人比较。

但作品的输入、Mapping、选择、删减和最终判断仍由人决定。

**人决定 → AI 执行 → 人运行 → 人判断 → 再修改。**
