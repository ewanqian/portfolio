**钱誉文 Ewan Qian · Performance System / Field Journal · 2026**

在俱乐部的控制台前，视觉演出有一个很实际的问题：音乐一直向前走，画面却不应该一直做加法。什么时候保持不动，什么时候让某一层慢慢出现，什么时候突然停下？这些决定，比拥有多少段视频更接近现场演奏本身。

我把目前使用的这一套方法称为 **BPM System**。它不是某个插件，而是一种组织时间和操作的方式：让一部分图像自己持续，让另一部分与节拍保持联系，再把关键的进入和退出留给人。REACTOR Opening 的现场经验，是这一方法的一次观察与实践。

下文先用最少的轨道说明它怎么工作，再把方法放回专业演出行业中：为什么有的视觉必须能被手动演奏，为什么大规模巡演又需要预编程，以及视觉、灯光、音乐怎样共享同一场演出的结构。

# 01 / 一张画面，三种时间

把画面想成三件可以同时发声的乐器。

**持续时间 / Continuous**：像低音的铺底，一段缓慢变化的影像可以连续存在几分钟。它让舞台有空间感，未必每拍都动。

**节拍时间 / Clocked**：像稳定的节奏组。一条脉冲、遮罩或发光线条可以按 BPM 重复。它负责让速度被看见，但不负责决定音乐是不是已经进入高潮。

**瞬时时间 / Human**：像现场演奏中的重音或休止。表演者可以按一下按钮、推入某条轨道，或者突然撤掉所有强光。它的价值正是“不一定按预设时间发生”。

**因此，系统不等于自动化。** 这三种时间可以叠加，也可以被分别撤除。真正的控制，是随时知道哪一层应该继续，哪一层应该停。

# 02 / 三条轨道，就能开始演奏

在 Resolume Arena 中，**Layer（图层）**可以理解为三条并行的视频轨道。每条轨道都有自己的 **Opacity（透明度）**：0% 不显示，100% 完全参与合成。推子改变的是这一层在最终画面中的存在程度，而不只是素材播放与否。

最小工程只需要：

- **L1 / BASE — 空间**：持续影像或实时场景，构成舞台的底色。
- **L2 / CLOCK — 速度**：有规律的脉冲、结构运动或亮度包络，按 BPM 运行。
- **L3 / HIT — 重音**：一次扫描、闪光或突发动作，可以被人工触发并退出。

先用鼠标拖动三条 Layer 的 Opacity。只留 BASE，是 **OPEN**；慢慢推入 CLOCK，是 **BUILD**；短暂加入 HIT，是 **PEAK**；将 CLOCK 与 HIT 拉回零，是 **BREAK**。四个状态的区别，不在切换了多少素材，而在画面的密度如何被控制。

右侧的小型混合器可以直接试这四个状态。它演示的是图层关系；实际的视觉层还可以有 Blend Mode、Effect 和更丰富的实时参数。

# 03 / 从鼠标到控制台：谁负责哪一个动作

鼠标足以验证最小系统，但在演出中，它不适合连续地同时控制几条轨道。最直接的升级是一台带推子的 **MIDI 控制器**：将前三支推子分别映射到 L1、L2、L3 的透明度。这样可以一边听音乐，一边用手逐渐展开或收起不同画面。

**BPM** 负责节拍速度，**Opacity** 负责层的混合，**Trigger** 负责某次事件的进入。三者不必绑在一起。比如 CLOCK 可以连续按拍运行，但是否让观众看见它，取决于你什么时候把推子抬起来。

外部系统也可以加入：TouchDesigner 或网页控制器能够通过 **OSC** 将参数送往 Arena；脚踏可以承担 Tap Tempo 或瞬时 Trigger，让双手继续操作推子。它们只是不同的输入设备，最终都应服务同一套清楚的操作关系。详细映射与排练步骤在文末附录。

# 04 / 为什么专业演出并不只有一种同步方式

现场视觉通常横跨三类工作。第一类是**自由即兴**：DJ 可能临时延长过渡，VJ 必须能听见变化并立即作出回应。第二类是**预编排演出**：一首歌的灯光、视频与舞台运动需要在固定位置准确出现，往往使用 Cue 和 Timecode。第三类是**实时生成**：画面的一部分来自摄像机、动作、传感器或图形引擎，参数在表演过程中不断变化。

实际制作常常混合三者，而不是选择其中一种。看起来完全同步的演出，背后可能是预先设计的时间轴；看起来随机的图形，也可能被严格限制在一定亮度、密度与色彩范围内。

**专业化不是把人的判断全部交给机器，而是让可预测的事情可靠，让需要选择的地方始终可以选择。**

# 05 / 五个值得研究的参照

下面这些案例并非我个人创作的直接师承，而是把 BPM System 放入当代实时演出实践时，最值得对照的不同技术路线。

**2010｜1024 Architecture × GarageCube：让空间映射成为演出工具。** [MadMapper 的诞生](https://madmapper.com/aboutus)来自艺术家与软件工程团队的合作：先解决在真实空间里实时映射的问题，再让创作者把注意力移回内容。值得学习的不是某种视觉外观，而是**把舞台几何、输出和控制流程当作创作系统的一部分**。

**2016｜Nosaj Thing × Daito Manabe：实时图像进入音乐表演。** [NO REALITY TOUR](https://research.rhizomatiks.com/en/works/nosaj_thing_coachella.html)把实时 3D 扫描、移动灯光和音乐现场组织为同一场演出。Rhizomatiks 的项目署名中明确区分了创意／技术导演、视觉程序员与技术支持。这说明复杂的实时作品不是一条炫目的素材，而是一套需要分工、调试和共同排练的系统。

**2020｜DJ KRUSH × Daito Manabe：读取乐器的动作，而不只读取音量。** [CONNECTED WORLD](https://rhizomatiks.com/en/work/connected-world/)分析转盘和混音台的运动，将搓碟等 DJ 行为转化为实时视觉。对我的启发是：节拍只是音乐信息的一种，**表演者正在做什么**本身也可以成为视觉输入。

**2022｜Rhizomatiks：音乐、灯光与空间设备共同工作。** [Light Sync Device](https://www.daito.ws/en/archive/nosaj-thing/)使用音乐时间信息与指令触发两类机制，把设备内预存的灯光图案与实时响应叠加。它与“持续 + 节拍 + 人工事件”的区分形成可比较的工程思路，同时提醒我们：舞台屏幕以外的整个环境，也可以是同一套演出语言的一部分。

**2026｜Comix：把实时视觉交付为可操作的巡演系统。** 在其[实时演出工作流程](https://www.thisiscomix.com/real-time)中，Notch 场景会向操作员开放模糊、拖尾、粒子密度、强度等参数，同时考虑摄像机、Timecode、灯光与现场硬件。这里最值得借鉴的是：**画面之外还要交付可调节的控制、预演方式与稳定运行的方法**。

这些实践从 Club 演出延伸到大型舞台，但问题是一致的：什么由机器重复，什么由演出者决定，什么必须由整个制作团队共同确认。

# 06 / 当画面遇到灯光：如何协作

在真实现场，LED 屏幕不是独立存在的。它与追光、染色灯、频闪、激光以及观众所处的暗场共享同一空间。如果所有部门都只想把自己的画面做得更亮，高潮很快就会失去层次。

因此，VJ 与**灯光设计师 / Lighting Designer（LD）**至少需要一套共同语言：

- **OPEN / BUILD / HOLD / PEAK / BREAK**：这一段要进入、推进、保持、释放还是收束？
- **BLACKOUT**：谁负责黑场？是否需要一起回到安全状态？
- **Brightness / Color**：屏幕与灯光的亮度上限、主色调和互相让出的空间是什么？
- **Cue / Timecode**：哪些动作固定在歌曲位置，哪些由操作员听音乐后手动触发？

大型巡演通常先设计 Cue、进行 **Previsualization（预演）**，再到现场编程与技术彩排。比如 Comix 在其[制作流程](https://www.thisiscomix.com/services)中列出概念与预演、内容制作、编程、排练及最终移交；Notch 的 [Alicia Keys: ALICIA UNSTAGED](https://www.notch.one/madewithnotch/alicia-keys-alicia-unstaged) 案例还说明实时参数让颜色、动画速度和灯光能适应现场表演。这些做法比单纯讨论“使用哪款软件”更接近完整的演出工程。

# 07 / 回到 REACTOR：从屏幕看向整个房间

REACTOR 的照片中，红色机械结构、激光、DJ 台和观众并不处在同一个亮度层级。近处的人是剪影，屏幕上的形态很强，光束又把画面延伸到舞池。这提醒我：视觉不是只在控制台预览窗口里成立，还必须在空间中成立。

我会把这种现场经验保留在 BPM System 的基本设计里：**BASE 建立空间；CLOCK 让运动获得方向；HIT 只在需要时出现；BREAK 把舞台重新交还给音乐与现场。**

从三条简单轨道开始，可以逐渐扩展到更复杂的实时引擎、摄像机、OSC、灯光与舞台预演。重要的不是一开始拥有完整系统，而是每增加一个部分，都能说明它承担了什么任务、由谁控制、出了问题如何退出。
