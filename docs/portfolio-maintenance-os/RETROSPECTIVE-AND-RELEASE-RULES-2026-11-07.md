## 十个明确踩坑点与修复规约

| 坑 | 根因 / 具体实例 | 下次强制动作 |
|---|---|---|
| 1. 把新快照当“唯一数据库” | `database/works.json`、`content/project-registry` 和 `content/works/*.json` 同时存在，部分 ID 并不相等 | 先看 crosswalk；对象身份、版本、发布快照分别治理；不凭相似标题强行合并 |
| 2. 前端改完却没有发布正确 JSON | 自定义域名曾在 `/content/*.json` 返回 SPA 的 HTML，HTTP 200 但内容错 | 发布包必须同时包含 `assets/data` 与旧兼容路径；QA 同时检查 Content-Type、JSON 结构和 ID 集合 |
| 3. 新版页面删掉原版媒体 | Kashiwa 历史十段视觉与六个 MANA 链接在新网页缩减后丢失 | 改页前读历史 Markdown／Git 历史／外站资料；提交保护规则，防媒体和合作署名静默减少 |

| 6. 履历与英文 PDF 采用位置匹配 | English R1.1 中 043（AI 盛典）与 044（国家地理矿晶）文字错位 | 以永久 ID/URL 连接中英文字；构建和审计时检查命名实体与角色；不能用列表序号推断身份 |

## 从现在起的高效操作协议

### 每轮只做一批：操作顺序固定

1. **读取状态**：`START-HERE.md`、manifest、最近 commit / PR。发现已通过的验收**不要重新从零设计**。
2. **确定批次边界**：例如“全部英文记录、索引切换、正式 PDF”作为一个批次，最多一次结构迁移；先记风险和回滚点。
3. **批量执行**：先修 canonical 数据，再统一生成子页面／索引／PDF；不要靠单个 Agent 手动遍历 61 份 HTML。
4. **测试阻断**：至少 `audit:graph`, `audit:cv`, `audit:preservation`, `audit:media`，发布后 154 HTTP 回归（含响应内容和图片 MIME）；新脚本要记录版本号。
5. **提交后复读**：验证 HEAD、内容、工作流结论；只说自己实际确认的范围。
6. **更新交接**：START-HERE 只保留一条当前重点；manifest 由可检查的事实状态更新；详细诊断在 handoff，不在公共艺术网页留 TODO。

### 目前合理的剩余收尾批次（估算，不是保证）

- **批次 A（本轮）— 可在仓库内执行**：保存复盘；恢复 57 条英文并纠正项目 ID；做双语索引/记录页生成与一致性检查；冻结旧错误 PDF 的出版状态。
- **批次 B — 正式双语发布（已完成）**：同一 CV 数据生成中英 3 页/60 链接 PDF、打印网页和正式站点入口；生产端 160/160 与精确校验码通过。剩余的不是重制 PDF，而是六类页面视觉验收。
- **批次 C — 素材与外站验收（可能被原始文件和授权阻塞）**：核对 MANA/Bilibili 真实播放、VAOE 四组原片和 AR、NFI 最终画面、Dialogue 作品静帧及 27 项版权署名；完成精选首页 30 秒与策展／制作 3 分钟版本。

**预计（在 R1.2 已上线之后）**：工程/网站正式视觉验收仍需约 **1 次集中验收，出现实质缺陷预留第 2 次**；涉及缺失原片、摄影授权和国外视频平台可访问性的内容是一个独立条件性批次，不能保证仅靠聊天完成。

## 不继续做的事

- 不新增同功能数据库，不进行大规模视觉重构，不制造 50 个装饰性的空作品页。
- 不为“有改动”重写已完整的 Drop Flow/TIMER 等页面。
- 不把外部搜索中未经核对的奖项、个人职责、照片和参与名单写成确定事实。
- 不因为有 61 条 CV 就要在首页放 61 条；首页用真实图像和能力，让读者在 30 秒辨识方向，三分钟看到 3–5 个可验证案例。

## 每次收尾的强制报告

`Changed / Generated / Validated (source, build, HTTP, browser, external video) / Unverified / Commit-or-PR / Rollback / Next blocker`。未完成的事留在 `START-HERE.md` 任务队列，**不只写在聊天里**。
