## Engineering model and marginal cost
- Small editorial revision: edit one `cv_zh`/`cv_en` pair in `content/cv-records-2026-11.json` (1 record / 2 fields); rebuild automatically to screen CV, React CV selection, print HTML and bilingual PDFs; avoid editing individual HTML pages or Google Docs manually. Normal case: one Git review + existing CI cycle, no new database. Actual hosted build tokens/minutes depend on account and CI plan; no fabricated fixed cost.
- Factual record revision: also amend full `zh/en`, claim/evidence/credits and linked presentation where relevant. More work and source review; not a simple display-only patch.
- Selection/order revision: edit `content/cv-selection.json` once; triggers 60-ID/3-page/dual-PDF checks. An added award may force re-layout.
- PDF release files are **immutable by versioned filename**; old links stay alive. Generated PDF SHA is recorded in the manifest.
- GitHub release QA: source/build hashes and 3-page/60-target constraints. Production HTTP, browser/mobile visual QA and third-party video playback are separate tests, not implied by file commits.
