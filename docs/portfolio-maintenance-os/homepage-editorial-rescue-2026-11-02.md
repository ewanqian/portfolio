# Homepage Editorial Rescue — 2026-11-02

## Direction

The homepage should read as an artist's edited portfolio, not a designed product dashboard.

Reference principle from the ANKA / Finn Archer comparison:

- small, clear typography instead of oversized interface typography;
- project imagery carries the page;
- each project gets a short factual introduction rather than taxonomy-heavy explanation;
- navigation and UI chrome stay quiet;
- fewer sections, stronger editorial selection;
- no repeated explanation of the site's information architecture.

## Current problem

The current homepage explains the same positioning several times:

1. cinematic hero descriptor;
2. Selected Works section title + explanatory paragraph;
3. Practice Structure section + four explanatory cards;
4. Profile section + two-paragraph biography.

This creates high text density but low information yield. The visitor sees a lot of interface and positioning language before learning concrete facts about the work.

The current typography also mixes display, body, mono, badges, large section titles, full-viewport hero type, floating navigation and card systems. Individually these are competent; together they make the page feel like a portfolio template / product website rather than Ewan Qian's own edited archive.

## Editorial decision

Homepage vNext should contain only:

1. compact identity / introduction;
2. four selected works, image-led;
3. one compact profile/contact footer.

Move practice taxonomy, workshop taxonomy, research systems and archive explanation off the homepage. They remain accessible through navigation and dedicated pages.

## Typography target

Desktop baseline:

- navigation / metadata: 10–11px
- project metadata: 10–11px
- project title: 16–18px
- project summary: 12–13px
- homepage introduction: 13–15px
- identity name: 30–44px, not 80–112px
- section labels: 10–11px; avoid 34–46px section headings

Small type is acceptable only with:

- high contrast;
- generous line-height;
- short line lengths;
- restrained uppercase / tracking;
- no low-opacity gray for essential information.

## Project-card content rule

Every selected project should answer, in roughly 35–70 words total:

- what it is;
- where / when it existed publicly;
- Ewan's role;
- one specific formal or technical characteristic.

Avoid phrases that could describe many artists, such as “explores the relationship between…”, “a practice around…”, or generic taxonomy labels when a concrete fact is available.

## Selected Works structure

Prefer one editorial list or a restrained two-column image grid.

Each project:

- image
- project title
- year / context
- role
- 1–2 sentence description

No badge cloud. No large numbered card UI. No “open this line” buttons.

## Remove from homepage

- full-screen rotating hero as default first impression;
- Practice Lines card grid;
- taxonomy explanation paragraphs;
- repeated “research stays in archive” messaging;
- large section titles that restate the navigation;
- UI decoration that does not explain a work.

## Keep elsewhere

- Practice Lines → Profile / dedicated practice page
- workshops → Workshops
- research systems → Research / Production
- rolling CV → Profile / CV
- archive rules → repository / archive UI, not homepage copy

## Quality gate

The homepage passes only if a new visitor can answer within ~20 seconds:

1. Who is Ewan Qian?
2. What are the four strongest works?
3. What did he actually do in each?
4. What makes the practice visually / technically distinct?

without needing to understand the site's internal taxonomy.
