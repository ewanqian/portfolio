# SceneForge RTC Changelog

## 0.4.0 — 2026-09-02

- 修复屏幕捕获后未稳定映射到 Three.js 屏幕材质的问题：等待视频就绪、保持 `VideoTexture` 更新，并在进入 WebXR 时恢复播放。
- 屏幕共享优先保持细节与分辨率，并对 WebRTC 视频 sender 设置 `maintain-resolution` 与较高码率上限。
- 增加稳定设备身份与“最近设备”：首次通过临时房间配对，之后只要接收设备保持本页打开，就可以直接点击设备共享，不再复制粘贴房间链接。
- 带 `?room=` 的分享链接在接收端打开后自动加入房间。
- 临时房间只承担首次配对与兜底连接；媒体仍由 WebRTC 点对点传输。
- XR 出生点改为进入 session 后读取真实头显位置，再校准到当前观看预设；默认观众位。
- 保留 Vision Pro 的注视地面 + 捏合移动，并增加“屏幕移到前方 / 回到观众位”。
- UI 重组为中文的本机、画面来源、最近设备、首次配对、场地与观看位置、XR 操作六个区域。
- 运行时拆分为 `core / rtc / xr / viewer` 版本化模块，保留 0.3.1 作为回退版本。

### 当前边界

浏览器没有标准 API 可以无服务端扫描整个局域网的网页设备，因此 0.4.0 使用“首次配对 + 最近设备直连”。若下一版需要真正的在线设备目录，应增加自托管 presence/signaling 服务或迁移到 Needle Engine 的房间状态层。跨复杂 NAT 的远程使用仍可能需要 TURN。
