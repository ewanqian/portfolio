环境试玩制作发布教程

先玩。
再拆。
最后做成自己的。

今天不从软件功能开始。我们从一个按键、一次鼠标输入、一段声音开始，把它变成一个能被操作、能被别人试玩、也能发布成网页的音画系统。

直接开始试玩 →先检查工具 →

你不需要提前会编程。需要的是一台电脑、耳机、一个你能正常使用的 AI 工具，以及愿意反复运行、比较和修改。

00 / Before we start

课前只检查这几件事

01 Chrome / Edge 等现代浏览器可以正常打开网页和播放声音
02 带电脑 + 有线耳机；现场不要外放
03 至少一个可正常使用的 AI：ChatGPT / 豆包 / Kimi / Codex / Claude Code 等，有一个即可
04 建议注册 GitHub；想把作品发布成链接的人最好提前登录
05 可选：准备 1–2 段短声音 + 3–6 张图片；没准备也可以用默认材料
06 今天不要求 MIDI、TouchDesigner、Resolume、复杂 API 环境
安全：如果某个工具要求 GitHub Token，只创建最小权限的 Fine-grained PAT。不要把 Token 发到微信群、Prompt、网页源码或公开仓库。能用 GitHub 官方登录 / Connector / gh auth login 时优先用这些方式。
01 / Choose one route

三种办法，任选一种就够

ROUTE A

聊天 AI + GitHub 连接

如果你正在使用的聊天 AI 提供 GitHub Connector / Integration，可以连接自己的仓库，让它帮助你创建文件、改代码、保存版本。

注册 GitHub
ROUTE B

本地 Agent / CLI

Codex、Claude Code 或你已经在用的代码 Agent 都可以。先让本地 Git 正常，再让 Agent 在项目目录里工作。

GitHub CLI
ROUTE C

最简单的手动发布

让 AI 生成一个单文件 index.html → 在 GitHub 新建仓库 → 上传文件 → 开启 Pages。不会 Connector 也不影响今天完成。

GitHub Pages

本工作坊不要求 Codex。工具只是施工层：真正重要的是你怎么定义输入、声音、视觉、状态，以及试玩之后决定改什么。

03 / What are you actually looking at?

不要问“这个效果怎么做”。先问：
我做了什么动作？系统怎么理解？我为什么还想再按一次？

INPUT / GESTURE ↓ MAPPING / RULE ↓ STATE CHANGE ↓ SOUND + VISUAL ↓ FEEDBACK ↓ NEXT DECISION

今天最重要的不是功能数量。好的系统需要让你知道自己做了什么，同时又留下一点需要继续探索的空间。

04 / Today's build

从试玩到自己的版本

选一个起点

从 Starter / Demo 中挑一个你愿意继续玩的结构，不从空白工程开始。

只改一个输入关系

先决定键盘、鼠标或按钮中的一个输入。不要先增加十个功能。

让 Sound + Visual 同时回应

不是“声音播完再驱动画面”，而是让同一个动作 / 状态成为共同来源。

换成自己的材料

声音、图片、文字、朋友语音、自己拍的素材都可以。个人材料往往比默认效果更快产生身份。

交给别人玩

作者先闭嘴 30–60 秒。看别人第一眼会按什么、哪里看不懂、什么时候开始无聊。

只修一个最大问题

不要继续加东西。删、改、限制、延迟、增加状态，都可能比再加一个效果更有效。

05 / How to talk to your Agent

先把问题讲清楚，再让 AI 写

BAD

“帮我做一个炫酷的音画网页”

范围太大，Agent 很容易不断加效果、加 UI、加依赖，最后变复杂也不好玩。

BETTER

“保留现有结构，只修改这一条关系”

告诉它：当前输入是什么、希望产生什么变化、哪些代码不要动、怎么验收。每次只推进一个小目标。

COPY THIS
先读取现有项目，不要重写框架。 当前输入：Space 当前行为：每次按下触发同一个声音和同一个视觉。 我只想修改这一件事： - Tap：保持原行为 - Hold：逐渐增加密度 - Release：进入 1.5 秒衰减 要求： 1. 不增加新的按钮； 2. 不改变现有视觉风格； 3. 不引入新的依赖； 4. 修改后告诉我改了哪些文件； 5. 我会运行测试，再决定下一步。

Generate fast. Judge slowly. AI 负责扩大候选，人负责运行、比较、删除和最终判断。

06 / Save it seriously

把作品变成一个可以分享的链接

创建 GitHub Repository

一个作品一个清楚的仓库，或在自己的长期仓库中建立独立目录。

至少保存 index.html

最好同时有 README：作品叫什么、怎么玩、当前版本、下一步准备改什么。

让 Agent 写入 / 自己上传

能连接 GitHub 就直接提交；不能连接，就手动上传生成好的文件。不要让工具权限挡住创作。

开启 GitHub Pages

Settings → Pages → 选择发布分支。等待部署完成后得到公开 URL。

发给旁边的人

真正测试的是别人打开 URL 后能不能立刻开始，而不是你的电脑上是否能运行。

继续保存版本

V1 / Test / V2。GitHub 的意义不是“程序员仪式”，而是让你以后还能找到、继续改、重新引用。

08 / End condition

今天结束时，不要求你“学会 AI”。
只要求你留下一个：
别人可以打开、可以玩、而且明显属于你的东西。

V1 → Playtest → V2 / Next Version。功能多少不重要；能运行、能被理解、愿意再玩一次更重要。
