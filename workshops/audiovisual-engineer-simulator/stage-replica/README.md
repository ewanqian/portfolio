# 舞台复刻 / Stage Replica

**系列：** 视听工程师模拟器 / Audiovisual Engineer Simulator  
**当前状态：** 2026-10-14 主推工作坊 / Demo Sprint  
**当前顺序：** 先《舞台复刻》，后《现场副驾》

## 当前定位

### 拆一场喜欢的演出，再做成自己的现场

你可能看过一场特别喜欢的演出，也可能已经做过一些自己的视觉。

《舞台复刻》从一张参考图、一段现场视频、一个游戏 / 电影里的虚拟空间，或者已经做好的内容开始。先看这个现场为什么成立：主屏在做什么，其他屏幕怎么配合，人物在哪里，灯光和空间什么时候发生变化。然后把最重要的关系重新搭出来，再换成自己的视频、AI 素材、人物、舞者或 3D 模型。

同一个舞台不会一直停留在一个状态里。课堂先用四个最小状态组织它：

**铺垫 → 建立 → 爆发 → 收束**

最后把它放进网页里真正跑起来：切换观看位置、替换内容、继续修改，也可以把上一期音画同源 / WebGL 面板作为实时画面源接进屏幕。

完成以后留下来的不只是一个模型，而是一个可以继续预演、修改和分享的数字现场。

## 为什么当前先推这一场

近期反馈比较一致：

- 《舞台复刻》第一眼更容易产生“这跟我有关”的感觉；
- 报名以前就能想象最后会做成什么样，也能想象过程；
- 不需要先理解复杂的现场控制、BPM、MIDI 和脚踏；
- 《现场副驾》更适合放在后面，作为已经拥有舞台 / 现场概念之后的进阶。

当前顺序因此调整为：

> **先有一个现场，再去控制这个现场。**

## 工作坊主线

```text
找一个参考
    ↓
找到最重要的屏幕 / 人物 / 空间关系
    ↓
搭低保真舞台
    ↓
换成自己的内容
    ↓
做四种状态
    ↓
网页预演
    ↓
再修改一遍
```

重点不是 1:1 复刻全部细节，而是知道以后再看到一个喜欢的现场时，怎么拆、怎么搭、怎么重新编排。

## 3 小时建议结构

- **00:00–00:25｜选择参考**：参考图、现场视频、游戏 / 电影空间，或自己的视觉。
- **00:25–00:55｜拆现场**：视觉中心、主屏、其他屏幕、人物、灯光和空间关系。
- **00:55–01:25｜搭第一版**：只保留真正重要的结构。
- **01:25–01:55｜换自己的内容**：视频、AI 素材、人物 / 舞者、3D 模型。
- **01:55–02:25｜做四种状态**：铺垫、建立、爆发、收束。
- **02:25–02:45｜网页预演**：放进屏幕、切换观看位置、看问题。
- **02:45–03:00｜第二遍修改 / 扩展**：Blender、MCP、Visual Audio、后续继续做什么。

## Web / Realtime 主线

Stage Replica 网页端统一支持四类 screen source：

- `file`：mp4 / webm / image
- `canvas`：Three.js / Shader / Visual Audio
- `capture`：通过 `getDisplayMedia()` 捕获浏览器标签页 / 窗口
- `webrtc`：从另一台设备接收实时视频轨

上一期的音画同源演出面板可以直接作为这一期的 screen source，形成前后联动。

WebRTC 第一版只解决一个问题：**把另一块网页 / 另一台电脑正在运行的视觉，真正送进 Stage Replica 的屏幕。**

统一状态：

`idle → armed → connecting → live → fallback → offline`
