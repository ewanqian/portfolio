# 科目二｜舞台预演
## Stage Previsualization

**系列：** 视听工程师模拟器 / Audiovisual Engineer Simulator  
**正式副题：** 科目二｜视觉工程、空间组织与现场预演  
**Module 02｜Visual Engineering, Spatial Organization & Live Previs**  
**长标题：** 画面做好以后，放到真正的舞台上还成立吗？

> 把视觉、屏幕、空间和音乐组织成一套可以被检查、修改和反复预演的现场工程。

## 工作坊简介

很多视觉内容最终并不是在普通电脑屏幕上播放。它可能进入十几米宽的 LED、曲面屏、天屏、环绕屏或多个异形屏幕。真正进入现场以后，视觉需要重新面对尺寸、观看距离、屏幕关系、Mapping、时间结构和最终输出。

《舞台预演》关注的不是单纯做一个三维模型，而是怎样把已有视觉内容组织成一套真正能够进入空间、进入时间、进入现场的视觉工程。

课程核心压缩成五步：

```text
读场
↓
组织
↓
编排
↓
预演
↓
输出
```

## 01｜读场

先确认：

- 有几块主要屏幕；
- 物理尺寸与像素尺寸；
- 比例与空间位置；
- 屏幕之间是否连续；
- 哪些内容需要单独输出；
- 最终怎样 Mapping；
- 观众主要从哪里观看。

先把场地读懂，再决定内容怎么做。

## 02｜组织视觉工程

屏幕信息只是基础。更重要的是决定空间里的视觉怎么工作。

例如“主屏 + 天屏”：

- 主屏可以承担主体叙事；
- 天屏可以承担空间延伸；
- 大多数时间可以互相独立；
- 高潮时再第一次形成完整连接。

参与者需要判断：

- 主屏、副屏分别承担什么；
- 是否需要 Master Canvas；
- 哪些内容连续，哪些内容独立；
- 哪些适合预渲染；
- 哪些适合实时控制；
- 素材与输出怎样分层，现场修改才不会崩。

目标是把“很多视频文件”组织成“一套视觉工程”。

## 03｜音乐和视觉谁带头

课程讨论三种基本结构：

### 音乐主导
音乐结构 → 视觉状态 → 空间变化。

### 视觉主导
视觉本身承担连续叙事，音乐支持视觉的起承转合。

### 共同结构
先定义进入、扩张、停顿、最大能量和退出，再让声音与视觉分别完成这些状态。

课堂统一使用四个状态建立最小时间结构：

**铺垫 / INTRO → 建立 / BUILD → 爆发 / OVERLOAD → 收束 / EXIT**

## 04｜Blender 与 Agent

Blender 是增强工具，不是课程唯一入口。

会 Blender 的参与者可以继续练习：

- 场景、模型、相机与灯光；
- 音乐时间线与 Mark 点；
- Keyframe 与 Graph Editor；
- 宽屏 / 特殊比例画面；
- 渲染输出检查。

真实项目里的场地资料也可能来自尺寸表、聊天记录、截图、模型或现场测量。Agent 可以先把零散信息整理成统一的 Screen / Stage Description，例如：

- Screen ID
- Physical Size
- Resolution
- Aspect Ratio
- Content Source
- Mapping

整理后的内容既可以输出成人能阅读的规格说明，也可以保留结构化数据，供预演程序、Blender 或其他工具继续调用。

## 05｜网页预演

预演是验证方法，不是课程终点。

把真正要播放的视频放进数字舞台，从不同观看位置检查：

- 主屏是否太满；
- 天屏是否抢戏；
- 跨屏内容是否断裂；
- 曲面以后画面是否失真；
- 远距离是否仍然可读。

然后回到工程继续修改。

真正的循环是：

**组织 → 预演 → 修改 → 再预演**

## 演出案例｜ENTROPY Show

课程会使用 ENTROPY Show 的真实演出准备作为案例。

该现场包含曲面主屏与天屏。曲面主屏原生画幅为 **9600 × 3456（25:9）**，内容需要同时面对超宽比例、上下屏幕关系和不同观看位置。

准备阶段先把场地简化成可预演的数字空间：整理主屏与天屏的尺寸、比例和 Mapping，再通过网页预演程序读取电脑窗口，把实时画面映射到对应屏幕中。这样在正式进场以前，就可以快速检查同一段视觉在不同屏幕和不同观看位置上的效果。

这个案例用于说明一种可以迁移的方法：

**先把主要屏幕和观看关系组织清楚，再开始验证视觉。**

## 三小时结构

### 00:00–00:25｜读场
从真实案例进入：屏幕、尺寸、比例、Mapping、观看位置。

### 00:25–00:55｜视觉工程组织
主屏 / 副屏角色、Master Canvas、连续 / 独立内容、预渲染 / 实时内容。

### 00:55–01:20｜音乐还是视觉带头
音乐主导、视觉主导、共同结构；建立四个基础状态。

### 01:20–01:55｜Blender 示范
模型、镜头、灯光、时间线、Mark、关键帧、曲线与输出。

### 01:55–02:25｜Agent + 场景描述
整理 Screen A / B、尺寸、分辨率与 Mapping，并形成规格说明。

### 02:25–02:45｜网页舞台预演
实时窗口 → Mapping → 数字舞台 → 不同观看位置。

### 02:45–03:00｜读场 / 舞台题测试
快速完成场景判断、视觉组织和预演。

### 3 小时后｜继续测试
继续预演、展示和修改个人视觉工程。

## 考核

### 理论考｜读场与组织
拿到一份陌生 Venue Brief，快速判断：

- 有几块主要屏幕；
- 各自承担什么；
- Mapping 怎么组织；
- 音乐还是视觉承担主要结构；
- 正式制作以前还缺哪些关键信息。

### 路考｜舞台题目
随机抽取以下一种：

- 超宽屏；
- 主屏 + 天屏；
- 曲面屏；
- 多屏 / 异形屏。

完成：

**读场 → 屏幕角色 → Mapping → 放入内容 → 四状态 → 预演 → 规格说明**

通过标准：

- **读对**：理解场地。
- **组织对**：屏幕角色与视觉逻辑成立。
- **映对**：素材、输出和屏幕关系正确。
- **演得起来**：至少有几个清楚的时间 / 能量状态。
- **交得出去**：留下清楚的场景说明和屏幕规格。

## 最终成果

参与者至少得到：

1. 一份场景描述；
2. 一份屏幕规格说明；
3. 一个可以运行的预演；
4. 一个包含“铺垫 → 建立 → 爆发 → 收束”的最小视觉工程。

这些结果可以继续发展成 Live Set、演唱会 / 开幕式视觉、策展 Demo、沉浸式空间原型或大型屏幕内容提案。

## 参与者准备

- 笔记本电脑、鼠标和耳机。
- 建议具备基础 Blender 使用经验：知道如何打开场景、使用相机和灯光，并渲染图片或视频。
- 没有 Blender 基础也可以参加或旁听，仍然可以完整理解读场、组织、Mapping 与预演主线。
- 可以准备一段音乐，以及可选的视频、模型或旧 Blender 工程。
