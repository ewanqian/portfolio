## 系列说明

《视听工程师模拟器》从《极简输入》继续往真实现场推进。科目一解决“我能演了”，科目二解决“我能搭了”。

《现场副驾》打开 Ewan 自己演出时使用的 Resolume Arena 工程，学习怎样组织爆闪、节拍与控制层，准备时间参考，再进入 DJ 现场模拟。

《舞台复刻》从参考图、现场视频、虚拟世界或自己的视觉作品开始，学习观察、解构、组织和重构，让同一个舞台拥有不同状态，最后通过网页预演和分享。

AI / MCP 辅助整理控制与空间；参与者练习现场判断和创作编排。

## 社交媒体短版

### 现场副驾

**如果音乐已经开始，只给你几个按钮和几层视觉，你能不能把现场的节奏真正控制起来？**

这场工作坊会直接打开我自己演出时使用的 Resolume Arena 工程，拆解我平时怎样组织几套不同频率、不同密度的爆闪和节拍状态，再把它们整理成一套现场真正能用的控制系统。

演出开始以前，我们也会讨论怎么和 DJ 确认 BPM 与 Beat Link 信息、怎么看音乐波形和结构、什么时候需要用 Ableton Link 同步 BPM，以及怎样把这些时间信息真正接进自己的工程。

只有键盘也可以，有 MIDI、脚踏和推子也可以继续扩展。AI / MCP 会帮助大家更快整理这些控制关系，但真正开始演出以后，什么时候保持、什么时候增加能量、什么时候改变爆闪方式、节奏跑掉以后怎么重新跟上，还是由你自己判断。

**最后，我们会把这套系统真正带进一次 DJ 现场模拟。**

### 舞台复刻

**你有没有看过一场特别喜欢的演出、一个游戏世界或者电影场景，想过：如果这个现场交给我，我会把它变成什么样？**

这场工作坊会从一张参考图、一段现场视频、一个虚拟世界，或者你自己已经做好的视觉开始。

我们会先把一个好的现场“拆开”：哪里是视觉中心，屏幕之间是什么关系，观众看到的空间是怎样被组织出来的。

然后重新搭一个自己的版本。

你可以换掉屏幕里的内容，加入自己的视频、3D 模型、人物或其他素材，也可以重新安排灯光、视觉和声音，让同一个舞台从安静的铺垫逐渐进入更强烈的状态。

最后通过网页直接预演和分享。

**你得到的不只是一个舞台模型，而是一套以后真正想搭一个现场时，可以重新使用的方法。**

## 现场副驾 最终长版

现场视觉真正开始演以后，我越来越少把注意力放在“下一条素材是什么”，而更多在想：

**现在这一段需要多少能量？**

同一套画面，并不一定需要不断切换素材。

只改变它围绕 BPM 运动和闪烁的方式，就已经可以产生完全不同的现场状态。

比如我自己的 Arena 工程里，会预先组织几种不同的爆闪和节拍结构：

慢一些的循环适合铺垫；

稳定的节拍让画面开始和音乐建立关系；

越来越密的闪烁可以逐渐增加压力；

短促、突然的爆闪则只在真正需要强调的时候出现。

这些状态再和视觉素材、黑屏、亮度和其他控制层组合起来，就会形成一套真正可以“演奏”的现场工程。

### 演出以前，先把时间准备好

真正进现场以前，我会先和 DJ 确认可以拿到哪些信息。

BPM 是多少？

现场有没有 Beat Link 信息？

能不能看到曲目的波形和音乐结构？

自己的软件有没有必要使用 Ableton Link 同步 BPM？

如果使用，自己的工程应该在哪里开启、怎样确认它真的跟上了？

这些并不是为了把现场完全自动化。

它们只是让你在演出开始以前，尽可能获得一个可靠的时间参考。

如果同步条件不存在，仍然需要会 Tap BPM；节奏偏掉以后，也需要知道怎样重新对齐。

### 把复杂工程压缩成少数控制

课堂会直接打开我自己的 Arena 工程，而不是重新做一套只用于教学的 Demo。

我们会一起拆：

**哪些层一直存在；  
哪些层负责节拍；  
哪些层是真正的视觉内容；  
哪些爆闪只在高能量时使用；  
不同闪烁频率怎么提前准备。**

然后再把这些东西变成参与者真正可以操作的控制。

只有电脑键盘，也可以完成。

有 MIDI Controller，可以把几个主要状态铺到不同按钮。

有推子，可以控制亮度、层次和强度。

有脚踏，也可以把最常用的动作放到脚下。

### AI / MCP 是怎么加入的

这里的 AI 不负责替你演出。

它更适合解决一个很实际的问题：

> **我已经知道自己想要哪些状态了，怎样更快把它们整理成适合自己的控制系统？**

你可以告诉 Agent：

我现在有哪些按键。

有哪些 MIDI 输入。

想准备几种爆闪。

需要 Tap、Resync、亮度和几个主要状态。

AI / MCP 可以辅助整理控制关系、参数层次和 Mapping，让这套常用结构更快迁移到不同人的工程里。

### 最后真正上场

最后我们会模拟有 DJ 演出的现场。

参与者会面对几种不同的音乐桥段，而不是播放一段完全提前编好的动画。

你需要用课堂里准备好的几种状态，去判断：

现在应该继续保持吗？

爆闪应该慢一点还是更密？

这一段是不是已经太满？

什么时候应该把能量收回来？

BPM 偏掉以后怎么重新跟上？

最终练习的不是“按钮有没有按对”。

而是：

> **能不能有意识地控制一段现场演出的节奏。**

## 舞台复刻 最终长版

很多时候，我们已经看过一个喜欢的现场，或者已经做出了一些自己的视觉。

真正困难的是下一步：

> **怎么把一条视频、一组画面或者一个模糊的现场构想，变成一个完整的空间？**

《舞台复刻》会从“复刻”开始。

可以是一张演唱会现场图。

一段 Live 视频。

一个游戏里的基地。

电影里的空间。

甚至是自己以前做过的一条影像。

我们先不急着做得一模一样，而是去看：

**这个现场为什么成立？**

### 第一步：拆一个场景

一个复杂的现场，真正重要的信息其实没有那么多。

我们会先找：

观众的注意力主要在哪里？

哪里是视觉中心？

最大的屏幕承担什么？

其他屏幕是在延伸同一个世界，还是在提供另一层信息？

舞台、人物和画面是什么关系？

哪些部分是真正决定这个现场感觉的，哪些细节其实可以暂时忽略？

这一步更像是在**解构一个已经成立的演出**。

### 第二步：重新组织

拆开以后，再开始把它变成自己的版本。

比如同样是：

一块主屏；

上方的一块屏幕；

舞台中央的人物；

几个辅助视觉面。

你完全可以重新决定它们的关系。

主屏可以一直承担核心画面。

也可以大多数时间很安静，到某一个状态才真正打开。

几块屏幕可以分别工作，也可以在高潮时第一次连接成一个整体。

还可以加入：

自己的视频；

AI 生成的素材；

人物或舞者；

3D 模型；

灯光；

文字和界面。

重点不是“每个地方都塞满”，而是让整个现场开始有**视觉中心和层次**。

### 第三步：让同一个舞台拥有不同状态

舞台搭出来以后，它不应该永远停在一张图里。

我们会尝试让同一个场景拥有大约四种不同状态：

**铺垫  
建立  
推进 / 变化  
爆发 / 收束**

具体怎么表现，可以完全不同。

可能是视觉内容发生变化。

可能是灯光改变。

可能是人物出现。

可能是模型开始运动。

也可能只是整个空间的速度、亮度和密度发生变化。

重要的是开始理解：

> **空间也可以像舞台剧一样被编排。**

它有视觉中心，也有时间上的起承转合。

### 第四步：把自己的内容真的放进去

我们会用网页预演工具快速搭建这些主要关系，再把自己的内容直接放到对应屏幕里。

不需要先完成一个特别重的三维工程。

先让它跑起来。

再从不同观看位置看看：

主屏和其他屏幕是不是在说同一件事？

画面之间有没有抢夺注意力？

某一个状态是不是应该更安静？

真正需要爆发的时刻有没有留下足够的空间？

然后继续修改。

### AI / MCP 怎么参与

AI 在第二场也不是主题本身。

它主要用来加速“重构”。

比如从参考图、现场视频或已有资料里，先帮助整理：

有哪些主要屏幕；

大概是什么比例；

哪些空间关系值得保留；

怎样生成一个最基础的场景描述。

如果会 Blender，还可以通过 Blender MCP 继续修改模型、镜头、灯光和动画。

不会 Blender，也可以沿着网页路径完成主要体验。

### 最后可以分享出去

最后形成的数字现场不只是课堂截图。

它可以继续通过网页运行和分享，让别人直接看到：

这个场景是什么样；

你把什么内容放了进去；

它在不同状态下怎样变化。

这也是“舞台复刻”有趣的地方：

> **先复制一个已经存在的世界，再慢慢把它改成自己的。**

## 考核方式

### 现场副驾

#### 理论考 听状态

直接听音乐，在保持、推进、爆发、留白和恢复之间做判断，说明什么时候切换、为什么切换。

#### 路考 DJ 现场模拟

与 DJ 老师共同完成一段包含不同音乐桥段的现场。检查 Tap / Resync、至少 3–4 种节拍或闪烁状态、强度升降、留白，以及出错后的恢复。

演出前确认可用的 BPM、Beat Link 与波形信息；需要时开启 Ableton Link 并检查同步，没有同步条件时使用 Tap BPM。

### 舞台复刻

#### 理论考 读场

从参考场景里找出视觉中心、主要屏幕与空间关系，说明屏幕、人物和内容各自承担什么，以及哪些部分值得保留或重新组织。

#### 路考 舞台复刻

完成“参考场景 → 屏幕结构 → 内容组织与 Mapping → 四种状态 → 网页预演与分享”。把自己的视频、人物或模型等素材放进场景，用视觉、灯光或运动组织变化。

检查视觉中心是否清楚、屏幕和内容是否相互配合、状态之间是否有节奏差异，以及网页是否能展示这些变化。四种状态按“铺垫、建立、推进 / 变化、爆发 / 收束”组织。

## Visual Audio Bonus

### 如果已经有了画面，能不能反过来写音乐？

当一个现场已经被编排以后，它其实已经有自己的时间结构：

这里安静。

这里开始运动。

这里灯光打开。

这里人物出现。

这里进入最大状态。

这些视觉变化本身就可以成为音乐结构的输入。

最基础的版本，可以用 Web Audio 根据几个状态快速生成声音变化。

如果本来使用 Ableton Live，也可以直接利用现有的音乐库、MIDI 和 Arrangement，把视觉里的几个阶段重新翻译成音乐：

**铺垫 → 建立 → 推进 → 爆发 → 收束**

重点不是“AI 自动配一首 BGM”。

而是：

> **已经有了一套视觉编排以后，能不能让音乐也从同一个结构里长出来？**

这就是 Visual Audio 在这门课里的位置。
