## 这是什么

《游戏化 AI 新媒体艺术工程师 101》是一场面向初学者的新媒体创作先导工作坊。

它把两项长期项目——**《游戏化 AI 新媒体艺术工程师》**与**《音画同源乐器》**——最基础、最需要先掌握的部分压缩进一次完整体验。

课程不要求参与者具备编程、音乐或现场演出经验，也不会把四个小时变成软件功能教学。第一期只建立一条短而完整的路径：

**想法 → AI 协作 → 项目骨架 → 视觉原型 → 声音 / 图像 Mapping → 测试 → Showcase**

这里的“101”表示基础入口。目标不是把参与者训练成程序员，而是让第一次接触这套方法的人，能够带着一个真实可运行的原型离开，并理解它接下来怎样继续发展。

---

## 为什么从“工程化”开始

AI 已经可以很快生成网页、代码和视觉效果，但真正影响一个作品能不能完成的，往往不是生成速度，而是开发顺序。

工作坊会介绍一个非常简单的三阶段方法：

**FRAME → FILL → FINISH**

- **FRAME / 框架：** 先确定作品怎样工作、有哪些状态、操作者能做什么
- **FILL / 填充：** 再加入声音、图片、文字、动画与个人材料
- **FINISH / 打磨：** 最后测试、删除多余部分、修复问题并准备展示

AI 最适合进入这个循环中协助执行、修改和排错；作品的目标、结构与判断仍然由人决定。

因此课程不会把 Prompt 当成最终技能，而是先建立最基础的 Human-in-the-loop 回路：

**人决定 → AI 执行 → 人运行 → 人判断 → 再修改下一版。**

# 4 小时课程

## 13:30–13:50｜00 / START HERE
### 看见一条完整的制作路径

先用一个完成度不高、但从输入到展示完整可运行的 Demo 开场。

参与者会先看到：

- 一个想法如何被 AI 拆成项目
- 一个按键如何改变视觉状态
- 一次操作如何同时触发声音与画面
- 一个作品怎样从 V1 经过测试进入 V2
- 最后怎样全屏并在大屏幕上展示

这一段只建立课程地图，不讲复杂原理。

---

## 13:50–14:35｜01 / BUILD THE FRAME
### 先做出一件能运行的东西

参与者打开已经准备好的 Starter Kit，通过 AI 辅助完成最基础的修改：

- 改一段文字、参数或视觉状态
- 增加一个按键行为
- 保存第一版 V1
- 理解项目文件夹、README 与版本的意义

这一阶段只讲少量必要概念：

- AI Coding / Agent 是什么
- FRAME → FILL → FINISH
- Human-in-the-loop
- V1 / V2 与最基础的版本意识

**目标：每个人已经有一个能运行、能响应操作的作品骨架。**

---

## 14:35–15:10｜02 / BUILD A VISUAL SYSTEM
### 把个人材料变成可以操作的画面

第二阶段进入视觉练习。

参与者可以从以下材料开始：

- 自己拍摄的图片、纹理与短视频
- AI 生成图像
- 字体、Logo 与简单图形
- Creative Coding / Generative Art

现场会用 Processing / Creative Coding 的小案例解释：视觉不一定是一条做完就结束的视频，也可以由按键、参数和状态实时改变。

参与者不需要同时学习多套软件，而是在同一个 Starter Kit 中建立 3–6 个最基础的视觉操作位。

**目标：画面已经从“素材”变成一个可以被控制的视觉系统。**

---

## 15:10–15:40｜REMOTE GUEST SESSION
### 远程连线：从 AI 工具到系统思维

本期计划邀请一位相关实践者进行约 **30 分钟远程连线**。

这部分不承担软件教学，而是从另一位实践者的角度，把前半段刚刚发生的操作放回更大的创作与工程语境中，例如：

- AI Coding / Agentic workflow 为什么正在改变个人创作方式
- 一个“能生成的 Demo”为什么还不等于一个可持续使用的系统
- 人在 AI 协作中仍然需要保留哪些判断
- 怎样理解工具、接口、版本与自动化之间的关系
- 个人如何从一次性的 AI 使用，逐渐发展出自己的工作方法

建议结构：

- **20 分钟分享**
- **10 分钟 Q&A / 对谈**

远程嘉宾的作用是补充视角，而不是占据主要制作时间。第一期以 30 分钟为标准；如果未来进入多日组合课程，再扩展到 45–60 分钟或共同授课。

---

## 15:40–16:20｜03 / CONNECT SOUND + VISUAL
### 让声音和画面开始发生关系

这一阶段进入 Audio Visual 与 Mapping。

参与者会理解三种最基础的关系：

- **Trigger**：按一下，声音和画面同时发生
- **Continuous**：鼠标移动或持续操作，同时改变声音与视觉参数
- **State**：让作品在 Quiet、Active、Peak、Reset 等状态之间切换

声音可以来自：

- 手机现场录音
- 提前准备的 MP3 / WAV
- 身边环境中的声音
- Starter Kit 中的基础声音模块

课程会引用 TouchWaves、数字乐器与实时音画实践作为参考，但不要求参与者学习完整音乐制作系统。

**目标：至少完成一组真正同时工作的 Sound + Visual Mapping。**

---

## 16:20–16:50｜04 / MAKE IT PLAYABLE
### 把 Demo 变成一个可以玩的系统

这一阶段停止继续堆功能，开始整理已有内容。

参与者会完成：

- 给作品起一个名字
- 设计 3–6 个清楚的操作动作
- 至少建立 Quiet / Active 两个状态
- 与另一位参与者交换试玩
- 找到一个最明显的问题并修改
- 保存 V2 或明确下一版修改项

这里第一次把“作者觉得能用”和“别人真的能用”区分开。

---

## 16:50–17:30｜05 / SHOWCASE
### 在大屏幕上完成第一次公开测试

最后 40 分钟直接进入结课 Showcase。

参与者可以用 30–90 秒展示自己的原型：

- 简单演奏一段视觉 / 音画状态
- 展示一个最有意思的 Mapping
- 让另一位参与者或观众直接试玩
- 用一句话介绍作品为什么这样设计

如果作品适合演奏，可以使用最简单的结构：

**进入 → 发展 → Peak → 收回 → 结束**

Showcase 不是作品比赛，也不要求四小时内完成成熟作品。它的作用是让每个原型真正经历一次公开使用，从而发现下一版本应该修改什么。

---

## 第一场不会教什么

为了保证四小时内真的完成一件可以展示的东西，第一期不会同时要求所有人学习完整的：

- Processing 独立工程
- Resolume / Arena
- NDI / Syphon / Spout
- MIDI Controller
- Strudel
- 完整 Tone.js 音频系统
- 复杂 Git 命令
- 高级 Agent / API 自动化

这些内容会保留在后续技能树中。

第一期参与者只面对一条已经预先测试好的默认路径：

**Browser Starter Kit + AI Coding + Creative Coding / Audio + Keyboard / Mouse。**

MIDI、现场软件和更复杂的音画系统可以在后续正式工作坊中继续发展。

## 最终带走

每位参与者至少带走：

- 一个可以运行的新媒体原型
- 一个保存下来的 V1
- 一个经过试玩或修改的 V2 / 下一版计划
- 至少一组 Sound + Visual Mapping
- 一套键盘 / 鼠标操作方式
- Quiet / Active 两个状态
- 一次大屏幕 Showcase
