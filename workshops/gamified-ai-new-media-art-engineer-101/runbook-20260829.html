01 / START

先不要问“我该学哪个软件”

实时视听创作很容易从工具开始：先打开一个软件，再寻找插件、参数和效果。这样当然可以工作，但它也很容易让创作者陷入一个循环——功能越来越多，作品却越来越难解释。

这场工作坊把顺序反过来。我们先确定一个动作，再决定这个动作和系统之间的关系。

一个动作 ↓ 一套规则 / Mapping ↓ 声音 + 视觉 + 系统状态 ↓ 观众看到结果 ↓ 表演者根据结果再次判断

技术不是起点。
真正的起点是：我希望这个系统怎样回应我？

所以第一步甚至可以简单到只有一个键、一次触摸或一次鼠标动作。问题不是“它能触发多少效果”，而是这个动作能不能在几秒钟里形成清楚、可理解、可继续发展的结果。

02 / MAPPING

什么是“音画同源”？

这里的“音画同源”不是一个固定的艺术史流派名称，而是我们在工作坊里使用的工作概念：声音和视觉不只是最后被摆在一起，而是尽可能从同一个动作、状态、参数或规则中共同产生。

常见的反应式可视化

声音先出现，再分析音量、频率或节拍，让画面跟着变化。声音是原因，视觉是反应。

同源控制

一个输入先进入控制系统，再分别影响声音与视觉。两者是同一套决定的不同结果。

INPUT / GESTURE ↓ MAPPING / RULE ↙ ↘ SOUND VISUAL ↘ ↙ SHARED STATE

最简单的例子是：按下一个键，同时出现一个声音和一个动画。但真正有意思的部分从第二层开始——同一个键在不同状态下，可以产生完全不同的意义。

QUIET
同一个输入只留下一个很轻的声音和一小段视觉痕迹。
BUILD
同一个输入开始增加节奏密度、重复和空间运动。
PEAK
同一个输入成为一个强烈的主事件，但系统仍然限制音量与视觉密度。
BREAK
同一个输入不再“增加”，而是抽离、延长尾音、制造空间或帮助过渡。

按钮没有变多，
系统却变得更深。

03 / CONTROL

为什么“会触发”还不等于“会演出”？

一个网页可以很容易做到“按一下，响一下，闪一下”。这叫触发，它很直接，也很适合第一次试玩。但如果每次按下去都只发生一次短暂事件，表演者就必须不停地按。观众看到的也更像是在测试一个网页，而不是观看一场演出。

要让它变成现场系统，需要多一层：状态、时间和反馈。

现在系统是什么状态 + 人刚刚做了什么 + 现场已经发生过什么 ↓ 系统进入下一个状态 ↓ 声音 / 视觉产生结果 ↓ 人听见、看见结果 ↓ 再决定下一步

这就是一个最基本的反馈回路。它和播放一段固定视频的区别在于：表演不是沿着唯一时间轴自动走完，而是不断在“判断—结果—再判断”之间循环。

我们真正关心的不是“我能控制多少参数”，而是“我能不能在正确的时间做一个有意义的决定”。

人和系统各自负责什么？

系统负责安全

BPM、节拍边界、音量限制、最大声部、最大视觉密度、自动衰减、Reset / Panic。

人负责判断

什么时候进入、什么时候继续等待、什么时候增加、什么时候减少、什么时候释放、什么时候结束。

这样做的目的不是让机器替人表演，而是把最容易出错、最需要精确计算的部分交给系统，把最有创作价值的结构判断留给人。

04 / STRUCTURE

为什么音乐、灯光和大型现场都需要“结构”？

一场演出通常不会把所有能量从第一秒开到最后一秒。音乐会有铺垫、推进、高潮、间隔和收束；灯光会隐藏、聚焦、打开、熄灭；视觉也需要建立、累积、转化和离开。

这些结构之所以有效，不是因为它们遵守某一种固定公式，而是因为它们帮助观众感受到变化的方向。如果没有前后的差异，就没有“现在更紧张”“终于释放”“突然空下来”这样的经验。

Micro / Event

一个声音、一次闪烁、一次敲击。发生在很短的时间尺度。

Meso / Phrase & Section

几个事件形成一段关系，例如 8 或 16 bars 的推进、等待与释放。

Macro / Show

整场演出的能量曲线、段落次序、高潮位置和结束方式。

Shared State

音乐、视觉、灯光可以用不同速度变化，但共同理解“现在处于什么阶段”。

这也是“音画同源”的更深一层。声音和视觉不一定每拍同步，也不一定做相同动作。它们可以共享的是一个更高层的意图，例如：

STATE = PRE-RELEASE / 还不能释放 音乐：减少完整鼓组，保留紧张感 视觉：减少新对象，让已有结构继续积累 灯光：保持狭窄，不完全打开空间

三种媒介没有复制彼此，却在解释同一个状态。

05 / SCORE

一个最小的五段演出剧本

对于第一次做实时系统的人，不需要先写复杂乐谱。可以先用五个段落组织一段 60–90 秒的小演出。每一段只回答四个问题：现在能量多高？密度多高？谁是主角？下一段怎么进入？

01 / OPEN铺垫少、慢、留白。先让观众理解空间和基本材料。
02 / BUILD推进增加重复、方向和密度，但暂时不把所有东西放出来。
03 / PEAK主段最明确的身体能量和视觉层级。高能，但仍然可控。
04 / BRIDGE桥段抽离主要脉冲，留下尾音、空间、记忆或重新组合。
05 / RETURN收束回到更少的材料，决定结束、重启，或把旧元素召回。

同一个结构，不同媒介可以有不同动作

OPEN
音乐：稀疏；视觉：大负空间；控制：少操作，让系统自己存在。
BUILD
音乐：增加 subdivision；视觉：开始累积与分裂；控制：ADD / HOLD。
PEAK
音乐：完整低频与节奏；视觉：强前景与大尺度对比；控制：选择主行为，不无限叠加。
BRIDGE
音乐：抽离主脉冲；视觉：空场、残留、延迟；控制：REMOVE / RELEASE。
RETURN
音乐与视觉都重新获得空间；控制者决定结束还是再次进入。

结构不是限制创作。
结构让“什么时候发生”本身成为创作。

06 / PRACTICE

工作坊里，我们怎样把理论变成可以玩的东西？

课堂不会先讲一长串软件功能。我们用几个非常小的版本做比较，让参与者亲手感受到“触发”和“系统”之间的差别。

13:30–14:30
理解：从效果到系统

先看一个完整 Demo，再拆解 Input、Mapping、State、Feedback 与演出结构。yiyisogreen 从 Audio Visual、Mapping、限制与表演界面补充实际经验。

14:30–15:30
搭建：做出一个最小 V1

从一个键或一次鼠标输入开始，让它同时产生声音、视觉与状态变化。先做到“能跑”，再比较不同版本为什么一个薄、一个更可演奏。

15:30–16:05
替换：把系统变成自己的

加入个人声音、图片、文字、AI 图像或 Creative Coding 材料。重点不是功能数量，而是重新设计输入与结果之间的关系。

16:05–16:20
盲测：作者先不解释

把作品交给另一个人直接操作。观察对方第一步做什么、哪里看不懂、什么时候觉得无聊。然后只修一个最大问题。

16:20–16:30
Showcase：用 30–60 秒证明它成立

展示一个最有意思的 Mapping、一次状态变化，或者一段最小的音画演出。目标不是“做完所有功能”，而是让别人真正看懂并愿意继续玩。

课堂里的四个版本

Trigger Baseline

按一下 → 一个声音 + 一个视觉。故意保留最简单版本，用来说明为什么它很快耗尽。

State Instrument

同一个输入在不同状态中得到不同结果。开始出现“当前在哪里”的概念。

Safe Loop

系统拥有 BPM 和连续背景，人不需要手动制造每一个 beat，只负责增加、减少、等待和释放。

Mini Live System

声音与视觉共同读取结构状态，形成一段可以从 OPEN 走到 PEAK 再回来的小型演出。

07 / OUTCOME

三个小时以后，你应该真正带走什么？

这不是一门要求你在三小时里掌握某个专业软件的速成课。更现实也更重要的结果，是你亲手走完一次完整的小型创作循环。

  • 一个可以在浏览器里运行的实时视听原型；
  • 一个明确的 Input；
  • 至少一组由你决定的 Sound + Visual Mapping；
  • 至少一个 State / 状态变化；
  • 一次他人试玩；
  • 一个经过修改的 V2，或一条明确的下一版计划；
  • 一段 30–60 秒可以被观看的 Showcase。

判断一个系统是否值得继续做，可以只问四句话：

现在是什么状态？
我这个动作改变了什么？
我停手以后会发生什么？
我怎么把它收回来？

最终目标不是让每个人变成程序员或音乐家。
而是让你开始拥有一套属于自己的实时创作与判断方法。
