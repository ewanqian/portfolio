# SOP-02｜30 秒 Opening：从 V1 到 V2

## 目的

用一段 30 秒 Opening 建立最小的演出时间结构，并完成一次真正的“做出来—看一遍—指出问题—只改一件事”的迭代。

这条 SOP 不要求完成一场完整演出，也不追求最终视觉风格。它训练的是最基础的编排能力：什么时候出现、什么时候推进、什么时候达到第一次峰值、什么时候拿掉东西。

## 输入

开始前至少需要：

- 一个已经通过 SOP-01 的 Gray Box；
- 一个主体：Performer、Object、Installation、文字、图形或其他对象；
- 一段 30 秒左右的音乐、声音草稿，或至少一条声音结构描述；
- 一套最简单的视觉内容；
- 一条主光或最小灯光状态。

## 输出

完成后必须留下：

1. 一张 30 秒 Storyboard；
2. 一张 Cue Sheet；
3. V1 录屏；
4. 一条明确反馈；
5. V2 录屏；
6. 一句话说明“V2 只改了什么”。

## Procedure

### Step 1｜先划分功能，不写效果

使用六段结构：

```text
00–06   OPEN
06–12   REVEAL
12–18   BUILD 01
18–24   BUILD 02
24–30   PEAK
30+     RELEASE
```

每一段先只写“这段负责什么”。

不要写：粒子、Bloom、镜头抖动、某种 shader。

先写：隐藏、出现、建立、扩大、汇合、收回。

**Gate 1**：六段必须在功能上有差异。如果只是六个不同效果，重新写。

### Step 2｜先安排声音结构

即使没有完成音乐，也写成：

```text
ambience
→ texture
→ pulse
→ rhythm
→ hit
→ release
```

如果已有音乐，标出真正的段落变化，而不是只看波形大小。

**Gate 2**：必须能指出至少一个“这里为什么要推进”和一个“这里为什么要收回”的位置。

### Step 3｜安排主体动作

Performer / Object / Installation 至少有一次明确状态变化，例如：

- 出现；
- 进入；
- 展开；
- 停止；
- 转向；
- 消失。

不要让主体一直只是“站在那里供屏幕照”。

### Step 4｜安排灯光

第一原则：Peak 之前必须有余量。

如果 6 秒时灯已经很亮，24 秒以后就只能靠更多效果弥补结构问题。

记录每段的大致强度和方向，不需要精确 DMX 数值。

### Step 5｜最后安排屏幕 / 视觉

到这一步才决定屏幕做什么。

检查两个问题：

1. 屏幕是不是每一段都在抢主角；
2. 屏幕的变化是否只是机械复制音乐变化。

允许某些段落屏幕几乎不动，甚至保持黑场。

### Step 6｜生成 Cue Sheet

最少包含：

| Time | Function | Sound | Performer/Object | Light | Screen |
|---|---|---|---|---|---|
| 00–06 | OPEN | ambience | still | 0–5% | black |
| 06–12 | REVEAL | texture | appear | 10–20% | fade in |
| 12–18 | BUILD 01 | pulse | hold | 20–30% | layer 2 |
| 18–24 | BUILD 02 | rhythm | move | 40–60% | expand |
| 24–30 | PEAK | hit | lock | 70–100% | full relation |
| 30+ | RELEASE | release | still | fall | remove layer |

表格不是最终设计，只是让不同媒介进入同一条时间线。

### Step 7｜播放 V1，但禁止立即修改

从头播放一次，完整看完。

播放过程中只做记录，不暂停，不边看边改。

结束后只回答六个问题：

1. 第一秒是不是太满；
2. 第一个明确材料出现得清楚吗；
3. 12–24 秒真的在推进吗；
4. Peak 是否明显强于前面；
5. 主体与屏幕是否有关系；
6. Release 是否真的拿掉了东西。

### Step 8｜只选一个最严重的问题

不能一次列十条修改。

选出一条会最大程度影响整体结构的问题，例如：

- Peak 不够明显；
- 所有媒介同时变化；
- 主体出现太早；
- 顶屏太早进入；
- 音乐没有清晰转折；
- Release 没有真正下降。

### Step 9｜做 V2

只修改这一条。

例如：

> Peak 不明显 → 把 18 秒前的亮度全部降低，并把顶部屏延后 2 秒进入。

不要趁机换风格、重做模型、加十个新效果。

### Step 10｜对比 V1 / V2

并排看两个版本。

回答：

- 修改是否真的解决了原问题；
- 是否产生新的副作用；
- 如果进入 V3，下一步只改什么。

## 常见失败

### 失败 1｜把音乐波形当结构

恢复：先关掉画面，只听音乐，用文字标记段落功能。

### 失败 2｜所有媒介一起变化

恢复：把至少一条轨道整体错开 1–3 秒，重新看层次。

### 失败 3｜Peak 只能靠“更亮、更闪”

恢复：先减少前面的密度和亮度，再判断 Peak。

### 失败 4｜V2 变成重做

恢复：回到 V1，撤销所有与目标问题无关的修改。

### 失败 5｜不断加东西但没有播放完整一遍

恢复：强制停止编辑，从 00:00 连续播放到 00:30，再做决定。

## 完成标准

通过这条 SOP 的人，应该能够不用解释风格，清楚说出：

> 这 30 秒为什么从这里开始，在哪里推进，第一次峰值在哪里，为什么这里收回来；V1 最大的问题是什么，V2 只改了哪一个关系。
