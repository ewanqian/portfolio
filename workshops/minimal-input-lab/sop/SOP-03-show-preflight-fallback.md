# SOP-03｜现场预检与 Fallback

## 目的

在进入真实场地、技术彩排或正式演出前，把最容易导致现场事故的问题提前暴露，并为关键链路准备可立即切换的备用方案。

这条 SOP 不是为了消灭所有风险。现场系统一定会出现不确定性。真正需要建立的是：哪些问题必须在演出前解决，哪些问题可以接受，主链路失效以后如何迅速回到一个可运行状态。

## 适用情境

- 实时视觉、网页、TouchDesigner、Processing、Blender、Arena、Ableton 等需要在现场运行；
- 使用外部媒体、字体、模型、插件或网络资源；
- 多屏、异形屏、投影、LED、Syphon / Spout / NDI、MIDI / OSC 等链路；
- 使用非本人电脑或临时现场机；
- 任何“现场打不开就没有第二次机会”的演出。

## 输出

演出前至少留下：

1. 主工程冻结版本；
2. 本机可运行备份；
3. 可脱离实时系统播放的 fallback 视频 / 静态画面；
4. 屏幕与输出规格记录；
5. 控制器与协议检查结果；
6. Panic / Blackout / Stop / Reset 路径；
7. 一份现场执行顺序与负责人。

## Procedure

### Step 1｜冻结演出版本

在正式演出前确定一个 show build。

冻结以后，任何修改都必须回答：

- 为什么必须改；
- 改动会影响哪一条链路；
- 是否有时间重新完整测试。

没有重新完整测试的改动，不进入正式 show build。

### Step 2｜做一次冷启动

完全关闭软件和工程，从桌面开始重新打开。

不要用已经运行了一下午的“热状态”证明工程没问题。

记录：

- 启动顺序；
- 所需权限；
- 需要手动连接的设备；
- 第一个稳定画面出现需要多久。

### Step 3｜检查外部依赖

逐项确认：

- 视频、音频、图片、3D 模型路径；
- 字体；
- 插件与软件版本；
- 浏览器权限；
- 网络请求和在线 API；
- 本地服务器；
- Syphon / Spout / NDI source；
- MIDI / OSC 端口；
- 音频设备和采样率。

任何演出关键内容如果依赖公网，必须准备离线方案。

### Step 4｜确认输出规格

对照场地方最终信息核对：

- 分辨率；
- 帧率；
- 屏幕排列；
- 旋转与折角；
- 色彩 / HDR 要求；
- 输入接口；
- 主备输出。

不要只相信项目早期 PDF。以最终现场链路为准。

### Step 5｜逐个测试控制

所有现场会使用的按钮、推子、脚踏和快捷键逐个操作。

特别检查：

- 是否存在重复映射；
- 控制器断开重连以后是否恢复；
- Resync 是否有效；
- 是否有误触会导致不可逆状态。

### Step 6｜测试 Panic / Blackout / Reset

必须能够在数秒内完成：

- 画面黑场；
- 停止异常声音；
- 回到已知 Scene；
- 重置时间 / BPM / Transport；
- 重新连接 source。

如果 Panic 本身需要五个步骤，它就不是 Panic。

### Step 7｜准备三级 fallback

**Fallback A：同系统备用路径**  
例如备用 scene、备用 source、备用浏览器标签页。

**Fallback B：预渲染视频**  
主实时系统失效时，至少有一条与现场规格匹配的视频可以继续演出。

**Fallback C：最低可接受状态**  
黑场、Logo、静态画面、基础灯光或其他不会破坏现场的安全状态。

### Step 8｜拔线测试

有意识制造至少三种失败：

- 拔掉控制器；
- 断网；
- 关闭一个 source / 软件。

观察系统如何失败，并实际执行恢复步骤。

### Step 9｜完整 Run Through

从开场到结束完整跑一次。

不因为“这一段已经测试过”就跳过。

记录：

- 哪一步需要人工确认；
- 哪个 cue 容易错；
- 哪个软件最慢；
- 哪条链路最脆弱。

### Step 10｜现场前停止无必要修改

最后阶段优先稳定，而不是继续追求 5% 的视觉提升。

如果一个修改不会显著提高作品，却可能破坏稳定性，留到下一版。

## 常见失败

### 失败 1｜开发机没问题，现场机打不开

恢复：在正式现场机上重新做冷启动；检查插件、字体、媒体路径和 GPU / 浏览器差异。

### 失败 2｜素材变紫 / Missing Media

恢复：把所有外部媒体集中到明确目录；重新链接；导出 fallback 视频。

### 失败 3｜网络断开后网页失效

恢复：所有演出关键代码、模型、音频和字体本地化；避免正式演出依赖 CDN / API。

### 失败 4｜MIDI / OSC 有信号但映射错位

恢复：使用固定端口 / 设备名；现场前导出 Mapping 表；准备键盘操作作为最低级 fallback。

### 失败 5｜临演前继续改工程

恢复：回到冻结版本。任何新增功能延期到下一次演出。

## 完成标准

另一位执行人员在你短暂离开电脑的情况下，至少能够根据文档完成：

- 启动工程；
- 输出正确画面；
- 触发主要状态；
- 黑场 / Stop；
- 在主系统失败时切换到 fallback。

如果这些只能靠作者本人“凭感觉”完成，系统还没有达到现场可用状态。
