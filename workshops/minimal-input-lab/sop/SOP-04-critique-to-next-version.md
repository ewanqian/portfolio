# SOP-04｜一次 Critique 怎么进行

## 目的

把“我觉得哪里差点意思”转换成一个下一版可以执行的修改任务。

Critique 的目标不是证明作者做得好不好，也不是把所有问题一次说完。它要帮助作者确定：这一版最重要的问题是什么，为什么重要，下一版只改什么。

## 输入

- 一个可以完整观看的 V1；
- 作品当前要解决的问题；
- Stage Plot / Cue Sheet / 操作说明中的至少一种；
- 10–30 分钟不被打断的评审时间。

## 输出

- 一条最重要的观察；
- 一条原因判断；
- 一个明确的 V2 修改任务；
- 一个验证方法。

## Procedure

### Step 1｜作者先说当前目标

只说两句话：

1. 这一版只研究什么；
2. 最担心哪里不成立。

不要先解释所有设计意图。

### Step 2｜完整看一遍

评审者第一次观看不打断，不问问题，不要求现场修改。

记录第一次观看时真正注意到的东西。

### Step 3｜先说观察，不先说方案

使用可被验证的描述：

- “18–24 秒里四条轨道同时增加，所以我没有感到第二次推进。”
- “人物进入以后主屏仍然是最亮的，因此我的注意力没有转到人物。”
- “顶部屏从第 6 秒就出现，24 秒的 Peak 没有新的空间层。”

避免：

- “感觉不高级”；
- “再酷一点”；
- “有点 AI”；
- “这个不太行”。

### Step 4｜判断问题属于哪一层

把问题先归到一类：

- Structure / 结构
- Timing / 时间
- Relation / 媒介关系
- Control / 控制
- Craft / 制作质量
- Documentation / 沟通

优先解决上层问题。

如果结构本身不成立，不先花时间调材质。

### Step 5｜只选一个主问题

如果出现十个问题，问：

> 哪一个问题修好以后，会同时改善最多其他问题？

把它定义为本轮 V2 的主问题。

### Step 6｜把反馈写成动作

错误写法：

> 高潮不够强。

可执行写法：

> 18 秒以前把主光上限从 60% 降到 30%，顶部屏延迟到 22 秒进入；其他轨道暂时不改。

### Step 7｜定义验证方式

在修改前先写清楚怎么判断有效。

例如：

> V2 与 V1 连续播放时，不看时间码也能明确指出第一次完整空间展开发生在哪一版、哪一秒。

### Step 8｜做 V2 后重新看

先只检查原问题是否改善。

不要因为出现新想法，就忘记本轮 Critique 在验证什么。

## 两人互评模板

每个人只需要说四句：

1. **我最清楚的一段是……**
2. **我最不清楚的一段是……**
3. **我认为主要原因是……**
4. **如果只改一件事，我建议……**

## 常见失败

### 失败 1｜评审变成审美投票

恢复：所有意见必须指向具体时间、对象、操作或空间关系。

### 失败 2｜讲师一次说二十条

恢复：完整记录可以保留，但本轮只批准一条进入 V2。

### 失败 3｜作者不断解释

恢复：先让作品自己被看见。解释放在第一轮观察以后。

### 失败 4｜反馈直接要求换风格

恢复：先判断原来的目标是否成立；只有目标本身错误时才讨论重新定方向。

### 失败 5｜V2 无法证明更好

恢复：回看修改前写下的验证方法。如果无法验证，说明反馈本身定义得太模糊。

## 完成标准

一次有效的 Critique 结束时，不应该留下“我得回去全改了”的状态，而应该留下一个非常具体的下一步：

> **我知道这一版最严重的问题是什么，也知道下一版只需要先做哪一件事。**
