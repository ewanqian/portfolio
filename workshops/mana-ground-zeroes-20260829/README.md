# Ground Zeroes｜MANA 先导工作坊
## 游戏化 AI 新媒体艺术工程师 × 音画同源乐器｜速通合订版

**日期：** 2026-08-29  
**形式：** 3 小时工作坊 + 当日晚间 After Party / Micro Showcase  
**建议人数：** 12–20 人  
**发起人 / 导师：** 钱誉文 Ewan Qian  
**定位：** 两条长期工作坊的第一期先导演示版 / Demo Edition

> 三小时内不试图把参与者训练成程序员或音乐人，而是先给每个人一套能继续探索的“最低可用装备”：知道怎样和 AI 一起搭项目、怎样先做骨架再填细节、怎样把声音与图像接进同一个可演奏系统，并在当天晚上完成第一次公开试玩或短演出。

---

## 为什么叫 Ground Zeroes

这是正式系列展开之前的起点。

它把两项长期工作坊中最必要的部分压缩到一次体验里：

1. **《游戏化 AI 新媒体艺术工程师》**：怎样开始一个项目、怎样和 AI 协作、怎样用工程化的方法避免一开始陷入细节。
2. **《音画同源乐器》**：怎样把声音、图像和操作动作组织成一件可以实时玩的数字乐器。

第一期不追求完整知识量，只追求一个结果：

> **下午做出来，晚上可以玩。**

# 三小时流程

## 00:00–01:00｜LEVEL 01 — 先制造一辆能跑的车
### 游戏化 AI 新媒体艺术工程师｜最低必要技能包

这一小时不是软件培训，而是建立一个以后能反复使用的开发顺序。

### 1. AI Coding 是什么

用一个非常短的演示说明：

```text
想法
 ↓
让 AI 帮助拆任务
 ↓
得到第一版
 ↓
运行
 ↓
发现问题
 ↓
修改
```

参与者不需要理解底层模型，只需要知道：AI 可以写、改、解释和排查，但**人负责决定目标和判断结果**。

### 2. 工程化创作的最小循环

用三个阶段解释开发：

**FRAME → FILL → FINISH**

- **FRAME / 框架：** 先决定作品到底怎么工作
- **FILL / 填充：** 再加入素材、声音、视觉与状态
- **FINISH / 打磨：** 最后测试、删减、修复和发布

核心提醒：

> 不要第一小时把一个按钮做得特别漂亮，却到第三小时还没有完整作品。

### 3. Human-in-the-loop

参与者只需要记住：

**AI 提议 / 执行 → 人运行 / 判断 → AI 修改 → 人决定下一版。**

### 4. 项目与版本

只讲最基础的几个概念：

- 项目文件夹
- README
- V1 / V2
- Git / GitHub 是什么
- 为什么要保留能工作的版本

不在课堂里展开复杂 Git 命令。

### 5. 第一个小练习

每个人从统一 Starter Kit 开始，完成一个最简单的交互：

> **一个按键 / 鼠标动作 → 一个视觉状态变化。**

到第一小时结束，所有人的系统必须已经“能跑”。

## 01:00–02:00｜LEVEL 02 — 声音和图像原来可以一起发生
### 从 Visual Exercise 到 Audiovisual Mapping

第二小时开始进入新媒体艺术与实时音画。

### 1. 先看几个非常短的例子

不从软件历史讲起，而从身体经验进入：

- 按一下，为什么同时听见和看见会更像一件“乐器”？
- 一个声音为什么不一定只能控制音量？
- 一张静态图片怎样通过运动、闪烁、尺度和状态变成 Live Visual？
- TouchWaves 一类案例为什么让人觉得声音和视觉来自同一个动作？

### 2. 视觉练习

导师可使用 Processing / Creative Coding 做快速示范，例如：

- Logo 在屏幕中弹跳
- 粒子速度变化
- 画面反相 / 爆闪
- 1 / 2 / 3 / 4 切换不同状态

参与者版本保持更简单，直接在统一 Browser Starter Kit 中修改视觉模块，避免临时切换多个软件环境。

### 3. 十个声音

参与者用手机或电脑快速收集 **5–10 个身边声音**：

- 敲桌子
- 门声
- 脚步
- 水声
- 说话
- 电器声
- 环境噪声

也可以使用自己提前准备的 MP3 / WAV。

### 4. 第一组 Mapping

至少建立三种关系中的一种或两种：

- **Trigger：** 按键 → 声音 + 视觉事件
- **Continuous：** 鼠标移动 → 声音参数 + 图像参数
- **State：** 一个动作 → Quiet / Active / Flash 等状态切换

到第二小时结束，每个人必须已经有一个**声音和图像同时响应的原型**。

---

## 02:00–03:00｜LEVEL 03 — 把 Demo 变成一件可以玩的东西
### Personal A/V Instrument MVP

第三小时不再继续增加知识，而是收口。

### 1. 给它一个身份

每个人完成：

- 一个名字
- 一个非常简单的视觉界面
- 3–6 个可操作动作
- Quiet / Active 至少两个状态

作品可以很怪，但必须让人知道怎样玩。

### 2. 加入个人素材

可以使用：

- 自己拍的照片
- AI 图像 / 视频片段
- Generative Art
- Logo / 字体
- 扫描 / 纹理
- 自己录制的声音

### 3. Blind Test

两人交换电脑，作者不解释。

测试者只回答：

- 我知道怎么开始吗？
- 哪个键最好玩？
- 我在哪里卡住？
- 哪个效果可以删掉？

然后只修最重要的一处。

### 4. Rehearsal

每个人准备一个 **30–60 秒 Micro Set**。

不是介绍 PPT，而是直接操作作品：

```text
进入
→ 建立一个状态
→ 变化
→ 高点
→ 收回来
→ 结束
```

# After Party / Micro Showcase

当天晚上安排一个轻量 After Party / Playground。

它不是正式演出考核，而是第一次让参与者体验：

> **我下午做的系统，晚上真的可以被别人看到、听到和玩到。**

建议形式：

- 每人 30–90 秒
- 可以单人，也可以两人临时 B2B
- 作品直接电脑全屏输出即可
- 现场如有 MIDI Controller，可设置少量轮换体验位
- 不强制所有参与者上台
- 可以保留一个开放试玩桌，让观众直接操作作品

After Party 同时承担第二轮测试：哪些作品真的可以玩？哪些 Mapping 在现场成立？哪些作品需要继续开发？

# 第一版技术策略

## 参与者唯一默认主线

为了保证三小时能完成，第一期尽量只维护一套 Starter Kit：

**Browser + JavaScript Creative Coding + Audio Library + AI Coding Assistant**

目标是：

- 打开即可运行
- 可以全屏
- 可以加载本地图片与音频
- 支持键盘 / 鼠标
- 支持多状态
- 后续可以增加 MIDI
- 可以发布成一个网页链接

### 为什么第一期不把 Arena / NDI / Syphon 设为必修

这些都是后续演出系统可以使用的扩展，但它们不会直接提高第一期参与者完成作品的概率。

第一期首先保证：

> **一台电脑 + 浏览器 = 一件可以玩的作品。**

导师可以展示 Processing、Arena、MIDI 或其他自己的真实工作流，但参与者不需要在三小时内完成整套专业演出链路。

# 发布

Browser 版本的另一个重要意义是作品可以继续存在。

课程结束后，参与者可以进一步把项目发布到 GitHub Pages、Cloudflare Pages 或其他静态网页托管平台，获得一个可以直接分享的 URL。

第一期如果现场网络或账号状态不适合部署，则优先保证本地版本可运行，发布作为课后步骤，不让部署吃掉创作时间。

# 课前准备原则

所有能提前解决的安装问题都不要占用正式三小时。

参与者报名后收到 Preflight Guide，至少确认：

- 笔记本电脑可用
- 推荐浏览器已安装
- Starter Kit 可以打开
- 能修改一行文字并重新运行
- 耳机可用
- 准备 5–10 个声音或允许现场录音

AI Coding 工具的具体默认方案，在活动前根据稳定性统一确定，不要求参与者自行研究多套工具。
