# 音画同源乐器
## Personal A/V Instrument

**项目类型：** 公众工作坊 / Audiovisual Instrument / Creative Coding / Live Performance  
**发起人：** 钱誉文 Ewan Qian  
**当前状态：** 2026 合作提案与长期研发中

> 带来自己的声音、图像和动作，把它们制造成一件能够用键盘、鼠标甚至 MIDI 控制器亲手演奏的网页音画乐器。

## 这是什么

《音画同源乐器》不是一门“音乐可视化”教程，也不是 Tone.js、MIDI 或某一种软件的功能课。

它讨论的是一个更基础的问题：**什么时候一个网页不再只是网页，而开始成为一件可以学习、练习、分享和演奏的乐器？**

参与者会使用自己的声音、照片、视频、扫描、文字和动作习惯，从最基础的键盘与鼠标开始，设计声音、图像与身体操作之间的关系，并最终完成一件属于自己的 Browser-based Audiovisual Instrument。

工作坊的核心不是“让声音驱动画面”，而是 **Mapping / 映射**：一个动作怎样同时改变声音与视觉？一个旋钮为什么控制这个参数而不是另一个？什么时候作品应该安静，什么时候应该进入高能状态？这些关系共同决定一件数字乐器的性格。

## 核心方法

整个工作坊可以压缩成一条很清楚的路径：

**个人材料 → 动作 / Gesture → Mapping → 声音 + 图像 → 状态 → 演奏**

例如：

- 一个按键同时触发一段声音与一个视觉事件
- 鼠标移动同时改变声音滤波和图像尺度
- 一个推子同时改变声音密度与画面残影
- 一个按钮让作品从 Quiet State 切换到 Active State

参与者不是简单替换模板素材，而需要自己决定：**这件乐器应该怎样被玩、怎样被理解、怎样形成自己的节奏和个性。**

## 从玩具开始

公众版不会从长篇理论或代码讲解开始，而是先让参与者试玩几件简单的网页乐器、小游戏和数字控制界面。

我们从很日常的经验进入：键盘、鼠标、Pad、Knob、Fader、计算器式界面、游戏机式操作——为什么有些数字东西一碰就让人想继续玩？当声音和图像同时回应时，它什么时候会变成一件真正可以“演奏”的东西？

理论和技术只用于帮助回答这些问题，而不是成为课程主体。

## 参与者会做什么

每个人提前准备少量个人材料，例如：

- 3 段 3–10 秒的环境声音
- 5 张自己拍摄的照片或纹理
- 可选的短视频、扫描、点云或 3D 素材
- 一个自己感兴趣的动作：敲、拖、转、摇、按、重复、停止等

现场会先用“动词”而不是文件格式重新整理素材，再设计至少三种 Mapping：

1. **Trigger**：一次操作触发声音与视觉事件
2. **Continuous Mapping**：连续操作同时改变声音与视觉参数
3. **State Change**：让系统在不同演奏状态之间切换

每件作品至少拥有 **Quiet State** 与 **Active State**，避免最终只变成不断叠加效果的 Demo。

## 3 小时公众版

**00:00–00:15｜Play First**  
先试玩示范乐器，只讨论“为什么它像乐器”。

**00:15–00:35｜从玩具到数字乐器**  
用非常短的案例介绍 Audiovisual Instrument、Mapping 与实时演奏。

**00:35–01:00｜个人材料与 Mapping Card**  
整理个人素材，建立 Trigger、Continuous Mapping 与 State Change。

**01:00–01:45｜Build V1**  
从统一 Starter Kit 出发，用 AI 辅助替换素材、连接参数和排查错误。

**01:45–02:10｜State & Identity**  
建立 Quiet / Active 状态，并为作品取名、设计视觉外壳与控制方式。

**02:10–02:30｜Controller Station**  
现场可提供约 2–4 个 MIDI Controller 轮换体验，把已有键鼠 Mapping 映射到 Pad、Knob 或 Fader。

**02:30–02:45｜Blind Playtest**  
交换电脑，作者不能解释，让别人第一次直接尝试演奏。

**02:45–03:00｜Micro Performance**  
进行 30–60 秒短演出。展示的不是“网页有哪些功能”，而是“我怎样演奏它”。

## 参与者最终带走

每位参与者至少完成：

- 一件有名字的 Browser A/V Instrument
- 一个可运行网页或完整项目包
- 至少三组明确的 Mapping
- 一套 Keyboard / Mouse 控制方案
- Quiet + Active 两个演奏状态
- 一套个人视觉身份与控制说明
- 一次 Blind Playtest 记录
- 一段 30–60 秒短演出
- V2 修改计划

MIDI 是增强层，而不是参加门槛。即使没有任何控制器，参与者也必须能够仅用键盘和鼠标完成、练习和演奏自己的作品。

## 形式与条件

- **公众版：** 3 小时，建议 12–20 人
- **参与门槛：** 不要求音乐训练或编程基础，自带笔记本电脑与有线耳机
- **设备建议：** 现场可提供 2–4 个 MIDI Controller 作为体验位
- **场地建议：** 投影、稳定 Wi-Fi、电源、桌椅；如安排最终演出，建议提供基础扩声系统

正式活动前会提供 Preflight Guide，用于完成浏览器、声音、Starter Kit 与可选 MIDI 的基础测试。

## 可扩展为 Workshop + After Party

这项工作坊更适合被理解为一个持续过程，而不是一次三小时课程。

推荐长期结构：

**Build → 7–14 天 Incubation → Rehearse → Perform**

参与者在第一次工作坊完成 V1 后继续修改自己的乐器，再通过第二次排练或 After Party 真正演奏它。After Party 不只是结课展示，而是第二轮压力测试：一件原型是否真的可以被练习、理解和公开演奏？

长期可逐渐形成 **Personal A/V Instrument Archive**，记录不同参与者的乐器、版本、操作方式、Playable URL 与演出片段。

## 研究背景

工作坊的方法参考数字乐器与 NIME（New Interfaces for Musical Expression）领域长期关于 **parameter mapping、gesture、instrument design、performance practice 与 instrument longevity** 的研究。其中，Hunt、Wanderley 与 Paradis 在 NIME 2002 的 *The Importance of Parameter Mapping in Electronic Instrument Design* 是本项目关于 Mapping 的重要理论起点。

研究不会作为大段学术讲授进入公众课堂，而是用于持续校准课程设计：参与者是否真的在设计一件乐器，而不是堆叠视觉效果？别人是否能够理解并演奏？作品是否值得在工作坊结束后继续存在？
