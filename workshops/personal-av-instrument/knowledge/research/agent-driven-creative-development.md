# Agent 驱动的创意技术开发：版本、上下文与经验沉淀

## 摘要

AI Agent 进入网页、实时视觉和创意技术开发以后，开发速度明显提高，但项目也更容易出现范围失控、版本混乱、重复修正和经验无法累积的问题。稳定的工作方式需要同时处理三个层面：项目版本、项目上下文和可复用经验。

本笔记结合 8.29「极简输入：构建视听系统」工作坊的实践，以及 Ewan Qian 对 Antoine van der Lee 在 LET'S VISION 2026 关于 Agent-driven development / Agent Skills 分享的整理，形成一套适用于 Creative Coding、Web Audio、实时视觉与网页音画乐器的工作框架。

---

## 1. Agent 改变的是开发循环

传统的 AI 辅助方式常以单次 Prompt 为单位：提出需求，获得代码，再继续追加要求。

当 Agent 可以读取仓库、修改多个文件、运行命令并持续迭代以后，问题开始转向开发流程本身：

```text
目标
↓
读取项目上下文
↓
提出修改范围
↓
执行
↓
运行 / 测试
↓
Human Review
↓
保存版本
↓
下一轮
```

这一循环要求每一轮都存在明确边界和验收方式。Agent 的执行能力越强，范围管理越重要。

---

## 2. Git 保存项目状态

聊天记录能够解释一次讨论，但不能替代项目版本。

对于 AI 辅助开发，Git 至少承担四个作用：

1. 记录每轮实际修改；
2. 比较 Agent 改动前后的差异；
3. 允许失败实验被撤销；
4. 让公开视频、在线页面与当时的源码建立对应关系。

一个可追溯的创意项目可以同时记录：

```text
作品版本 v0.8
Commit SHA
公开 URL
录屏 / 截图
简短 DEVLOG
```

这样，视觉结果、交互行为和代码状态能够被重新找到。

---

## 3. 项目上下文与通用经验分层

Agent 需要上下文，但所有经验都放进同一个长文档会逐渐降低可维护性。

可以分成两类。

### 项目上下文

保存在 README、AGENTS.md 或项目文档中：

- 目录结构；
- 运行命令；
- 当前视觉语言；
- 文件与资产规范；
- 禁止改动的模块；
- 当前部署方式；
- 项目专有术语。

### 可复用经验

整理成 Skill：

- Beat Clock / Quantize；
- Shared-State A/V；
- Variant Design；
- Density / Safety；
- Audio Voice Design；
- Blind Playtest；
- Versioned AI Iteration。

项目文档回答「这个项目是什么」，Skill 回答「遇到这类问题时通常怎么处理」。

---

## 4. 从 Prompt 到 Skill

一次 Prompt 解决一次任务。Skill 保存一类问题的判断路径。

经验适合固化为 Skill，通常需要具备以下特征：

- 多次重复出现；
- 可以跨项目使用；
- 有稳定步骤；
- 有失败模式；
- 有明确验收方式。

一个 Skill 可以使用下面的结构：

```text
触发条件
↓
目标
↓
需要读取的输入
↓
执行步骤
↓
常见失败
↓
验收标准
↓
输出格式
```

这比保存越来越长的 Prompt 更适合长期维护。

---

## 5. 创意判断需要另外保存

创意技术项目中，很多重要经验并不是代码规则。

例如：

- 一个 Visual Variant 是否真的改变了行为；
- 声音和视觉是否共享同一个状态；
- 一个界面是否具有演奏感；
- 密度什么时候已经过量；
- 哪种随机仍然保留可控性；
- 哪个版本虽然技术正确，但不值得继续。

这类经验可以先写成设计原则、测试问题或案例笔记。只有当它形成稳定判断和验收方式以后，再升级成 Skill。

因此，知识沉淀可以分成三层：

```text
项目记录 / DEVLOG
↓
设计原则 / 研究笔记
↓
可复用 Skill
```

---

## 6. Human Review 的位置

Agent 适合处理：

- 读取大量上下文；
- 生成候选；
- 执行重复步骤；
- 运行静态检查；
- 整理 diff；
- 汇总测试结果。

创作者需要保留：

- 目标设定；
- 边界控制；
- 美学判断；
- 版本选择；
- 是否进入下一轮。

在实时音画项目中，一个稳定的循环可以写成：

```text
Skill / Rule
↓
Agent 修改
↓
运行
↓
试玩 / 观看 / 聆听
↓
Human Review
↓
Git Commit
↓
有效经验回写 Skill 或笔记
```

---

## 7. 对工作坊的意义

在工作坊中学习 Git 的意义不只在发布网页。

参与者可以把每一次小练习保存成独立版本：

- v0.1：只有 Trigger；
- v0.2：加入 Tap / Hold / Release；
- v0.3：加入 BPM；
- v0.4：加入 Shared State；
- v0.5：加入 Visual Variant；
- v0.6：第一次 Blind Playtest；
- v0.7：根据反馈修正。

这种记录方式使学习过程本身成为可以回看的开发历史，也让后续 Agent 能够读取项目如何一步步形成。

---

## 8. 最小实践建议

对于个人 Creative Coding 项目，可以从下面四个文件开始：

```text
README.md      项目是什么、怎么运行
AGENTS.md      当前项目的规则和边界
DEVLOG.md      每轮重要修改与决定
skills/        已经验证的可复用方法
```

再配合 Git commit 和一个稳定的在线发布地址，就可以形成一个长期可维护的创作项目。
