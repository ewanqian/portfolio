# Skill 13｜把重复经验整理成 Agent Skill

## 用途

当你发现自己反复对 AI 说同样的话、反复修同一种错误，或者某一类判断已经形成稳定经验时，可以把它从一次性的 Prompt 中抽离出来，整理成可复用的 Skill。

这适用于代码，也适用于视觉、声音、交互、现场系统、资产整理和发布流程。

---

## Prompt 和 Skill 的区别

### Prompt

解决当前这一轮任务：

```text
把这个按钮改成 Hold 以后进入持续状态。
```

### Skill

保存一类问题的判断路径：

```text
当系统出现 Hold 输入时：
- 判断是否需要阈值；
- 判断 Hold 进入 sustain、loop 还是 accumulation；
- 检查 Release；
- 检查 voice cleanup；
- 检查视觉 residue；
- 检查 Reset。
```

Skill 的重点是让经验可以再次调用。

---

## 什么值得整理成 Skill

满足下面任意两项，就值得考虑：

- 同一个提醒已经说过三次以上；
- 在多个项目中都会遇到；
- 错误发生后代价较高；
- 有清楚的检查方法；
- 已经形成固定判断顺序；
- 可以通过输入、步骤和输出来描述；
- 需要 Agent 在修改前先读一组参考资料。

例如本工作坊已经整理出的：

- Beat Clock / Quantize；
- Shared-State A/V；
- Release / Residue / Memory；
- Audio Voice Design；
- Blind Playtest；
- Video Reference Analysis；
- Versioned AI Iteration。

---

## 什么先不要做成 Skill

- 一次性的审美偏好；
- 还在快速变化、自己也没想清楚的判断；
- 只适用于一个具体文件的临时修补；
- 没有验收方法的抽象口号；
- 单纯把一个长 Prompt 换个文件名保存下来。

这类内容可以先留在项目笔记或 `AGENTS.md`。

---

## 项目规则与通用经验分开

可以使用两层：

### 项目自己的 `AGENTS.md`

保存当前项目才有的信息：

- 文件结构；
- 运行方式；
- 当前视觉语言；
- 禁止改动的区域；
- 发布路径；
- 项目特有命名。

### 可复用 Skill

保存跨项目仍然有效的方法：

- 如何设计 Variant；
- 如何做 Blind Playtest；
- 如何检查 Web Audio gain staging；
- 如何进行版本化 Agent 修改；
- 如何从参考视频提取结构。

这样项目上下文不会越来越臃肿，通用经验也可以在不同项目中复用。

---

## 一个 Skill 的最小结构

```text
名称
↓
什么时候调用
↓
目标
↓
需要读取什么
↓
执行步骤
↓
常见错误
↓
验收方法
↓
输出格式
```

例如：

```md
# Skill｜Blind Playtest

## 什么时候调用
一个交互原型已经能运行，但作者无法判断哪里不好用。

## 输入
- 当前 URL
- 操作说明
- 试玩记录

## 步骤
1. 作者不解释；
2. 记录第一操作；
3. 记录卡住位置；
4. 归类问题；
5. 只修一个最大问题。

## 验收
第二位陌生用户是否更快找到主要输入。
```

---

## 从一次开发中提取 Skill

一次项目结束后，可以做下面的整理：

### 1. 找重复出现的问题

```text
这次我提醒 AI 最多的是什么？
```

### 2. 找稳定判断

```text
哪些修改我每次都会保留？
哪些结果我每次都会删掉？
```

### 3. 找验证方式

```text
我怎么知道它做对了？
```

### 4. 把项目专属信息删掉

把文件名、作品名、客户名换成通用输入。

### 5. 用另一个项目测试

如果换一个项目仍然能用，这条经验才开始接近 Skill。

---

## Human in the Loop

Skill 不负责替人完成最终判断。

适合交给 Agent 的部分：

- 读取项目；
- 执行重复步骤；
- 做静态检查；
- 生成候选；
- 对比版本；
- 汇总测试结果。

需要人保留的部分：

- 目标；
- 边界；
- 审美判断；
- 哪个版本值得保留；
- 是否进入下一轮。

---

## 和版本管理一起使用

最稳定的组合是：

```text
Skill
↓
Agent 执行一轮
↓
运行 / 测试
↓
Human Review
↓
Git Commit
↓
有效经验回写 Skill
```

代码版本保存“发生了什么”，Skill 保存“以后遇到类似问题应该怎么做”。

---

## 可直接复制给 Agent

```text
请复盘这个项目最近的开发记录和 Git 历史，帮助我判断哪些经验值得整理成可复用 Skill。

请分类：
A. 项目专属规则：留在 AGENTS.md / README；
B. 可跨项目复用的方法：候选 Skill；
C. 一次性尝试：只留在开发记录；
D. 还没有验收标准的判断：暂不固化。

对于每个候选 Skill，输出：
- 名称；
- 什么时候调用；
- 输入；
- 执行步骤；
- 常见失败；
- 验收标准；
- 一个最小示例。

不要把长 Prompt 原样包装成 Skill。优先提取反复出现、可验证、跨项目有效的经验。
```

## 研究来源

本条目结合 8.29 工作坊的 Agent 辅助开发实践，以及 Ewan Qian 对 Antoine van der Lee 在 LET'S VISION 2026 关于 Agent-driven development / Agent Skills 分享的整理：项目规则与通用领域经验可以分开维护；可重复、可检查的经验适合逐步沉淀为 Agent 能再次调用的结构。
