01 · WHAT WE BUILT

不是从软件开始，
而是从关系开始。

这次工作坊把一个很小的输入逐步扩展为一套可演奏系统。重点不在某个软件，而在输入如何进入时间、状态与反馈，并同时作用于声音和视觉。

INPUT ↓ TAP / HOLD / RELEASE ↓ BPM / BEAT / QUANTIZE ↓ MAPPING / SHARED STATE ↙ ↘ SOUND VISUAL ↓ SCENE / MEMORY / FEEDBACK ↓ PERFORMANCE / SHARE
02 · SIX CONCLUSIONS

这次真正留下来的六件事。

01

极简输入不等于极简行为

一个按钮还可以读取按下、按住、松开、重复频率、间隔和当前 State。输入很少，行为可以很深。

02

节拍是共享坐标

BPM 不只是一个显示数字。人的输入可以先被确认，再被放进 beat、1/8 note 或 bar，让声音与视觉共同进入稳定时间结构。

03

声音与视觉共享 State

声音不必先产生、画面再去跟随。更值得研究的是让二者共同读取 energy、density、scene、memory 等高层状态。

04

演奏性来自关系

观众需要看见动作与结果的关联，但不必在几秒内完全看穿。Trigger、Intensity、State 与身体动作可以形成简单但成立的演奏关系。

05

小练习可以累积成 Live Set

先让一个状态单独运行也成立，再保存、比较和继续修改。长期积累的 Scene、Role 与 Variant 最终比一次生成完整系统更可靠。

06

AI 更适合快速产生候选

描述一个小问题，让 Agent 实现，运行、比较、删除、保留。生成更多不是终点，判断哪些值得留下才是创作。

03 · FROM BROWSER TO STAGE

网页是入口，
不是边界。

浏览器适合快速原型与分享。需要更长期的现场系统时，可以继续把同一套 Input / Mapping / State / Feedback 逻辑带进 Processing、OSC、Syphon / Spout、TouchDesigner 或 Resolume 等环境。

Keyboard / Mouse / Phone / Sensor ↓ Mapping / State / Clock ↓ WebGL + Web Audio or Processing / p5.js ↓ OSC / Syphon / Spout ↓ Stage Software / Live Output
