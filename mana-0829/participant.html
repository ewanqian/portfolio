8.29 WORKSHOP · PARTICIPANT FOLLOW-UP

把这次练习
继续做下去。

不需要重新学一套软件，也不需要马上做完整 Live Set。每次只选一个关系继续修改，保存下来，再让别人试玩。

01 · REMEMBER THIS

课后只需要记住这条主线。

INPUT ↓ MAPPING ↓ STATE / CLOCK / MEMORY ↙ ↘ SOUND VISUAL ↓ FEEDBACK ↓ NEXT DECISION
02 · SIX SMALL EXERCISES

一次只改一件事。

EXERCISE 01

一个按钮

继续研究 Tap / Hold / Release / Idle。先把一个输入做出时间结构。

EXERCISE 02

放进节拍

加入 BPM / Transport / Quantize，让输入进入稳定 beat 或 1/8 note。

EXERCISE 03

增加 State

OPEN / BUILD / PEAK / BREAK。让同一个 Trigger 在不同状态中有不同意义。

EXERCISE 04

增加视觉结构

GRID / ORBIT / GLYPH / FIELD / GRAPH / TRAIL。优先改变空间与行为，不只换颜色。

EXERCISE 05

把键盘做成控制器

Space 做主输入，方向键改 BPM / Scene，数字键切 Visual Variant，F 全屏，Esc Reset。

EXERCISE 06

加入外部输入

鼠标速度、摄像头亮度、手机陀螺仪、MIDI Fader 都可以先转成 0–1 参数，再进入 Mapping。

03 · COPY TO YOUR AGENT

一个按钮的继续练习。

先读取当前项目，不要重写框架。 保持一个主要输入键。 加入四个状态： - TAP：短促的声音与视觉事件； - HOLD：按住后进入持续状态； - RELEASE：松开后进入 1–3 秒衰减； - IDLE：没有输入时仍保留轻微 ambience / residue。 加入唯一的 BPM / Transport。 Audio 与 Visual 都读取同一组 state、beat 和 bar。 保留 Reset / Panic。 完成后告诉我：改了什么、怎么测试、还有什么限制。
04 · CONTROL MAP

最小键盘可以这样开始。

SPACE Main Trigger ↑ / ↓ BPM ±5 ← / → Scene 1 / 2 / 3 / 4 Visual Variant A Auto / Assist F Fullscreen ESC Panic / Reset

以后继续增加按键时，先给它们定义角色。尽量避免 Effect 1 / Effect 2 / Effect 3 这种没有结构的堆叠。

05 · SAVE + SHARE

让练习变成一个真正可以分享的链接。

01
创建 GitHub Repository。
02
保证 index.html 是入口。
03
图片、声音、CSS、JS 全部使用相对路径。
04
Settings → Pages，选择发布分支。
05
等 Pages URL 出现后，用无痕窗口重新打开。
06
测试声音、键盘输入、全屏和移动端是否正常。
请把当前静态网页项目整理成适合 GitHub Pages 发布的版本。 要求： 1. index.html 是入口； 2. 所有资源使用相对路径； 3. 不把 token、密码、内网地址写入仓库； 4. 添加简短 README，写清楚操作方式； 5. 提交到我指定的 GitHub 仓库； 6. 告诉我如何开启 GitHub Pages； 7. 发布后重新检查最终 URL 是否可以正常打开、播放声音和进入全屏。
06 · ADVANCED ROUTE

网页之外，可以继续接到现场系统。

Phone / Sensor ↓ OSC ↓ Processing / TouchDesigner / Other Runtime ↓ Syphon (macOS) / Spout (Windows) ↓ Resolume / Stage Output
浏览器仍然很适合快速测试和分享。只有当你开始需要更稳定的现场链路、更多外部设备或多软件协同时，再进入这一层。
07 · SHARE BACK

回群里不用写长总结。

如果继续做了一个版本，发三样就够：

一个可以直接打开的 URL
10–20 秒操作录屏
一句话：这次只改了什么关系
如果卡住，直接发截图 + 当前链接
例：我这版只研究 Hold Duration。按住越久，声音密度和视觉残影越强；松开后会留下 2 秒 residue。
