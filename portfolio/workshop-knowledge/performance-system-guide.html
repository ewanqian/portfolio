FINAL GUIDE · BROWSER PERFORMANCE SYSTEM

从网页视觉，到可以直接上台演出的控制系统。

把已有 HTML、WebGL 视觉、音乐结构和参考图整理到同一个 Stage。系统负责保持时间、状态和稳定性；表演者负责改变 Phrase、Scene、Energy 与连续参数。

INPUT ↓ FILTER / QUANTIZE ↓ SHARED CLOCK + PERFORMANCE STATE ↓ AUDIO ENGINE VISUAL ENGINE ↓ ↓ MUSIC PHRASE VISUAL SCENE ↘ ↙ PERFORMANCE

02. 已经有很多 HTML？直接接进 Stage。

最快的方法是让主页面负责音乐、时钟、输入和场景切换；已有视觉 HTML 继续只负责画面。先保留，再统一控制。

QUICK ROUTE

Stage Shell + iframe

把视觉放到 /visuals/scene-01.html 等路径。Stage 使用 same-origin iframe 加载，并通过 postMessage 发送共享状态。

frame.contentWindow.postMessage({ type: 'AV_STATE', state }, '*')
LATER

性能要求更高再模块化

当多个 WebGL Scene 需要共享 renderer、camera、GPU 资源或精确 dispose，再改成模块接口。

scene.mount(container) scene.update(state, dt) scene.trigger(event) scene.dispose()

03. 控制维度不需要很多。

KEYBOARD

离散决定

A/S/D/F、J/K/L/; 可以负责 Phrase / Scene；1–4 负责 OPEN / BUILD / PEAK / BREAK；Space 负责 NEXT / ROUTE / ACCENT。

MOUSE XY

连续变化

Mouse X 可以控制 cutoff / width / orbit radius；Mouse Y 可以控制 density / reverb / line width / depth。按住 A + Mouse XY 时，可以进入 A Scene 的第二层控制。

人的输入可以表达“现在想发生”，系统再把正式事件安排到正确的音乐边界。

human input → acknowledgement now → pending intent → next 1/8 note / beat / bar → audio + visual phrase

04. Scene 是演出角色，不只是 Preset。

OPEN / GRID / WAVE / OBJECT

分别承担建立空间、明确节奏、连续运动、3D 空间推进。

SCAN / MATRIX / IMPACT / RELEASE

分别承担高频过渡、字符与数据密度、强重音、尾声与残影。

4–8 幕已经足够完成一段短演出。每幕至少要在声音角色、视觉行为、进入方式和退出方式上有区别。

05. 视觉可以写得更具体。

如果画面不够丰富，不必只说“再酷一点”。为每幕写 6 个字段：Scene / Composition / Motion / Density / Material / Response。

SCENE: MATRIX SCAN COMPOSITION: 中央 40×24 数据网格，两侧留黑。 MOTION: 每个 beat 横向扫描；每 4 beats 一次结构错位。 DENSITY: OPEN 20%，PEAK 80%。 MATERIAL: 细白线、少量高亮 Glyph、无渐变背景。 RESPONSE: Mouse X 控制扫描方向；Mouse Y 控制线宽；A 触发局部坍缩。

参考图可以放入 /references/。告诉 Agent 借鉴 composition、line language、density、depth、motion、material，而不是让它“照着做”。

06. 音乐可以自己运行，但变化要受约束。

Shared BPM → 8/16-step pattern → 3–4 pattern variants → 每 1–2 bars 只改变 1–2 个参数 → 每 4–8 bars 才允许较大 Scene / Energy 变化
SONIC ROLES

LOW / MID / HIGH / AMBIENT / FX

统一 Scale / Key。Low 放结构，Mid 放主体，High 放时间颗粒，Ambient 放空间，FX 放过渡。比不断增加随机声音更容易形成演出身份。

SAFETY

Gain Staging

保留 Voice Limit、Master Volume、Compressor、Limiter。高密度时自动降低单事件 Gain，避免“越按越响”。

07. 直接复制给 Agent。

终极版 · Browser Performance System
请把当前网页项目整理成一个可以直接用于现场演出的浏览器音画系统。

先完整读取当前项目，不要从零重写已经能运行的视觉文件。优先复用现有 HTML / Canvas / WebGL 内容。

目标：打开 index.html 后，我可以使用键盘和鼠标完成一段连续实时音画表演。系统自己维持音乐结构，同时允许我的输入改变 Phrase、Scene、Energy 与连续参数。

技术：Visual 保留现有 Canvas / WebGL / Three.js；Audio 使用 Web Audio API 或 Tone.js；建立唯一 BPM / Transport / Scheduler；Audio 与 Visual 使用同一个 shared state；第一次用户操作后启动 AudioContext。

Shared State 至少包含：BPM / beat / bar / step / scene / energy / density / mouseX / mouseY / holdDuration / fxAmount / lineWidth / patternVariant。

输入：Keyboard 负责离散决定；Mouse XY 负责连续控制。A/S/D/F、J/K/L/; 可作为主要 Scene / Phrase；1/2/3/4 = OPEN / BUILD / PEAK / BREAK；Space = NEXT / ROUTE / ACCENT。按住 Scene Key + Mouse XY 时可进入该 Scene 的第二层控制。

加入 input filter：Quantize / Debounce / Cooldown / Max Active / Priority。按键立即给轻量 acknowledgement，正式音乐事件进入下一 1/8 note、beat 或 bar。人工输入优先于 Auto。

音乐：建立可持续运行的实验电子结构，约 128–150 BPM；统一 scale / key；Low / Mid / High / Ambient / FX 分工；3–4 个 pattern variants；每 1–2 bars 只改变 1–2 个参数；每 4–8 bars 才进行较大 Scene / Energy 变化；加入 master volume、compressor、limiter、voice limit。

Visual：整理 4–8 个主要状态，可从 waveform / data grid / chart / node graph / wireframe geometry / 3D abstract object / scan / flash / glyph / matrix / release residue 中选择。每幕定义 Composition / Motion / Density / Material / Response。不要只用 frequency analyser 驱动画面，beat、bar、step、energy、scene、patternVariant、mouseX/Y 都可以直接驱动画面。

已有 HTML Visual：先使用 Stage Shell + same-origin iframe / postMessage 接入，主 Stage 负责 Audio、Clock、Input、Router、Fullscreen、Panic。Visual 只负责渲染并接收 AV_STATE。需要更高性能时再改成 mount / update / dispose 模块。

参考图：如果 references/ 存在图片，只提取 composition、line language、density、depth、motion、material 等视觉属性，并转译成当前 WebGL / Canvas 行为。

演出控制必须提供：F Fullscreen；Esc Panic；Master Volume；FX Amount；至少一个视觉连续参数，例如 Line Width / Density；可隐藏 Guide；Stage Mode 中隐藏大部分文字。

稳定性：资源 preload；演出过程中不依赖临时网络资源；限制 audio voices；Scene 切换正确 cleanup；快速连续按键不会爆音或无限创建对象；resize / fullscreen 正确；提供 Reset / Panic。

先完成稳定 V1，不继续堆功能。完成后给我：CONTROLS / SCENES / SAFE TO MODIFY / CORE KEEP STABLE / HOW TO ADD A VISUAL / HOW TO ADD A REFERENCE IMAGE / PERFORMANCE CHECK。

如果当前系统已经能运行，优先局部改造，不要重新生成整个项目。
视觉不够丰富时
保持现有控制系统、Audio、Transport、Keyboard Mapping 完全不变，只扩展 Visual Scene。

请先列出当前 Scene，并为它们建立视觉差异。每一幕只增加一个主要视觉语言。

希望包含：DATA / INFOGRAPHIC、WAVEFORM / SIGNAL、WIREFRAME GEOMETRY、3D ABSTRACT OBJECT、GLYPH / MATRIX、SCAN / FLASH、RELEASE / RESIDUE。

每幕说明 Composition / Motion / Density / Material / Response。所有 Scene 继续读取现有 shared state。
音乐太单调时
保持视觉与演出控制不变，只重新整理音乐结构。

建立统一 scale / key；Low / Mid / High / Ambient / FX 分工；3–4 个 pattern variants；OPEN / BUILD / PEAK / BREAK 四个 energy state；每 1–2 bars 小变化；每 4–8 bars 结构变化；用户输入优先；Quantize；Compressor / Limiter / Voice Limit。

重点改善 groove、层次、release、空间和动态，不增加大量随机声音。

08. 演出前检查

Audio
首次点击可启动；Master 不削波；Limiter 工作；连续操作 30 秒不失控。
Visual
F 全屏；resize 正常；Guide 可隐藏；1920×1080 稳定；闪烁强度可控。
Input
焦点稳定；key repeat 不失控；Mouse XY clamp；Esc 永远保留给 Panic。
System
资源已 preload；相对路径正确；核心系统断网仍可运行；至少一个低能状态。
