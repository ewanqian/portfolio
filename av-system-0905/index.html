00 / INTRO

这次我想把问题讲大一点：一场实时音画演出，到底怎么被组织起来？

我做现场视觉以后，慢慢发现“画面本身”只占工作的一部分。真正到了现场，还要处理音乐时间、状态、Layer、控制器、切换、恢复，以及自己什么时候介入。

8.29 的工作坊里，我从一个很小的控制练习出发，讨论 Tap / Hold / Release、BPM、State 和 Mapping。那一轮更接近“一个动作怎么变成可以演奏的东西”。

这次把镜头往后拉。我们看整套演出：音乐端给了什么，视觉端能读到什么，系统怎么记住当前状态，多个视觉怎么被组织，人又在什么时候做判断。

如果只剩下一张图，我会把这堂课画成：Music → Signal → System → Visual → Performance。

02 / WHY SYSTEM

为什么几条视频很好演，十套实时工程就开始难管理？

素材少的时候，我可以记住“哪条适合重拍、哪条适合 Break”。内容一多，记忆就开始不够用。

比如十套 Processing，每套又有几个状态，再加 Arena Layer、MIDI、BPM、不同参数和恢复方式。这时候需要管理的已经不是文件数量，而是它们之间的关系。

系统最先解决的几个问题其实很朴素：我现在在哪里？什么正在运行？下一步能去哪里？如果切错了怎么回来？

CURRENT STATE 现在处于什么状态？ ACTIVE LAYERS 什么还在运行？ MUSIC TIME 现在是第几拍 / 第几小节？ ROUTING 这个控制现在管谁？ NEXT 下一步可以去哪里？ RECOVERY 怎么回到安全状态？
03 / MUSIC → VISUAL

现场音乐开始以后，视觉到底靠什么知道“现在发生了什么”？

这件事没有唯一答案。最常见的几种方法可以同时存在。

HUMAN

我自己听

陌生 DJ set 里最常见。听到 Break、Drop、停顿、能量变化，再手动决定画面。

CLOCK

拿音乐时间

只知道 BPM、Beat、Bar、Phase。程序知道什么时候发生，不知道声音内容是什么。

MIDI / DATA

拿控制信号

鼓机、DAW、控制器发送 Note、CC、Trigger。视觉端得到明确事件或数值。

AUDIO

直接听波形

分析音量、低中高频、瞬态或 FFT。适合获得声音此刻的物理特征。

DJ / LIVE ELECTRONICS / AUDIO ↓ MUSIC ┌───────┼────────┬────────┐ ↓ ↓ ↓ ↓ HUMAN CLOCK MIDI AUDIO └───────┴────────┴────────┘ ↓ VISUAL SYSTEM
04 / TIME · EVENT · VALUE

程序里先把音乐信息分成三类，会省掉很多麻烦。

TIME

现在走到哪里？

BPM、Beat、Bar、Phase、Phrase。它们给整个系统共同时间。

EVENT

刚才发生了什么？

Kick、MIDI Note、Cue、Trigger。通常是一瞬间发生的事件。

VALUE

现在有多少？

Volume、Bass Energy、MIDI CC、Envelope。通常整理成 0 到 1。

EVENT kick 0 0 0 1 0 0 0 1 note 0 → 1 → 0 它回答： “发生了吗？”
VALUE MIDI CC 0 ─────── 127 ↓ 0.0 ───── 1.0 density = 0.72 它回答： “现在有多少？”

0–1 不是某种视觉风格，它只是一个方便交换的数值范围。今天的 0.72 可以来自 Fader，明天也可以来自 Bass Energy，视觉模块照样能读。

05 / SHARED CLOCK

BPM 最实用的地方，是让音乐和视觉共用一把时间尺子。

120 BPM 大约每 0.5 秒一拍。Beat 组成 Bar，更长的 Bar 再形成 Phrase。视觉共享这套时间以后，切换就可以放在下一拍、下一小节或者下一段落。

Ableton Link 处理的正是这类共同时间：tempo、beat、phase。Resolume 也可以加入同一个 Link Session。

没有 Link 也能演。最简单的方法就是听音乐 Tap BPM，再在新的 Phrase 第一拍 Resync。

06 / BPM LINK EXPERIMENT

我自己的一个例子：声音端已经有结构化信号，视觉端就可以直接接进来。

Mark 用 CDJ 和人声采样建立 Loop；RÖ 继续处理声音，同时向视觉端发送 MIDI / BPM；我在 Processing 里接收这些信息，控制视觉状态。

演出前一晚，我用 Codex + Processing MCP 快速做出约十套能运行的视觉。真正排起来以后，只留下约四组。

这里最值得讲的不是“十套做得很快”，而是后面那一步：看、比较、删掉、留下，再把留下的内容接进同一套时间和控制里。

07 / FROM MATERIAL TO SYSTEM

我现在会先把内容分成四层：Material、Layer、State、Show。

MATERIAL

手上的材料

一条 Clip、一个 Processing Visual、一个 Shader、一个短行为。

LAYER

长期存在的通道

例如 Base、Rhythm、Accent、Transition。它们可以同时存在。

STATE

当前的一组关系

哪些 Layer 开着、参数是多少、哪些控制有效、释放怎么处理。

SHOW

整场怎么走

State 怎么切、什么时候自动、什么时候由人决定。

MATERIAL ↓ LAYER ↓ STATE ↓ SHOW

这四层够我在课上把问题讲清。更细的 Capsule、Sequence、Graph 可以留到以后继续研究。

09 / HUMAN + SYSTEM

系统负责精确和重复，我负责判断这一刻应该发生什么。

SYSTEM BPM CLOCK QUANTIZE DENSITY LIMIT TRANSITION RESET / PANIC
HUMAN FOLLOW? WAIT? ADD? REMOVE? KEEP IT EMPTY? CHANGE STATE?

面对没排练过的 DJ，我会更多依赖耳朵和现场判断。面对信号完整、排练充分的合作演出，系统可以接管更多精确工作。两种方法本来就可以放在同一套工具里。

10 / LIVE PROJECT

最后打开真实工程。我只带大家追三条线。

TIME

音乐时间怎么进来

BPM → Transport → Beat / Bar → Visual Timing。

CONTROL

控制信号去哪

MIDI / Keyboard → Router → Parameter / Action。

STATE

状态怎么改变输出

State → Layers / Parameters → Visual Output。

我不会从第一行代码开始讲。先找到这三条线，再看一次 Reset / Panic。面对陌生工程时，有了这几个观察点，就不会一下被文件数量淹没。

11 / AV SYSTEM 0.1

最后 10 分钟，先把一个最小系统骨架跑起来。

1 × SHARED CLOCK BPM / BEAT / BAR 1 × EVENT Space / MIDI Note / Kick 1 × VALUE Mouse X / MIDI CC / Audio Energy 2 × STATES CALM / ACTIVE 2 × VISUAL MODULES 1 × RESET / PANIC
