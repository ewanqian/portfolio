INTRO / WHERE THIS COMES FROM

当画面进入舞台，它会和音乐时间、设备、控制和人的判断同时发生关系。

我做现场视觉时，越来越多时间花在一个问题上：这些关系怎样被组织成一套可以持续演出的系统？

8.29 的工作坊从极简控制出发，讨论 Tap / Hold / Release、BPM、State 和 Mapping。那次研究更靠近“一个控制怎样变得可以演奏”。今天把视角拉到整场演出，讨论音乐信息怎样进入视觉、多个视觉怎样被组织、State 怎样保存一组关系，以及人在什么时候接管系统。

01 / PAURIC FREEMAN

一场持续 60 分钟的实时音画表演，系统要帮表演者管理什么？

Pauric Freeman 为《Structures》制作了自己的 audiovisual performance system。分享里涉及声音数据、场景保存与召回、不同视觉元素的组合、快速切换和现场稳定性。

Data

音乐与控制器产生的数据怎样进入视觉。

Scene

一整组参数怎样被保存，再在现场完整叫回来。

Permutation

已有元素怎样重新组合，支持长时间变化。

Reliability

切换发生在观众面前，系统必须持续可用。

02 / WHY A SYSTEM

当手上有十套视觉、几十个状态和多个控制信号时，靠记忆还够吗？

几条视频很好管理。每条素材的位置、节奏和用途都可以记住。实时工程增加以后，表演者开始同时处理内容、状态、时间、Layer、MIDI、参数和恢复方式。系统的第一份工作，是让这些关系可观察、可调用、可恢复。

现在在哪里？

当前 State、Scene、Layer、Bar、Phrase。

什么正在运行？

哪些视觉、声音、Layer 和自动过程仍然活动。

下一步能去哪？

哪些变化可以立即发生，哪些应该等下一拍或下一小节。

怎么回来？

Reset、Panic、Recall、低负载状态。

LIVE PERFORMANCE SYSTEM MUSIC TIME BPM / BEAT / BAR / PHRASE CURRENT STATE what is active now? LAYERS what can coexist? ROUTING what controls what? TRANSITIONS what can happen next? RECOVERY how do we return safely?
讲者提示
这里直接举自己的工程数量。比如“十套 Processing，每套 4–8 个状态”，再加 Arena Layer 和控制器以后，人的记忆开始成为瓶颈。系统的意义先从实际负担讲，不从软件架构讲。
听众能说出“内容多以后，管理关系本身成为问题”。
03 / MUSIC INFORMATION

视觉系统到底能从音乐里拿到什么？

“听得到音乐”与“程序拿到音乐数据”是两件不同的事。现场常见的连接方式至少有五种。

01 · HUMAN

表演者自己听。判断 Break、Build、Drop、停顿，再手动切换视觉。

02 · CLOCK

只拿 BPM / Beat / Bar / Phase。系统知道音乐时间，不知道声音内容。

03 · MIDI

鼓机、DAW、控制器发送 Note、CC、Trigger 等离散或连续消息。

04 · AUDIO

程序直接分析波形、音量、频段、瞬态或 FFT。

DJ / LIVE ELECTRONICS / AUDIO FILE │ ↓ MUSIC │ ┌────────────┼────────────┬────────────┐ ↓ ↓ ↓ ↓ HUMAN CLOCK MIDI AUDIO listening BPM / Beat Note / CC waveform │ │ │ │ └────────────┴────────────┴────────────┘ ↓ VISUAL SYSTEM

专业 DJ 环境还可能提供 Waveform、Beatgrid、Playback Time 等 metadata。不同场地能拿到的信息不同，因此一套可迁移的系统最好同时保留自动信号和人工 fallback。

讲者提示
先问大家：“如果今天 DJ 的音乐完全没排练过，我怎么做视觉？”答案就是耳朵和判断。然后再一层层增加 Clock、MIDI、Audio。这样 Audio Visual 的发生环境会先被理解，再进入技术。
听众知道 Audio Visual 不只等于 FFT；程序可以从人、时间、MIDI、音频等不同渠道获得信息。
04 / SHARED MUSIC TIME

BPM 为什么会成为声音和视觉的共同坐标？

BPM 表示每分钟多少拍。120 BPM 大约每 0.5 秒一拍。Beat 组成 Bar，多个 Bar 继续形成更长的 Phrase。视觉系统共享这套时间以后，可以把 Pulse、切换、Transition 和动画放在音乐边界上。

BPM

整体速度。

Beat

当前这一拍。

Bar

一组 Beat，常用作更大的切换边界。

Phase

当前在循环中的相对位置。

Ableton Link 同步 beat、tempo 和 phase。Resolume 也可以加入 Link Session。没有 Link 时，可以听音乐 Tap BPM，再在 Phrase 第一拍 Resync。

05 / TIME · EVENT · VALUE

程序收到的音乐信息，怎样整理成可以反复使用的数据？

TIME

现在走到哪里？

BPM、Beat、Bar、Phase、Phrase。

EVENT

刚才发生了什么？

Kick、MIDI Note、Cue、Trigger、Scene Change。

VALUE

现在有多少？

Volume、Bass Energy、MIDI CC、Envelope、LFO。

EVENT / 离散事件 KICK 0 0 0 1 0 0 0 1 MIDI NOTE 0 → 1 → 0 回答： “有没有发生？”
VALUE / 连续数值 MIDI CC 0 ───────── 127 ↓ normalize 0.0 ─────── 1.0 density = 0.72 回答： “现在有多少？”

0–1 只是统一范围。视觉模块收到 density = 0.72 后，不需要知道它来自 MIDI Fader、Bass Energy 还是鼠标。设备来源可以换，视觉逻辑仍然成立。

讲者提示
拿一个真实 MIDI 旋钮演示 0–127，再说明程序经常把它整理成 0–1。Freeman 的 Data Formatting 就放在这里解释。不要先说“二值/连续变量”这种课本语言。
给任意信号，听众大致能判断它是 Time、Event 还是 Value。
06 / BPM LINK EXPERIMENT

在一次真实合作里，音乐和视觉是怎样真正连起来的？

Mark 用 CDJ 与人声采样建立 Loop；RÖ 继续处理声音，并向视觉端发送 MIDI / BPM；我在 Processing 中接收这些信息，控制实时视觉和状态切换。

Mark CDJ / Voice Loop ↓ RÖ FX / Bit Machine │ ├── MIDI └── BPM ↓ Ewan / Processing ↓ State / Visual Switching ↓ Resolume / Stage

07 / SYSTEM ARCHITECTURE

四组好用视觉，怎样继续变成一套演出系统？

先把不同时间尺度分开。一个行为可以很短，一条 Layer 可以持续存在，一组 State 可以同时调整多条 Layer，Show 负责更长时间的推进。

Material

一段 Clip、一个 Processing Visual、一个 Shader、一个 Pulse 行为。

Layer

持续可用的演出通道，例如 Base、Rhythm、Accent、Transition。

State

当前这一刻，多条 Layer 和参数共同形成的一组关系。

Show

State、Transition、自动过程与人的判断怎样构成整场演出。

MATERIAL one visual / one behaviour ↓ LAYER a continuous performance channel ↓ STATE a recalled configuration ↓ SHOW long-form progression
讲者提示
最好打开 Arena 对照着讲：一条 Loop 是 Material；把它放在第二层后，它属于 Layer；多条 Layer 的开关和参数一起保存，成为 State；多个 State 形成整场 Show。这里不需要继续展开 Capsule、Sequence 等更细层级。
听众能区分素材、通道、当前配置和整场结构。
08 / STATE

State 到底保存的是什么？

State 保存的是一整组当前关系。进入一个状态时，系统可以同时决定 Visual Bank、Layer、Density、Flash、Release 和 Clock Division。这样现场不需要重复做一串细小操作。

STATE = a set of relationships visual bank + active layers + parameter ranges + clock division + release behaviour + available controls

同一套控制器，在 HEAVY 和 BREAK 里可以拥有不同意义。State 让系统知道“现在应该怎样解释输入”。

讲者提示
直接点 HEAVY / BREAK。让大家看到一次切换改变多个关系。这里不要把 State 讲成“预设名称”，重点是它保存了当前系统的配置和上下文。
听众能解释“切 State”为什么比“切一条视频”包含更多信息。
09 / ROUTING

同一个信号，为什么可以在不同段落控制不同东西？

BASS ENERGY ↓ ROUTER │ ├── STATE A → SCALE ├── STATE B → DENSITY └── STATE C → CAMERA PRESSURE

Routing 负责把一条信号送到当前需要的目标。Bass Energy 不必永远控制 Scale；MIDI Note 36 也不必永远触发同一个效果。State 可以改变 Routing，于是同一套设备在不同段落拥有不同作用。

MIDI NOTE 36 ↓ ROUTER │ ├── BUILD → ADD PULSE └── PEAK → FLASH / ACCENT

当 State 进一步增加，还可以用 Graph / Route 规定合理的迁移路径，让表演者知道“当前在哪里”和“下一步可以去哪”。

讲者提示
这一节只要讲懂“同一个信号可以被重新指向”就够。Graph / Node / Route 只作为下一层提示，不现场展开实现。
听众知道 Mapping 会受到 State 影响，因此系统有上下文。
10 / HUMAN + AUTOMATION

哪些事情交给系统，哪些事情留给现场的人？

MUSIC ↓ TIME / EVENT / VALUE ↓ SYSTEM ↙ ↘ AUTOMATION HUMAN precise / repeat judgement ↘ ↙ VISUAL STATE ↓ STAGE
系统适合负责

BPM、Clock、Quantize、最大密度、Transition Scheduling、参数范围、Reset / Panic。

人适合负责

这个 Drop 要不要跟？这一段要不要留白？什么时候提前进入下一段？什么值得留下？

面对陌生 DJ set，人承担更多实时音乐判断。面对排练充分、信号完整的合作演出，系统可以接管更多精确和重复的工作。两种工作方式可以在同一套系统里并存。

讲者提示
最好讲一个自己现场“选择不跟”的例子，再讲一个一定希望系统自动完成的例子，比如 Quantize 或 Density Cap。这样自动化和人的职责会很具体。
听众能各说出一件适合系统负责、以及一件适合人负责的事。
